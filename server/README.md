# cca 的同步服务器（cca-core team-server）

这是 Team 的同步服务器（cca 那一半见 docs/dev/team.md）。一个 Team 有管理员的设备和别的设备，服务器由管理员自己部署（`cca team deploy`，
托管平台上 `cca team hosted`）：管理员给每台设备发邀请、定它能用哪些账号，账号走哪个节点、节点的定义由管理员的设备加密、签名后存在
这台服务器上，各台设备取自己的那一份。自己的几台设备之间同步也是建一个 Team。Team 给的账号还经它：

- App 账号页里的“设备”一节：这些账号在某台设备上经 cca 使用时（命令行会话、`cca app` 打开的桌面 App），那台设备报告给这台服务器。
- 官方账号记下的 API key（`cca key 账号`、App 的「记录 API key…」）同步给登录了这个账号的其他设备：设备只传密文，服务器存着转交，解不开。
- App 的「折合金额」（按官方 API 标价折算的用量）：每台设备算自己的，经它交换密文，账号的合计才包括所有设备。

它还给这个 Team 的远程会话做中转（`cca remote pair` / `attach`，见「远程会话的中转」）：两台配对过的机器之间的终端内容经它转发，
是端到端加密的，它只转字节；开了网页端时，手机在浏览器里也接得进来（见「网页端」）。

服务端程序就是 cca 的辅助程序自己：`cca-core team-server`，给网页端向 Let's Encrypt 要证书的证书助手是 `cca-core team-acme`（代码在
`cli/src/server/`；装到 Linux 服务器上的是 musl 静态链接的那一份，x86_64、arm64 各一份，服务器上不用 Python）。这个目录里：`hub-install.sh`
（一键安装脚本的模板：辅助程序把服务端程序放进去才是能运行的那一份，`cca team deploy` 经 SSH 运行它，发布页上的 `cca-hub-install.sh` 就是它）、
`web/`（网页端的页面）。这两样都编进了辅助程序，改了要重新编（`cd cli && cargo build --release --locked`）。3.6.x 以前服务端是 Python 写的
（`cca-presence.py`，证书助手 `cca-acme.py`）：那时装的服务器用这一版再部署一次就换过来，见「部署」。

以前还有两种服务器，都去掉了：3.5.3 以前的「自己的同步服务器」（`--mode own`，cca 的 `cca hub`）；3.6.0 以前的维护者的服务器
（`--mode maintainer`，`./policy.sh presence deploy` 装的 compose 项目：只认维护者拿发布密钥（`--release-key`）签的设备清单
`/v1/machines` 里的设备）。现在 `--mode` 只剩 `team`（照旧认得），给了 `--mode maintainer`、`--release-key` 起不来，`/v1/machines`
回 404。拿以前的状态文件起 Team 的服务器是从头开始（以前的设备、记录、密文都不要了，日志里说一行）。以前装在 `/opt/cca-hub` 的照
「Team 的同步服务器 → 部署」里说的卸载；维护者的服务器在它的目录里 `docker compose down`、再删掉这个目录（3.6.0 起的 cca 不再连它）。

## 隐私

服务器能看到的只有这些：

- 各台设备的公网 IP、名字（加入 Team 时定的）。
- 账号的摘要 HMAC(盐, 工具 + 邮箱)。
- 哪个账号在什么时候、开着几个会话、闲置了多久。
- 每个账号记下的 API key 的密文、哪台设备什么时候传的（那台设备被移除以后不再记着是它）。
- 每个账号在每台设备上的折合金额的密文（大小大致随用了多少个小时变）、什么时候传的（设备被移除时删掉）；每台设备认不出是哪个账号的那一份
  也是这样一份密文，它的账号摘要是固定的那一个，服务器认得出哪一份是它，看不到里面的金额。
- 远程会话：哪两台设备配了对；哪台设备现在开着几个可以接入的会话、各给哪几个配对看（会话的说明是密文）、什么时候开始的、
  谁在什么时候接入了多久、转了多少字节。
- 手机上的账号（3.7.5 起）：每个手机的配对一份账号的状态的密文（大致多大、什么时候放的，只在内存里）；额度用完的通知什么时候推的；
  到点再推的那几条什么时候到点（也就是那台设备上有个账号的额度什么时候恢复：看不出是哪个账号，同一个账号的同一个窗口在这个配对里
  一直是同一个编号）。

它看不到邮箱，也看不到会话内容和 API key。每个请求都不记日志。

API key 的密文：密钥由 Team 的盐、邮箱和账号的登录身份（Claude 的 accountUuid、ChatGPT 的 chatgpt_user_id）用 HMAC-SHA256 派生
（`root = HMAC(盐, "cca-keyshare-v1\0" 工具 "\0" 邮箱小写 "\0" 身份)`，加密用 `HMAC(root, "enc")`、认证用 `HMAC(root, "mac")`；
盐是管理员给各台设备的配置里那串十六进制解出来的字节（建 Team 时生成的：32 个字符、16 个字节；服务器看不到它），工具是 `claude` 或 `codex`，字符串都按 UTF-8），
只有登录过这个账号的设备算得出来。内容是 `{"v":1,"key":key 或 null（删掉了）,"at":记下的时间}`，用空格补齐到 256 字节的整数倍（看不出是 key
还是删除、key 有多长），以 `HMAC(enc, nonce + 8 字节的块号)` 当密钥流异或加密（nonce 是随机的 16 个字节，块号从 0 起、大端，每块 32 字节），
再以 `HMAC(mac, "cca-keyshare-v1\0" 账号摘要 "\0" nonce 密文)` 认证（账号摘要是上报用的那 32 个十六进制字符）；
传的是 `{"n": nonce, "c": 密文, "t": 认证}`（base64）。谁新谁旧、真的假的由设备按认证过的时间自己判断：别的设备传上来旧的、伪造的，
登录了这个账号的设备不认，还会把自己的传回去。

折合金额的密文（op `ledger`，`/v1/ledger`）：密钥整个 Team 共用、只由盐派生（`root = HMAC(盐, "cca-cost-v2")`，加密用 `HMAC(root, "enc")`、
认证用 `HMAC(root, "mac")`）：Team 给了这个账号的设备不用登录也解得开，服务器没有盐、解不开；和 API key 的互不相通。3.6.5 及以前的 cca
用的是标签 `cca-cost-v1`，密钥照上面 API key 的算（`root = HMAC(盐, "cca-cost-v1\0" 工具 "\0" 邮箱小写 "\0" 身份)`），只有登录过这个账号的
设备解得开；新版的 cca 登录着这个账号时还认这种，传的都是新的。内容是 `{"v":1,"at":传的时间,"h":{整点的时间戳:[金额（百万分之一美元）, 请求数, 输入, 输出, 缓存读, 缓存写, 其中没有标价的请求数]},"um":[没有标价的模型…]}`
（只有这台设备上这个账号最近 14 周的）。3.6.8 起还带着按模型分的 `"hm":{整点的时间戳:{模型名:[同上的七项]}}`（模型名是会话记录里的写法：
小写，去掉 `[1m]` 这类后缀和末尾的日期，没写时是空字符串；一个小时最多 64 个模型；一个小时里各个模型的加起来就是 `h` 里那一个小时的；
放不下时先去掉它，旧版 cca 读到时忽略，读的一方核对样子，不对的整个当没有），新版的 cca 还带着这台设备的诊断 `"dg":{"cca":版本,"claude_code":命令行里最近用的 Claude Code 版本,
"why":[{"code":为什么有回复认不出是哪个账号的,"last_epoch":最近一次（只到 UTC 的天）,"claude_code":那时的版本}…]}`（没有条数；读的一方核对样子，
不认得的丢掉，旧版 cca 读到时忽略）、这台机器的标识 `"dv"`（config.json 的 `device_id`，16～64 个小写十六进制字符；一台机器在不同的服务器上
设备指纹不一样，读的一方据此把它认成一台；没有 `device_id` 的设备不带，读的一方核对样子，不对的丢掉），Antigravity 的账号还带着这台设备的状态栏记下的套餐 `"pl":{"n":叫法,"at":记下的时间}`（agy 1.5 的登录信息里没有套餐，只有开过交互会话的设备记得下：Team 里别的设备取各台传的里面最新的一份显示；记下了套餐的设备没有用量也传，`h` 是空的；只放这台设备自己记下的，从别的设备那里拿来的不放；读的一方核对样子：叫法不空、最多 64 个字、没有看不见的字，时间是数、不晚于现在一天以上，不对的丢掉；3.7.7 及以前的 cca 不带，读到时忽略），zlib 压缩，前面加 4 个字节（大端）的压缩后长度，用零字节补齐到 1024 字节的整数倍，再照上面的办法加密；
认证是 `HMAC(mac, 标签 "\0" 账号摘要 "\0" 设备指纹 "\0" nonce 密文)`（标签是 `cca-cost-v2`，以前的是 `cca-cost-v1`；设备指纹是这台设备在 Team 里的密钥的
`SHA256:…`，挪不到别的账号、别的设备上）。
认不出是哪个账号的用量（会话记录里没有账号信息）3.6.8 起也照样传一份：账号摘要是固定的
`HMAC(盐, "cca-cost-orphan\0")` 的前 32 个十六进制字符（和账号摘要同一个算法：工具是 `cca-cost-orphan`、邮箱是空的），同一种密文、同一把密钥，
内容的样子一样（`h`、`hm` 是这台设备认不出账号的那些小时；没有时也传一份空的，读的一方据此知道这台设备的 cca 够新、只是没有这种用量）；
只传给这台设备有账号在里面的那几个 Team 的服务器。
请求是 `{"put": {账号摘要: 密文}, "get": [账号摘要…], "have": {账号摘要: {设备指纹: 认证码}}}`：put 只写这台设备自己的那一份，
get 回名单里各台设备的 `{fp, name, me, revoked, tag, age, blob}`（have 里认证码没变的、这台设备自己的不带 blob；设备被移除时它传的就删了，`revoked`
总是 false：3.6.5 及以前的服务器留着移除了的设备的，标 true），`missing` 是 30 天内经 cca 用过这个账号、却没传过折合金额的设备（多半是 cca 太旧）。
一次请求里 put、get、have 各最多 64 个账号，一份密文最长 98304 个字符，一台设备最多 128 个账号、4 MB，一次回的密文最多 512 KB（其余的下次再取）。

## Team 的同步服务器

服务器上只配置 Team 的根公钥（公开的），没有要保密的东西。怎么装见下面「部署」「托管平台」（设计和客户端那一半见 docs/dev/team.md「部署」）。

`--team-root 'ssh-ed25519 AAAA…'`（也可以用环境变量 `CCA_TEAM_ROOT`；只看前两段，后面的备注不管；`--mode team` 照旧认得，写不写都一样）：
Team 的根公钥，一定要给。它是公开的，服务器上没有任何要保密的配置。根密钥（ed25519）在管理员的设备上，不出那台设备。Team 的编号是根公钥
（base64 那一段解出来的字节）的 SHA-256 的前 32 个十六进制字符，`GET /v1/health` 的 `mode` 是 `team`、`team` 是这个编号。API key、
折合金额的密文照上面「隐私」里的格式。最多 256 台设备。

请求都是签过名的 `POST /v1/<op>`：body 是紧凑 JSON（`v`、`op`、`key`（签名的那把密钥的指纹 `SHA256:…`）、`ts`、`nonce`，和这个 op
自己的几项），签名是 `ssh-keygen -Y sign` 的 SSHSIG（Ed25519，命名空间 `cca-presence`），armored 的输出再 base64，放在 `X-Cca-Sig` 头里；
`ts` 和服务器的时间差 5 分钟以内，`nonce` 不能重复。分两种签名的人：

- 管理员的 op 拿**根密钥**签，`key` 是根公钥的指纹；3.6.15 起也认**管理员名单**里的密钥（见下面「几位管理员」），`key` 是那一把的指纹。不是它们签的回 403 `denied`。
  换名单的 `team_admins` 只认根密钥。根密钥不是设备：别的 op 不认它，它也登记、加入不了。
- 设备的 op 拿这台设备自己的密钥签。不在名单里的（被移除了、服务器的记录清掉了）回 403 `unknown_device`，带着 `gen`（这一份记录的编号：
  从头开始时生成，32 个小写十六进制字符。和设备记着的一样是被移除了，不一样是服务器的记录没了）。

| op | 谁 | 请求 | 回 |
|---|---|---|---|
| `team_enroll` | 管理员 | `devices`：`{设备编号: {"pub": "ssh-ed25519 …", "name": 名字}}`，一次最多 64 台 | `{names: {设备编号: 名字}, members, gen}`：直接登记设备的公钥（管理员自己的那台；服务器的记录没了以后照 `team_members` 回过的公钥登记回去）。名字被别的设备用了时后面加 `-2`、`-3`……；这个编号原来是另一把密钥的，那一把就此不认（它传的折合金额跟着删掉，记下的 API key 的密文留着、不再记着是它传的）；这个编号还没用掉的邀请作废。同一把公钥再登记（管理员给设备改名字）：加入的时间、加入时带的 `proof` 照旧。公钥已经是别的编号的设备 409 `taken`；满了 507 `full`；公钥是根公钥 400 |
| `team_invite` | 管理员 | `token`（邀请里的令牌的 SHA-256）、`dev`（设备编号）、`ttl`（多少秒后过期：60 秒～30 天） | `{invites, gen}`：还没用掉的邀请有几个。同一个编号再发，前一个作废。这个编号的设备已经加入了 409 `taken`（先移除它）；令牌用过了 409 `used`；没用掉的邀请满 64 个 507 `full` |
| `team_join` | 要加入的设备 | `pub`（`key` 是它的指纹，签名也用它）、`name`、`token`（邀请里的令牌）、`proof`（公钥的认证码，见「邀请链接」；可以没有） | `{name, dev, members, gen}`：令牌就此用掉，这把密钥记成邀请里的那个编号。没有这个邀请和签名不对一样回 403 `denied`；签名对了、邀请过期了是 403 `expired`、用过了是 403 `used`（过期、用掉 30 天以内说得出来）；这把密钥已经是一台设备了 409 `taken`；满了 507 `full` |
| `team_put` | 管理员 | `docs`：`{设备编号: {"seq": 序号, "ct": 密文, "sig": 签名}}`，一次最多 64 台，请求最大 1 MB | `{stored: [设备编号…], stale: {设备编号: 存着的序号}, unknown: [设备编号…], gen}`：序号要比存着的大（一样、认证码也一样的算存过了）；不认得的编号（没登记过、也没有给它的邀请，或者被移除了；邀请过期 30 天以后也不认，给它存的跟着删掉）不存。还没加入的设备（邀请还没用掉）的可以先存着。每一项只有这三个键：`seq` 是 1 到 2^53 − 1 的整数，`ct` 的 `c` 最长 131072 个字符，`sig` 最长 1024 个字符；所有设备的 `c` 加起来最多 16 MB（按 base64 的字符数算），超了 507 `full` |
| `team_get` | 设备 | `have`（手里那一份的序号，没有就不带） | `{dev, me_name, seq, doc, gen}`（有管理员名单时 `gen` 前面还有 `admins`: `{list, sig}`，`team_members` 也是）：`seq` 是存着的序号（还没有是 0），`doc` 是 `{seq, ct, sig}`（别的管理员签的还有 `by`），和 `have` 一样时是 null（不一样就给，比 `have` 小的也给：要不要由设备定）。只取得到自己的。服务器记着 `have`（只在内存里），管理员看名单时看得到 |
| `team_members` | 管理员 | （没有别的） | `{members: [{fp, dev, name, pub, proof, joined_age, seen_age, seq, have}], invites: [{dev, expires_in, seq}], gen}`：`proof` 是这台设备加入时带的认证码（没带、管理员直接登记的是 null），`seq` 是这台设备存着的配置的序号（没有是 0），`have` 是它最近一次同步配置时说的手里那一份的序号（没说、服务器重启以后还没同步过是 null），`invites` 是还没用掉、没过期的邀请 |
| `team_revoke` | 管理员 | `dev` | `{members}`：这台设备的密钥就此不认，给它的配置、还没用掉的邀请一起删掉，它上报的记录、传过的折合金额的密文跟着删掉（记下的 API key 的密文是账号的，留着，只是不再记着是它传的）。这个编号没有设备、也没有邀请是 404 `no_device`（只有还没用掉的邀请时就是撤回邀请） |
| `team_leave` | 设备 | （没有别的） | `{members}`：自己退出，和被移除一样 |
| `team_admins` | 根密钥（3.6.15 起） | `list`（名单的紧凑 JSON 文字）、`sig` | `{epoch, gen}`：换成这一份管理员名单。签名不对、样子不对、不是这个 Team 的、有根公钥或者重复的公钥、超过 16 位 400；纪元不比存着的大 409 `stale`（带着存着的 `epoch`） |
| `team_astate_get` | 管理员（3.6.15 起） | （没有别的） | `{rev, ct, gen}`：几位管理员共用的设置（密文，服务器不懂）；还没有是 `rev` 0、`ct` null |
| `team_astate_put` | 管理员（3.6.15 起） | `base`（照着改的那一版，还没有是 0）、`ct`（`{"n","c","t"}`，`c` 最长 524288 个字符；请求最大 1 MB） | `{rev, gen}`：存成 `base + 1`；`base` 不是存着的那一版 409 `stale`（带着存着的 `rev`） |

启动时给的根公钥和上次不一样（换了一个 Team；以前是维护者的服务器、自己的同步服务器）就从头开始：以前的设备、邀请、上报的记录、存的密文都删掉。状态文件里有一项
`"team": {"root": 根公钥, "gen": 这一份记录的编号, "invites": {令牌的 SHA-256: {"dev", "exp", "at"}}, "spent": {用掉的令牌的 SHA-256: 什么时候}}`，
`machines` 的每一台带着 `joined` 和 `dev`；各台设备的配置在旁边的 `team-docs.json`（`{"docs": {设备编号: {"seq", "ct", "sig", "at"}}}`）。

服务器看得到的比上面「隐私」里的多这些：哪台设备是什么时候被邀请、加入、移除的，每台设备的配置有多大、什么时候换的。它看不到配置的内容
（哪些账号、走哪个节点、节点的定义），也改不了、换不了：见下面。

### 几位管理员

3.6.15 起，建 Team 的设备（拿着根密钥）能让别的设备也当管理员，根密钥不出那台设备：

- **管理员名单**：`{"v": 1, "team": Team 的编号, "epoch": 纪元（1 到 2^53 − 1）, "admins": [{"pub": "ssh-ed25519 AAAA…", "name": 名字}…]}`，紧凑的 JSON（UTF-8），
  最多 16 位、最长 8192 个字符。根密钥签的是 `"cca-team-admins-v1\0"` 接着名单的文字（`ssh-keygen -Y sign`，命名空间 `cca-team`；配置签的那一段以
  `cca-team-doc-v1` 开头，两种签名挪不到对方那里）。服务器验过签名才存（状态文件 `team.admins`: `{list, sig}`，启动时照根公钥再验一遍），在 `team_get`、
  `team_members` 的回复里原样给。名单里的公钥就是那台设备在 Team 里的密钥。
- **别的管理员签的配置**：外面多一项 `by`（它的公钥，`ssh-ed25519 AAAA…`），`sig` 是这把密钥签的（签的字节和根密钥签的一样）。`team_put` 原样存、
  `team_get` 原样给；服务器不验。设备照名单（照根公钥验过；纪元比自己记着的小的不要）认 `by`。根密钥签的配置明文里有 `admins_epoch`（名单到第几版了）：
  设备记下见过的最大的，别的管理员签的配置照的名单比它旧就不要。
- **几位管理员共用的设置**：`team_astate_get` / `team_astate_put` 存一份密文和版本号（状态文件 `team.astate`: `{rev, ct}`），版本号只能照着存着的那一版往上加一
  （两位管理员同时改，后存的那位是 409 `stale`）。密钥：`root = HMAC(akey, "cca-team-astate-v1")`（`akey` 是 32 个随机字节），加密 `HMAC(root, "enc")`、
  认证 `HMAC(root, "mac")`；明文是紧凑的 JSON，空格补齐到 1024 字节的整数倍；认证是 `HMAC(mac, "cca-team-astate-v1\0" Team 的编号 "\0" 版本号 "\0" nonce 密文)`。
  `akey` 只经根密钥签的配置交给管理员的设备（明文里的 `"admin": {"key": akey 的 64 个十六进制字符}`；设备只认根密钥签的这一项）。
- **收回**：根密钥签一份新的名单（纪元加一）、换一把 `akey`。被收回的那台已经看过的（主密钥、节点的密码）收不回来。

服务器看得到谁是管理员（名单是明文）和共用的设置多大、什么时候改的，看不到内容；伪造不了名单（要根密钥），能扣着新的名单不给、把旧的拿出来——见过新的一版的设备不认。
`/v1/health` 的 `ops` 里不列这三个 op（和以前逐字节一样）：旧的服务器收到它们回 404 `not_found`。`tests/kit/spec.rs` 的 `team_admins_text`、`team_admins_sign`、
`team_admins_verify`、`astate_keys`、`astate_seal`、`astate_open` 照这一节独立实现。

### 邀请链接

管理员给**一台**设备发一个：`cca-team1.<base64url(JSON)>.<校验>`（base64url 不带 `=`，校验是前面 `cca-team1.<base64url>`
这一段的 SHA-256 的前 4 个十六进制字符，读的时候不管中间的空白：聊天软件里贴过来可能折了行）。校验只为看出复制时少了一截、抄错了，不防人改。JSON 是紧凑的
`{"u": 地址, "p": [证书公钥的指纹…], "r": 根公钥的 base64 那一段, "k": 一串随机数, "n": Team 的名字, "e": 什么时候过期（时间戳，可以没有：给人看的，过没过期服务器说了算）,
"d": 管理员给这台设备起的名字（可以没有：3.5.3-beta.7 起有；设备加入时没另外写名字就用它报给服务器，不合规时照主机名）}`。
地址是 `https://主机:端口`（不带结尾的 `/`），指纹是 curl `--pinnedpubkey` 的写法 `sha256//…`（0～4 个：没有时设备照系统的证书机构验服务器的证书，
托管平台上的是这样，见下面「托管平台」）。盐不在链接里：它在设备的配置里（见下面），加入以后才拿得到。以后只加「旧版本不认得也不要紧」的字段；
旧版本必须认得才安全的改动换成 `cca-team2.`。

`k` 是 16 个随机字节写成的 32 个小写十六进制字符（只认这个样子）。下面三样都由它派生，HMAC-SHA256 的密钥是那 16 个字节（不是 32 个字符）：

- 令牌 `token = HMAC(k, "cca-team-token-v1")` 的前 16 个字节，写成 32 个小写十六进制字符：加入时交给服务器（服务器只存它的 SHA-256，
  哈希的是这 32 个字符）。
- 设备编号 `dev = HMAC(k, "cca-team-dev-v1")` 的前 8 个字节，16 个小写十六进制字符。服务器回的 `dev` 设备要和自己算的比（回复没有签名）。
- 这台设备那份配置的两把密钥：`root = HMAC(k, "cca-team-key-v1")`，加密用 `HMAC(root, "enc")`、认证用 `HMAC(root, "mac")`。
- 公钥的认证码 `proof = HMAC(HMAC(k, "cca-team-pub-v1"), 公钥)`，base64（44 个字符）；公钥是 `ssh-ed25519 AAAA…` 这一行的前两段（中间一个空格）
  的字节。设备加入时带上，服务器原样存着、在 `team_members` 里回给管理员：管理员照自己算的 `k` 核对，对得上才把这把公钥记成这台设备的
  （服务器的记录没了以后照它登记回去）。服务器不知道 `k`，换不了公钥；它不验这个码。

`k` 只有管理员的设备和拿到链接的那台设备知道：服务器从令牌推不出密钥，别的设备的链接也推不出这一台的。链接是凭证，而且只能用一次：
cca 只经 stdin、提问会话传它，不进命令行和环境变量。它在用之前被别人拿到，别人就能冒充这台设备加入、取走给它存的配置（真的那台再用时是
`used`）；用过以后被别人拿到，那人加入不了，但从服务器上弄到这台设备的密文的话解得开。

### 设备的配置

管理员给每台设备一份（只有它能用的账号和这些账号要的节点），服务器存的是 `{"seq": 序号, "ct": 密文, "sig": 签名}`：

- `ct` 和 API key 的密文一样是 `{"n", "c", "t"}`（base64；nonce 是 16 个随机字节，认证码 32 个字节），用上面那两把密钥。明文是紧凑的 JSON（UTF-8），
  用空格补齐到 1024 字节的整数倍；认证是 `HMAC(mac, "cca-team-doc-v1\0" Team 的编号 "\0" 设备编号 "\0" 序号 "\0" nonce 密文)`：挪不到别的 Team、
  别的设备、别的序号上。序号在这里写成十进制的数字，不带前面的 0（1 到 2^53 − 1）。
- `sig` 是根密钥的签名（`ssh-keygen -Y sign`，命名空间 `cca-team`，armored 的输出再 base64），签的是
  `"cca-team-doc-v1\0" Team 的编号 "\0" 设备编号 "\0" 序号 "\0"` 接着 nonce、密文、认证码（都是解出来的字节：16 个、任意多个、32 个；
  长度不对的设备先就不要）。
- 设备拿到以后：先照邀请链接里的根公钥验签名（比的是整把根公钥，不是 Team 的编号），再认证、解密，序号不比手里那一份大的不要。
  这只挡得住服务器拿旧的一份来换一台一直在用的设备手里的：刚加入的、重装过的设备手里没有序号，服务器给哪一份它都只能认；
  服务器扣着新的不给，设备也看不出来，只知道很久没变过。服务器不验 `sig`、不懂 `ct`：它没有那两把密钥，也没有根密钥。

明文里有什么服务器不管（盐也在里面：账号摘要、API key 和折合金额的密钥照「隐私」一节的算，盐是配置里的这一份）：cca 用的字段见
docs/dev/team.md。`tests/kit/spec.rs` 的 `team_id`、`invite_parts`、`invite_encode`、`invite_decode`、`team_doc_seal`、`team_doc_open`、
`team_doc_signed`、`team_doc_sign`、`team_doc_verify` 照这一节独立实现。

### 部署

一台 Linux 服务器（x86_64 或者 arm64，很小的就够：服务端是一个静态链接的程序，内存限在 256 MB）上，要 openssl、gzip，还要 Docker
（带 compose 插件：`docker compose`；老的 `docker-compose` 1.x 不用）或者 systemd。服务端程序带在安装脚本里（两种机器的都带，约 10 MB）：
服务器上不用 Python、不拉镜像、不联网下载。

- 从管理员的设备上：`cca team deploy Team root@服务器`（`-p` SSH 端口、`-i` 私钥、`--port` 服务的端口、`--host` 各台设备连的地址、
  `--web-port` / `--no-web` 手机的网页端、`--docker` / `--systemd`、`--dir` 装在哪；App 里是「共享与同步」里这个 Team 的「部署到我的服务器…」，接上以后在「更多」里：「更新服务器、搬到别的服务器…」）。
  经 SSH 运行安装脚本，装好了接上。SSH 用户是 root 或者能免密码 sudo。再运行是更新（数据、证书、端口都不变）；写别的服务器就是搬过去。
- 直接在服务器上：运行发布页上的 `cca-hub-install.sh`（或者在管理员的设备上 `cca team deploy --script > cca-hub-install.sh` 拷过去：那一份是
  本机验过签名的 cca 生成的）：`sudo sh cca-hub-install.sh --team-root 'ssh-ed25519 AAAA…'`（根公钥是 `cca team new` 给的那一行），
  另有 `--host`、`--port`、`--relay-port` / `--no-relay`、`--web-port` / `--no-web`、`--docker` / `--systemd`、`--dir`。最后打出管理员接上它的那一行
  `cca team attach Team https://地址:端口 sha256//指纹`（地址和指纹都是公开的）；认不出公网地址时有终端就问，没有就要加 `--host 公网IP或域名`。
  再运行（带 `--team-root`，或者 `--dir 装过的目录`）是更新。
- 3.6.x 以前装的（Python 的服务端）：用这一版再部署一次（或者在服务器上运行新的安装脚本）就换成 `cca-core`，数据、证书、端口、指纹都不变，
  各台设备不用动；换好了才删掉以前的程序。还用着 3.6.x 的管理员设备再部署会换回 Python 的那一份（数据同样不动），所以管理员的设备先更新。
- 自己运行：`cca-core team-server --team-root 'ssh-ed25519 AAAA…' --cert … --key … --state …`（Linux 的 `cca-core`：装过的服务器的 `app/` 里
  就有；中转、网页端见下面两节）。
  根公钥也可以经环境变量 `CCA_TEAM_ROOT` 给，只写 `ssh-ed25519` 后面那一段也行（没有空格，环境变量文件里好写）。

每个 Team 一个服务：systemd 的服务名 / 系统用户、Docker 的容器名 / compose 的项目名都是 `cca-team-<Team 编号的前 8 位>`（下面叫「服务名」），
装在 `/opt/<服务名>`（`--dir` 换：要是新的、空的目录，或者以前装过这个 Team 的，不能在 `/usr`、`/etc`、`/home`、`/root`、`/run`、`/tmp` 这些下面），
所以一台服务器上能装几个 Team，互不相干。端口没写时照上次的，第一次从 18445 起找空着的。这个 Team 的远程会话的中转默认开着，数据端口是下一个
空着的；手机的网页端再用一个，证书由证书助手（`cca-core team-acme`）向 Let's Encrypt 要（给 IP 地址的是短期证书），到期前自己续。网页端要中转开着、
认得出公网地址、地址不是内网的、80 端口给得了证书助手（证书机构从公网连它验证）：开不了时照样装好、说为什么，再运行时再看。80 端口只有一个：
一台服务器上的几个 Team 共用一个证书助手（服务名 `cca-team-acme`，装在 `/opt/cca-team-acme`）——第一个开网页端的 Team 装上它，别的 Team 在它
那里登记自己的地址，同一个地址只要一张证书，各个 Team 只读得了放给自己的那一份；最后一个用它的 Team 卸载时连同它一起删掉。3.5.3-beta.5 以前的
安装脚本每个 Team 自己一个证书助手（`<服务名>-acme`，占着 80 端口）：用新的再运行一次那个 Team，它的证书、账户就搬给共用的、接着用。
`--name`（`cca team deploy` 放进 Team 的名字）：网页的标题、手机主屏幕上的名字带上它。

目录里：`app/`（服务端程序 `cca-core`——网页端的文件编在它里面——和 Team 的名字 `name`）、`certs/`（自签的 P-256 证书，私钥不出这台服务器：设备按公钥指纹认它）、`data/`
（设备、记录、密文）、`.env`（运行方式、端口、根公钥；改了以后再运行一次安装脚本；没装完时换回原来的）、`.cca-hub`（记着这个目录是安装脚本装的）。
Docker 的另有 `compose.yaml`（容器用本机建的一个空镜像 `cca-team-runtime:1`——`docker import` 一个空的 tar，不拉镜像——程序从 `app/`
只读挂进去；只读、去掉所有权限），容器是
`<服务名>`；systemd 的是 `/etc/systemd/system/<服务名>.service`。共用的证书助手的目录里：`app/cca-core`（同一个程序；Docker 的还有 `app/ca.pem`：这台服务器的 CA 证书拷的一份，容器里没有）、`teams/`（用它的 Team 登记的地址）、
`store/`（每个地址的证书）、`webcert/<服务名>/`（放给那个 Team 的：只有它读得了私钥）、`acme/`（证书机构那里的账户的私钥）；容器、systemd 的服务
都叫 `cca-team-acme`。日志：`docker logs <服务名>` 或者 `journalctl -u <服务名>`（证书助手的换成 `cca-team-acme`）。

`data/` 里（自己运行时在 `--state` 的旁边）：

| 文件 | 内容 |
|---|---|
| `state.json` | 名单（各台设备的公钥、名字、编号、什么时候加入的）、邀请（只存令牌的 SHA-256）、各台设备最近一次的报告、每个账号上次使用的时间（保留 30 天，`--retain-days`） |
| `team-docs.json` | 管理员给各台设备的配置（密文和签名） |
| `keys.json` | 各个账号记下的 API key 的密文（每个账号一份，新的换掉旧的）和最后传它的设备；设备被移除后密文留着（是账号的），不再记着是它传的 |
| `cost-slots.json` | 折合金额的密文：每个账号、每台设备一份（设备只能写自己的那一份）；设备被移除时它的跟着删掉（以前的版本留下的，更新以后启动时删掉），100 天没再传的也删掉（`--cost-days`） |
| `remote.json` | 远程会话：哪两台设备配了对（配对的编号、两台设备的指纹、什么时候配的、最近什么时候用过）、网页端的访客。没有密钥；设备被移除、取消配对、180 天没用过就删。会话的内容、会话的列表都不落盘 |

- 云服务商的安全组（轻量应用服务器的防火墙）里放行服务的端口、中转的数据端口，开了网页端的再加它的端口和 80；`cca team deploy` 装完会说
  放行哪几个。systemd 方式下服务器上开着 ufw、firewalld 时脚本会说放行的那一行，不替你改（Docker 发布的端口不经它们）。
- 卸载：管理员删除这个 Team（`cca team leave`）时经 SSH 自己卸掉（带着根公钥：目录里装的是别的 Team 的不动）；手动的话
  `cca team deploy --script | ssh root@服务器 sh -s -- --uninstall --dir /opt/<服务名>`（或者在服务器上
  `sudo sh cca-hub-install.sh --uninstall --dir /opt/<服务名>`），连同数据一起删掉。3.5.3 以前装的自己的同步服务器（`/opt/cca-hub`）也这样卸载
  （`--dir /opt/cca-hub`），安装脚本不再往里装。Docker 方式的那个空镜像在这台服务器上最后一个 Team 卸载时一起删掉。

### 托管平台

没有服务器时部署到托管平台 Railway：在管理员的设备上 `cca team hosted Team`（只在终端里），生成部署文件
（默认 `~/<服务名>-railway`，里面只有 Team 的根公钥：公开的），照着打出来的步骤部署（目录里的 README.md 也写着），再在管理员的设备上接上
平台给的公网地址：`cca team attach Team https://平台给的地址`（没写端口就是 443）。托管平台只转一个 HTTP 端口：上面的不给远程会话做中转，
也没有网页端。

- 程序照样是这一个，只是 `--behind-proxy`：只说 HTTP，HTTPS 由平台做（设备照系统的证书机构验平台的证书，接上时没有指纹）；
  每个 IP 的限额按 `X-Forwarded-For` 的最后一项算（平台的代理加的那一项，客户端改不了），同一个 IP 同时几个连接不限（连过来的都是代理）。
- 平台上只给得了环境变量和一条命令（生成的 `Dockerfile` 里写好了）：环境变量 `CCA_HUB_HOSTED=1` 等于 `--mode team --behind-proxy --listen 0.0.0.0:8080 --state /data/state.json`
  （命令行里写了的照命令行的），`CCA_TEAM_ROOT` 是根公钥 `ssh-ed25519` 后面那一段，命令是 `/cca-core team-server`。端口固定是 8080
  （平台的公网地址转到它）。`/data` 要挂一块存储：没有时不启动（不然重启一次记录就没了）。
- Railway：生成的是 `Dockerfile`（`FROM scratch`：镜像里只有 `cca-core` 这一个静态链接的程序，Linux x86_64 的；`ENV CCA_HUB_HOSTED=1 CCA_TEAM_ROOT=…`）
  和程序 `cca-core`，用它的命令行工具
  `railway init`、`railway add`、`railway volume add --mount-path /data`、`railway up`、`railway domain --port 8080`。按用量计费（见它的价格页）；
  国内不一定连得上 `*.up.railway.app`。
- 更新：再运行一次 `cca team hosted`（这个 Team 接着的就是托管平台上的那一台时是更新），照打出来的步骤换上新的程序；数据在 `/data` 里照旧，
  设备不用重新加入。平台的界面会变，步骤以平台现在的为准。

## 远程会话的中转

`--relay-listen 地址:端口` 才开（不给时那几个接口回 404，和旧版服务器一样）；`--relay-port` 是告诉客户端连哪个端口（容器里外不一样时给）。
Team 的安装脚本默认开着（见「Team 的同步服务器 → 部署」）；托管平台上的开不了：只有一个 HTTP 端口。
格式照下面写的，`tests/kit/spec.rs` 是照这一节独立实现的一份（测试里拿它和 cca 互相配对、握手、收发）。

要防的是这台服务器自己（被攻破、被换掉）和路上的人：它们看不到终端的内容、敲不进按键、冒充不了配对过的机器。靠的是两台机器配对时
各自存下的一把密钥 P——服务器从头到尾见不到它。密码学只用 HMAC-SHA256（cca 的辅助程序里已有的）：没有前向保密，P 日后泄露的话，
之前被录下来的流量解得开（取消配对、重新配对就换一把）。

### 请求

和上报一样是签过名的 `POST /v1/<op>`（这台设备在 Team 里的密钥签；命名空间 `cca-presence`；`key`、`ts`、`nonce` 那几项照旧），所以服务器知道每个请求是
哪台设备发的。`rid`、`pid`、`sid` 都是 32 个小写十六进制字符。

| op | 请求 | 回 |
|---|---|---|
| `pair_open` | `rid` | 开一次配对（10 分钟；一台设备同时最多 4 个）。已经有了回 409 `taken` |
| `pair_put` | `rid`、`m`（密文） | 放自己的那一份（每边只能放一次）。头一个放的别的设备就是输入配对码的那一台，之后别的设备一律 409 `taken`；没有这个 `rid` 回 404 `no_pairing` |
| `pair_get` | `rid`、`wait`（秒，最多 10）、`until`（`"done"`：等到配对记下为止） | `{m, fp, name, done}`：对方的那一份（还没有是 null）、对方的指纹（服务器验过签名的）、名单里对方的名字 |
| `pair_commit` | `rid`、`pid` | 报自己算出来的配对编号。两边报的一样才记下这一对（`{done: true}`；同两台设备以前配过的换掉），不一样回 409 `mismatch`、这次配对作废 |
| `pair_close` | `rid` | 这次配对作废（哪一边中途不做了：显示配对码的那边取消了、过期了）。对方再问是 404 `no_pairing`；已经记下的配对不受影响 |
| `pair_drop` | `pid` | 取消配对（两台里哪一台都行）。这个配对正接着的连接随即断开 |
| `relay_host` | `sid`、`pids` | 宿主：给这个会话的控制连接换一张票据 `{tid, tkey, port, ttl}`。`pids` 里不是自己的配对的不算，一个都不是回 404 `no_pairing` |
| `relay_attach` | `sid`、`pid` | 接入方：换一张票据。会话不在、不是给这个配对看的、不是对方那台设备的，都回 404 `no_session`；接入的已经有 4 处回 429 `busy` |
| `relay_list` | `pids`、`have`（可以不带） | `{peers: {pid: {fp, name}}, sessions: {pid: [{sid, blob, age, viewers, online}]}}`：还在的配对、对方那台设备上给这个配对看的会话（`blob` 是说明的密文）；带了 `have` 的多一项 `status`（对方放上来的账号的状态，下面「账号的状态」） |
| `status_put` | `pid`、`blob`（密文）、`later`（可以不带） | 宿主：放这台设备上账号的状态、到点再推的通知（3.7.5 起，下面「账号的状态」）。不是自己的配对回 404 `no_pairing` |
| `push_note` | `pid`、`id`、`note`（密文） | 宿主：马上推一条额度的通知（3.7.5 起，下面「推送」）。回 `{"v":1,"ok":true,"sent":…}`（交给推送网关了没有）；不是自己的配对回 404 `no_pairing` |

`push_set`（下面「推送」）、`status_put`、`push_note` 是后加的：`/v1/health` 的 `ops` 不列它们（和以前逐字节一样），旧的服务器收到它们回
404 `not_found`，设备照它知道服务器太旧。

票据 30 秒内有效、只能用一次，`tkey` 是 32 个随机字节（base64）。配对 180 天没用过（没接入过）就删掉（用过的时间一天最多记一次）。

别的错误：429 `rate`（这台设备问得太勤；同时开着 4 个配对了；手里没用掉的票据有 128 张了——3.7.10 以前是 16 张）、429 `edges`（配对的机器到 16 台了，
这次配对作废）、429 `sessions`（同时开着的会话到 101 个了：100 个远程会话加上启动器；3.7.10 以前是 8 个）、507 `full`（服务器上的配对总数满了）、`relay_host` 的 409 `taken`
（这个会话编号是别的设备的）；格式不对的一律 400 `bad`。

### 配对

配对码 C 是 10 个随机字节，写成 16 个字符（Crockford base32：`0123456789ABCDEFGHJKMNPQRSTVWXYZ`，四个一组用横线隔开；输入时大小写、
横线、空格随意，I、L 当 1，O 当 0）。只在两台机器的屏幕上出现，不发给服务器。

- `Kc = PBKDF2-HMAC-SHA256(C, "cca-remote/v1/pair", 65536 轮, 32 字节)`。配对码只有 80 位：这一步故意算得慢，拿着服务器上的记录去试配对码的
  代价翻 6 万多倍
- `rid = hex(HMAC(Kc, "rid"))` 的前 32 个字符；封两边那一份用的密钥是 `HMAC(Kc, "enc")`、`HMAC(Kc, "mac")`
- 每边放的那一份：`{"v":1,"fp":自己的设备指纹,"n":32 个随机字节（十六进制）,"name":机器名}`，用空格补齐到 256 字节的整数倍，照上面
  API key 那一节的办法加密、认证（`{"n","c","t"}`），认证里的标签是 `cca-remote-pair`、后面跟 `rid` 和角色（显示配对码的是 `a`，输入的是 `b`）：
  `HMAC(mac, "cca-remote-pair\0" rid "\0" 角色 "\0" nonce 密文)`
- 取到对方的那一份：认证不过（不知道配对码的人放的）就停；里面写的指纹和服务器说的不一样也停
- `P = HMAC(Kc, "secret\0" nA nB fpA "\0" fpB "\0")`（A 是显示配对码的那台），`pid = hex(HMAC(P, "cca-remote/v1/pid"))` 的前 32 个字符
- 两边各自把 P 存好（钥匙串 / 密钥文件）、`pair_commit` 报 `pid`；服务器只记 `pid` 和两台设备的指纹

### 会话的说明

宿主把每个会话的说明封给各个允许接入的配对：`{"v":1,"machine":机器名,"tool":工具,"name":账号的短名字,"cwd":文件夹,"since":开始的时间,
"access":"control" | "view","aid":账号摘要}`（没有邮箱；`aid` 是 3.6.16 起加的，可以没有：和设备统计里的一样，`HMAC(这个配对的 Team 的盐, 工具 "\0" 小写的邮箱)` 的前 32 个十六进制字符，
接入方用同一个 Team 的盐算自己的账号，对得上的显示自己那里的别名），空格补齐到 256 字节的整数倍，密钥 `Kd = HMAC(P, "cca-remote/v1/dir")`、`HMAC(Kd, "enc")`、
`HMAC(Kd, "mac")`，认证 `HMAC(mac, "cca-remote-dir\0" pid "\0" sid "\0" nonce 密文)`（挪不到别的会话、别的配对上）。

### 启动器（远程启动）

3.7.6 起的 cca：允许远程启动的手机能照那台机器上的模板新建会话（docs/dev/launch.md）；之后的 cca 配对过的电脑也行（`cca remote launch`、Mac 上的 cca App），
下面说的「手机」都是接入的那一头。服务器不用改：启动器在它看来就是一个会话
（`relay_host`，编号固定，占那台设备的一个会话名额），手机和它对接、握手，和接入会话一样。

- **说明**：ANNOUNCE 里给每个允许远程启动的配对一份，封法和「会话的说明」一样（`{"n","c","t"}`，`c` 最长 4096 个字符），密钥换成
  `Kl = HMAC(P, "cca-remote/v1/launch")`、`HMAC(Kl, "enc")`、`HMAC(Kl, "mac")`，认证 `HMAC(mac, "cca-remote-launch\0" pid "\0" sid "\0" nonce 密文)`：
  会话的说明的密钥解不开它（旧的 App、网页端当它不存在），反过来也一样。明文是紧凑的 JSON（非 ASCII 原样），空格补齐到 256 字节的整数倍，最长 3072 字节：
  `{"v":1,"machine":机器名,"t":[模板…],"more":放不下的个数,"accounts":[能挑的账号…]}`；模板 `{"i":编号,"h":摘要,"n":名字,"k":工具,"a":账号的短名字,"aid":账号摘要,"d":文件夹,"x":参数,"l":能不能带开场白}`：
  `i` 是 8 个、`h` 是 16 个小写十六进制字符，`n` 最多 40 个字，`k` 是 `claude`、`codex`、`agy` 之一，`a` 最多 64 个字，`aid` 同会话的说明（可以没有），
  `d` 是 `~/…` 的写法、最多 200 个字，`x` 是给人看的一行（shell 的写法，最多 300 个字，超了截断）。只放有能挑的账号的模板，最多 16 个；没有模板也发。
  收的那头丢掉样子不对的模板（编号、摘要不是小写十六进制，不认识的工具，重复的编号）
- **能挑的账号** `accounts`（3.7.10 起；以前的没有这一项，模板用它自己的账号：`a`）：起会话时手机挑一个。`{"i":编号,"k":工具,"n":短名字,"aid":账号摘要}`：
  说明里的模板用到的工具的、会话走这台服务器的账号，一个工具最多 16 个；`i` 是按配对算的 16 个小写十六进制字符（同「账号的状态」里这个账号的编号：手机照它对上
  「账号」页里的那一个），`n` 最多 64 个字，`aid` 同会话的说明（可以没有）。模板的 `a`、`aid` 留给不认 `accounts` 的旧手机：能挑的只有一个时是它的，
  不止一个时 `a` 是「启动时选账号」、没有 `aid`。收的那头丢掉样子不对的（编号不是 16 个小写十六进制，不认识的工具，重复的编号）
- **摘要** `h`：`hex(SHA256(紧凑 JSON [工具, 文件夹, 参数数组]))` 的前 16 个字符（3.7.9 及以前账号也算在里面）；起的时候对不上（模板在那台机器上改过了）是 `changed`
- **起一个**：手机照接入会话那样 `relay_attach`（启动器的编号）、连数据端口、握手（「两头之间的通道」），头一帧发 LAUNCH（不发 HELLO），等 LAUNCHED（20 秒），
  启动器回完就断开。帧是通道里那一套（`类型(1) 长度(4) 内容`；和控制连接上的 `0x09` BYE 不是一层）：
  - LAUNCH `0x09`（手机 → 启动器）：`{"v":1,"t":模板编号,"h":摘要,"c":列,"r":行,"l":开场白,"a":账号的编号}`（`l`、`a` 可以没有），最长 4096 字节；列 20～500、行 5～300；
    开场白最多 500 个字、没有控制字符、不能全是空白，模板的 `l` 是 false 时不能带；`a` 是说明里 `accounts` 的 `i`（16 个小写十六进制字符）。
    没有 `a` 时能挑的只有一个就用它
  - LAUNCHED `0x18`（启动器 → 手机）：`{"v":1,"ok":true,"sid":新会话的编号}`，或者 `{"v":1,"ok":false,"code":…,"text":给人看的原因}`。`code`：`denied`（这台手机、电脑现在不能远程启动）、
    `no_template`、`changed`（这两个：刷新再选）、`no_account`（说的账号没有了；没说的话是一个能挑的都没有）、`need_account`（没说用哪个账号，能挑的不止一个：手机太旧）、
    `no_dir`、`bad_args`、`other_hub`（挑的账号的会话现在走别的 Team 的服务器）、`busy`（那台机器上走这台服务器的会话满了：3.7.10 起的服务器 100 个，以前的 7 个）、
    `rate`（一分钟最多起成 4 个；同一台手机两次接进来不到 3 秒也是它）、`spawn`（没起来）、`bad`（请求不对，缺了哪一项也是）
  - 起来的是一个普通的会话：手机接着 `relay_attach` 新的编号（刚起的可能还没登记上：头 45 秒里服务器说 `no_session` 时隔 1.5 秒再问）
- 会话那头的转接进程不转 LAUNCH：接着一个会话起不了别的

### 账号的状态

3.7.5 起：宿主把这台设备上账号的状态（iPhone 上的 cca App 的「账号」页：登录、套餐、用量；明文的样子见 docs/dev/remote.md「手机上的账号」，
没有邮箱）封给各个手机（访客）的配对，`status_put` 放到这台服务器上，手机 `relay_list` 时带着 `have` 取走。

- **密文**：明文是紧凑的 JSON，空格补齐到 256 字节的整数倍；密钥 `Ks = HMAC(P, "cca-remote/v1/status")`、`HMAC(Ks, "enc")`、`HMAC(Ks, "mac")`，
  认证 `HMAC(mac, "cca-remote-status\0" pid "\0" nonce 密文)`，照会话的说明那样封成 `{"n","c","t"}`（`c` 最长 40960 个字符）
- **放**：`status_put` 的 `pid` 得是这台设备的配对；这个配对里这一头原来放的那一份换掉。只在内存里（服务器重启就没了：宿主下一轮再放，没变的也最多
  隔半小时放一次），14 天没再放就不给了，取消配对、移除设备时一起删
- **取**：`relay_list` 带了 `have`（`{pid: 手里那一份的 n}`，可以是空的 `{}`）的，回的里面多一项 `status`：`{pid: {"blob", "age"}}`（`age`：
  放上来多少秒了），手里那一份的 `n` 和服务器上的一样时是 `{"same": true, "age"}`；对方没放过的不在里面。不带 `have` 的回的和以前一样（旧版的
  手机）；手机看回的里面有没有 `status` 知道这台服务器给不给
- **到点再推的**（`later`，可以不带）：额度恢复的那一刻推的通知（下面「推送」），`[{"slot", "at", "id", "note"}]`，最多 8 条：`slot`、`id` 是
  16 个小写十六进制字符（`slot` 不能重复：同一个账号的同一个窗口是同一个 `slot`），`at` 是 Unix 时间（秒，不晚于 8 天以后），`note` 是通知的
  密文（同下面「推送」的，最长 3072 个字符）。这个配对里这一头原来放的那几条换成这几条（不带、空的是都拿掉）；一天之内到点推过的同一条（配对、`id`
  一样）不再放。也只在内存里
- 样子不对 400 `bad`；访客发的是 403 `denied`

### 数据端口

普通的 TCP（cca 的辅助程序在 Linux 上没有 TLS）。连上先说一行可见的 ASCII，凭票据进：

```
CCA-RELAY/1 <角色> <编号> <cn> <mac>\n
```

- 角色 `host`（会话的控制连接）、`view`（接入方）：编号是票据的 `tid`，`mac = b64url(HMAC(tkey, "c" 角色 编号 cn))`（不带 `=`）
- 角色 `join`（宿主为一个接入方另连的那一条）：编号是服务器在控制连接上给的令牌，`mac = b64url(HMAC(控制连接那张票据的 tkey, "j" 令牌 cn))`
- `cn` 是客户端出的 16 个十六进制字符。服务器认了就回 `CCA-RELAY/1 OK <b64url(HMAC(同一把密钥, "s" 编号 cn))>\n`（它也证明自己认得这张票据），
  不认回 `CCA-RELAY/1 ERR <原因>\n` 后断开（`ticket`、`bad`、`nohost`：宿主那头不在、15 秒没连上来，`taken`、`sessions`、`slow`）。
  认证码不对的不算用掉票据。客户端只认这几个词，别的不原样显示

控制连接上之后是帧 `类型(1) 长度(2，大端) 内容`：宿主说 `0x08` ANNOUNCE（JSON `{pid: 说明的密文}`，换掉以前的）、`0x06` PING、
`0x09` BYE（会话结束了）；服务器说 `0x02` JOIN（JSON `{"token":…,"pid":…}`：有接入方来了）、`0x07` PONG。控制连接断了会话留 60 秒等它重连
（这期间 `online` 是 false、接不了）。同一个会话新的控制连接顶掉旧的。帧不对（太长、ANNOUNCE 不是 `{pid: 密文}`）、
只发不收让服务器待发的攒到 256 KB：断开这一条。数据端口是一条线程管着所有连接：哪一条出了没料到的错只断开它自己，记一行、接着转别的。

接入：接入方的 `view` 连接先等着；宿主收到 JOIN，拿令牌另连一条 `join`；两条都收到 OK 以后原样对接，服务器只转字节（一头写不动时不读另一头；
一头断了，把还没转给另一头的写完再关）。90 秒一个字节都没有的连接断开。配对取消了、设备被移除了，正接着的也断开。

### 两头之间的通道

对接好以后先握手（`pid`、`sid` 是 16 个字节，`fpH`、`fpV` 是各自配对时记下的宿主、接入方的指纹，`Ka = HMAC(P, "cca-remote/v1/auth")`）：

1. 接入方 → 宿主：`"CR" 01 01 nV(32) pid(16)`
2. 宿主 → 接入方：`"CR" 02 01 nH(32) tagH(32)`，`ctx = 01 pid sid nV nH fpH 00 fpV 00`，`tagH = HMAC(Ka, "host\0" ctx)`
3. 接入方核对 tagH（不对就什么都不再发），→ 宿主：`"CR" 03 tagV(32)`，`tagV = HMAC(Ka, "viewer\0" ctx tagH)`；宿主核对 tagV（不对就断开）

宿主不认这个配对（没有、取消了、不让它接入）、版本不一样时回 4 个字节 `"CR" 7F 原因`（1 不认这个配对，4 版本不一样）就断开。

`Ks = HMAC(Ka, "session\0" ctx tagH tagV)`，两个方向各一对密钥：`HMAC(Ks, "h2v-enc")`、`"h2v-mac"`（宿主发的）、`"v2h-enc"`、`"v2h-mac"`。
之后是记录：`序号(8，大端，每个方向从 0 起) 密文长度(2) 密文 认证(16)`。明文是 `长度(2) 内容 零补齐到 32 字节的整数倍`（内容最长 16384，
可以是空的：每 20 秒说一声，免得闲着的连接被掐）；密文是明文异或 `HMAC(enc, 序号 + 8 字节的块号)` 的密钥流；认证是
`HMAC(mac, 序号 密文长度 密文)` 的前 16 个字节。序号不是下一个、认证不过、补齐的不是零：断开。记录里装的是 cca 在这台机器上本来就用的那套帧
（`类型(1) 长度(4) 内容`：HELLO、INPUT、RESIZE、DETACH；WELCOME、OUTPUT、EXIT、NOTIFY、SIZE），当成一条字节流。不认识的帧接入方不理
（NOTIFY `0x16` 是后加的：内容是 JSON `{"title", "subtitle", "body"}`，一条通知——会话里的钩子推的，接入方弹出来；旧的接入方不认得它，照旧）。
SIZE `0x17` 也是后加的：会话现在的大小 `列(2) 行(2)`（大端），只发给 HELLO 的标志里带“能缩放”（4）的接入方（iOS 上的 cca App：会话比它的
屏幕大时缩小了画），接上时说一次（在回放前面），变了再说。会话照谁的窗口排：宿主自己的终端和不带 4 的接入方总算进去（取各处都画得下的），
带 4 的只有它最后打了字（鼠标的上报、焦点进出不算）时才算——谁最后打字照谁的大小；它接上时算它打了字（只看的不算）。旧的宿主不认 4：
照旧算进去，也不说 SIZE；3.7.4～3.7.6 的宿主接上时不算它打了字。

对方能做什么由宿主那头把关（配对表里写的），两个方向的帧都一个个看过再转：
- 接入方 → 宿主：只转头一个 HELLO、INPUT、RESIZE、DETACH。只让看的：HELLO 的标志上加“只看”（1）和“不算进窗口大小”（2），
  INPUT、RESIZE 不转（它敲不进键，窗口多小也不让会话跟着变）；别的标志（“能缩放” 4）原样转
- 宿主 → 接入方：只转 OUTPUT、EXIT、NOTIFY、SIZE（宿主的状态里有账号的邮箱、完整的路径、进程号，不给）
- 不让接入的不给它 ANNOUNCE（服务器也就不给票据）

### 限额

一台设备最多和 16 台配对、同时开 101 个可以接入的会话（100 个远程会话加上启动器）、手里 128 张没用掉的票据（3.7.10 以前是 8 个、16 张）；
数据端口同时 1024 个连接、同一个 IP 400 个（以前是 256、32）；连上 5 秒没说完开场白断开。

### 手机（访客）

手机上装不了 cca。3.7.0 起：iOS 上的 cca App（仓库的 `ios/`）拿和它配对的那台设备显示的二维码（里面有这台服务器的地址、证书公钥的
指纹和配对码，格式见 docs/dev/ios.md）配对，之后和 cca 的设备一样连这个端口（钉住证书）、经数据端口接入。开着中转就认手机；
`--no-guests`（或者环境变量 `CCA_GUESTS=0`）关掉：下面这些都没有，以前记下的访客的请求也一律不认（记录留着，再打开时还在）。认的时候
`/v1/health` 的 `relay` 里多一项 `"guests": true`。App 用的是 `ios/CcaRemoteKit`（`tests/ios_kit.rs` 拿它和真的服务器、真的 cca 对着测）。

**访客。** 手机不是 Team 里的设备、不在名单里，是和它配对的那台设备领进来的：

- `pair_open` 带 `"guest": true`：这次配对开给手机，回的里面多一项 `"guest": true`。不认手机（`--no-guests`）回 404 `no_guest`；旧版
  服务器不认这一项、照普通的配对开，回的里面没有它（设备看到没有就把这次配对作废）。3.7.0 以前的 cca 带的是 `"web": true`（开给网页端）：
  也是开给手机，回的里面多一项 `web`（网页端的地址：设备拿去显示，手机上打开它）；没开网页端（或者不认手机）回 404 `no_web`
- 开给手机、还没有别的设备放过密文的配对，不在设备清单里的密钥也可以 `pair_put`：请求里多一项 `pub`（`ssh-ed25519 AAAA…`，
  `key` 要是它的指纹），就拿这把密钥验这个请求的签名。知道 `rid` 才到得了验签这一步（`rid` 是配对码算出来的）。之后这次配对的
  `pair_get`、`pair_commit`、`pair_close` 也认它。别的情况（没有这次配对、不是开给手机的、已经有人放过、签名不对）回的都和
  不认识的设备一样（403 `denied`）：从回的内容里分不出是哪一种
- 两边 `pair_commit` 报的配对编号一样，服务器才把这把公钥记下来（`remote.json` 的 `guests`：`{指纹: {"key", "at"}}`）。记下来的访客
  只能发 `pair_put`（只进得了开给手机的配对）、`pair_get`、`pair_commit`、`pair_close`、`pair_drop`、`relay_attach`、`relay_list`、
  `push_set`（下面「推送」）；别的（`pair_open`、`relay_host`、`status_put`、`push_note`、上报、查询、同步）都是 403 `denied`
- 访客一个配对都不剩（取消了、180 天没用、领它进来的设备被移除了）就删掉。`pair_get` 回的 `name` 对访客是 null（它不在名单里：
  叫什么看它自己在密文里说的）

配对的密文、密钥、会话的说明、两头之间的通道都和上面写的一样：访客总是输入配对码的那一头（`b`）、接入方。

### 推送

手机锁着屏、App 没开着时，会话里的通知经苹果的推送服务（APNs）送过去（docs/dev/push.md）。推送服务的密钥只在维护者的服务器上的推送网关
（`cca-core team-push`）那里；这台服务器给了 `--push https://网关[:端口]` 和 `--push-pin sha256//…`（网关证书公钥的 SHA-256；也可以用环境变量
`CCA_PUSH_URL`、`CCA_PUSH_PIN`），开着中转、也认手机时才转，`/v1/health` 的 `relay` 里多一项 `"push": true`（没开时 health 和以前一样）。

- **登记**：手机（访客）发 `push_set`：`token`（推送服务给这台手机上这个 App 的令牌，64～200 个小写十六进制字符；空的是不要推送了）、`env`
  （`production`：App Store、TestFlight 装的；`sandbox`：Xcode 装的），可以带 `sids`：只推这几个会话（会话编号的列表，最多 8 个；手机上
  「已关闭的会话也推送」关着时是 App 里开着的那个，一个都没开着是空的列表），不带、`null` 是都推；3.7.5 起可以带 `usage`（`true`：也推额度的通知，
  下面「额度的通知」；不带、`false` 是不推）。回 `{"v":1,"ok":true}`，带了 `sids` 的多一项
  `"sids": true`（旧的服务器不认 `sids`、照旧都推：手机看这一项知道），带了 `usage` 的多一项 `"usage": true`（旧的服务器推不了额度的通知）；不是配了对的访客 403 `denied`，没开推送 404 `no_push`，
  格式不对 400 `bad`。记在 `remote.json` 访客那一项的 `push`（`{token, env, at}`，带了 `sids` 的另有 `sids`，要额度的通知的另有 `"usage": true`）；同一个令牌只记在一个访客上（后登记的算）；
  访客没了登记跟着没了
- **宿主交来**：控制连接上宿主说 `0x0a` PUSH（JSON `{"pid", "id", "note"}`）：给 `pid` 那个配对的手机推一条。`id` 是这条通知的编号（16 个小写
  十六进制字符；接入方收到的 NOTIFY 里也带着它：`{"title", "subtitle", "body", "id"}`，手机照它去重），`note` 是下面的密文。会话得是这条控制连接的、
  `pid` 得是这个会话给看的配对、配对的另一头得是登记了推送的访客（登记里带了 `sids` 的，这个会话得在里面），才转；对不上、样子不对的不理（不断开）
- **额度的通知**（3.7.5 起）：额度用完了，宿主发 `push_note`（`{"pid", "id", "note"}`，马上推）；额度恢复的那一条放在 `status_put` 的 `later` 里，
  这台服务器到点推（宿主那时睡着了也推得出去；推送的那条线程最多隔 15 秒看一眼）。配对的另一头得是登记了推送、带了 `"usage": true` 的访客才推
  （不看 `sids`：不是哪个会话的）；`push_note` 回的 `sent` 是推没推。转给网关的和会话的通知一样
- **转给网关**：`POST /v1/push`（TLS，只认 `--push-pin` 那把公钥：证书机构、名字、有效期都不看），内容 `{"v":1,"token","env","id","note"}`。网关回
  200 送到了、410 令牌没用了（这台服务器拿掉登记了它的访客的 `push`）、400 不收、429 太多了、502 推送服务出错、503 忙。这台服务器一条线程转，
  排不上就丢；每台手机攒得下 20 条、3 秒回一条
- **通知的密文**：明文 `{"v":1,"id","sid","at":秒,"title","subtitle","body"}`（紧凑的 JSON），空格补齐到 256 字节的整数倍；密钥
  `Kn = HMAC(P, "cca-remote/v1/note")`、`HMAC(Kn, "enc")`、`HMAC(Kn, "mac")`，认证 `HMAC(mac, "cca-remote-note\0" pid "\0" nonce 密文)`，
  照会话的说明那样封成 `{"n","c","t"}`（`c` 最长 3072 个字符）。手机上的通知扩展只拿得到 `Kn` 派生的这两把，拿不到 P。额度的通知是同一种密文，
  明文多一项 `"kind": "usage"`、没有 `sid`，另有 `event`（`used_up` / `back`）、`account`（这个配对里的账号编号）、`tool`、`name`、`machine`、
  `window`（`five_hour` / `seven_day`）、`resets_epoch`，可以有 `aid`（docs/dev/push.md「额度的通知」）；手机照 `window`、`resets_epoch` 自己写字，
  `title`、`subtitle`、`body` 是给认不出这一种的看的。认不出的 `kind` 手机照固定的那一句显示
- **网关交给推送服务的**：`{"aps":{"alert":{"title":"cca","body":"远程会话里有新的通知"},"mutable-content":1,"sound":"default"},"n":密文}`，
  `apns-push-type: alert`、`apns-topic: com.cca.remote`、`apns-collapse-id` 是 `id`、12 小时过期；令牌是 ES256 的 JWT（`kid` 是密钥的 Key ID，
  `iss` 是开发者账号的 Team ID）。手机上的通知扩展解开 `n`、换上真的字；解不开的照这一句显示

### 网页端

手机浏览器里的那一页（仓库的 `server/web/`，iOS 上的 App 做好以后去掉）：服务器把它发给手机的浏览器，页面自己配对、自己接入，
是上面说的访客。`--web-url https://域名[:端口]/` 才开（要和 `--relay-listen` 一起；`/v1/health` 里多一项 `web`）。地址照浏览器自己说的
那个样子记：主机小写，默认的端口（443）不写——WebSocket 的 `Origin` 要和它逐字相等。页面用的是 `server/web/core.js`，
`tests/web_relay.rs` 里的 `Guest`、`WsSock` 是照这一节独立写的一份。

**WebSocket。** 浏览器开不了普通的 TCP 连接，所以进数据端口的路是 `GET /v1/relay/ws?t=<tid>`（RFC 6455，版本 13，没有子协议、
没有扩展；`tid` 是 `relay_attach` 换来的那张票据的编号）：帧里的内容接起来就是本该发到数据端口的那条字节流（开场白那一行、握手、
加密的记录），服务器回的也装在二进制帧里。只认二进制帧（和它的后续帧）、ping（回 pong）、关闭；文本帧、没加掩码的、一帧超过 1 MB 的
断开。只在开着网页端时有（iOS 上的 App 不用它，走数据端口）。带了 `Origin` 的要等于网页端的地址（403 `denied`）。`tid` 要是一张还没过期、接入用的、还没有别的 WebSocket 拿它进来过的票据，
不然 403 `ticket`：没有凭证的人拿不到票据，也就开不了 WebSocket、占不了名额。票据的编号不是秘密，进中转靠的照旧是开场白里证明有
票据的密钥（证明不了的不算用掉票据）。之后和数据端口上的连接一样对待：同样的开场白、限额、5 秒没说完开场白断开；另有同时 64 条、
同一个 IP 8 条的上限（429 `busy`）。

**页面的文件。** `--web-root`（默认是程序旁边的 `web/`）里一层的文件，启动时读进内存，只发 `.html`、`.js`、`.css`、`.png`、`.svg`、
`.webmanifest`（名字只有小写字母、数字和 `. _ -`），`/` 是 `index.html`。每个回的都带 `Cache-Control: no-cache`、`ETag`（没变回 304）
和内容安全策略：脚本、样式、图片、请求、WebSocket 只认同一个源，不许被别的页面嵌进去。

**证书。** 浏览器只认证书机构签的证书。`--web-listen 地址:端口 --web-cert 证书 --web-key 私钥` 另开一个端口（同一个服务：同样的接口，
限流、用过的 nonce 是同一份），原来那个端口上自签的证书照旧给 cca 的设备用；证书文件换了（续上了）服务器一分钟内自己重新读。
启动时证书还没有、读不了（头一张要等证书助手去要）也照样起来，只是这个端口上一握手就断，每秒看一次，有了就用上；日志里说。
`--behind-proxy` 时 HTTPS 是平台做的，网页端就在同一个端口上。`--web-url` 是 `http://localhost:端口/` 时（本机试）`--web-listen`
只能听本机的地址、不用证书。这三项也可以用环境变量 `CCA_WEB_LISTEN`、`CCA_WEB_CERT`、`CCA_WEB_KEY`。

页面是这台服务器给的：管着服务器的人能换掉页面的代码，那以后配对的密钥、敲的键它都拿得到。两头之间的加密防得住只转字节的服务器，
防不住发页面的服务器——网页端只该开在自己管的服务器上。
