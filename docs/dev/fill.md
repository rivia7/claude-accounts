# 维护者的参考节点

映射本身见 policy.md；路由器端的其余部分见 router.md。

- 维护者的参考节点（`fill`）：映射仓库里的 `nodes.json`（`{"version": 1, "group": 组名, "proxies": [节点定义…]}`），`./policy.sh` 从维护者放在映射仓库目录里的 `custom.yaml` 抽出策略组（默认 `OpenAi`，`CCA_FILL_GROUP`）引用的节点生成，`custom.yaml` 本身绝不提交（已提交就拒绝发布）。签名命名空间是 `cca-nodes`，和 `cca-policy` 分开（两份签名不能互相顶替）；`policy_fetch` 两份都验过、查过格式（`fill_problems`，客户端和维护者同一套）才一起换上，仓库里没有 `nodes.json` 了就删掉本机的。本机的 `policy/nodes.json` 有节点密钥：在 `CCA_DIR_PRIVATE` 里，`cca restore` 的备份不打包（拉取时的临时文件 `policy/nodes.json.*`、`policy/tmp.*` 也不打包）。缺的节点**直接写进用户当前在用的配置文件**：OpenClash 选用的那份（uci 的 `config_path`）、ShellCrash 的 `yamls/config.yaml`——不在运行配置里补，钩子也不补。内置代理不写配置文件：生成内核的配置时照同一套规则补上（`core_defs`）。写法是 `router_rb` 的 `--fill-source`（在路由器上跑）：节点按块写法（`emit`，一键一行，值能不加引号就不加，交给 Psych 判断）插在 proxies 开头，`name` 排第一、那一行行尾带 ` # cca`；名字接在同名组块写法的 proxies 后面（引号照组里原有的成员），行尾也带 ` # cca`。以后按记号认出哪些是 cca 写的：维护者改了节点，带记号的那一项整个换掉（`span_end` 按缩进找到这一项的末尾）；2.8.0-beta.5～7 写成一行的改成块写法（内容没变时退出码 3：只换写法，不校验、不重启）；没记号的同名节点是用户的，不动。其余一个字节不动，写好的读一遍核对；组写成一行的只写节点。规则：同名的是用户的（只补进组）；名字被组/内置出站/ShellCrash 自定义节点占了的不写；摘要相同的用用户的名字（cca 写的不算）；`dialer-proxy` 缺的不写；relay、include-all 的组不动。辅助程序的 `fill_plan` 是同一套规则（合并路由器节点列表 `nodes-fill`、内置代理补节点 `core_defs`），两份要一致。映射要某个账号走参考节点、它又不在可选节点里时，`reconcile_all` 先把它加进可选节点（`policy_nodes_fill`，记下摘要；没有可选节点、删掉过的账号不算），映射里的账号随后照常加进来；不是参考节点的照旧要用户在 `cca router setup` 里选。写进去的不会主动删（参考配置里去掉的、卸载 cca 之后都留着）
- 参考节点进路由器靠账号表的 `fill`（带 `id`，没有参考节点时 `router_accounts` 和以前逐字节一样）。路由器端 `fill_source` 在 `apply`（同步，`FILLFORCE` 照读）、`ensure-now`（每次在家启动）、两套的钩子里跑；`/etc/cca/fill.seen` 记着账号表 + 配置文件 + 内核（大小、时间）的校验和，都没变时不再读配置文件（启动不变慢）。别处的节点这台路由器的内核不一定认，认不出 OpenClash / ShellCrash 整个起不来：每一版先拿内核 `-t` 校验（正在用的运行配置加上这些节点），通过了记进 `/etc/cca/fill.ok` 才写，找不到内核、校验不过都不写（原因记在 `fill.why`，`cca router status` 说）；写之前的配置文件留在 `/etc/cca/source.bak.yaml`。在跑的时候写了，记 `fill.pending`：`apply_now` / `ensure_now` 返回 3、说"只能重启一次"（获准后 `restart_now`，按写好的配置文件重新生成运行配置），不热加载。订阅更新会把配置文件整个换掉：ShellCrash 的钩子在它读订阅配置之前写回去，这次启动就有；OpenClash 的钩子在运行配置生成之后才跑，写回配置文件的同时用 `apply.rb --mirror` 照配置文件把这些节点也放进这次的运行配置（再重启就不用了）
- 自定义节点（local-proxy.md：`cca node add`、`cca node use`、App 的「自定义代理…」）走同一套：账号表另有一项 `custom`（`{"id": 摘要, "proxies": [可选节点里的自定义节点…]}`，辅助程序的 `custom_fill`；没有时 `router_accounts` 和以前逐字节一样，有了的机器升级后同步一次）。几台设备共用路由器时 `router_merge` 带这台的，再带上别的设备在用的（`others_custom`：回读的账号表 `custom` 里、名字是别的设备的槽位在用的，那个槽位的 `ck` 就是它、或者没带 `ck`）：订阅更新换掉配置文件以后，钩子照账号表把各台的都写回去，不用等那台再同步；卸载时 `router_evict` 也带着留下的设备在用的。同名、`ck` 不一样的：`router_push` 合并前先 `custom_clash_rename`——`py custom-clashes`（stdin 是回读的账号表和 owners）列出这台的哪些和别的设备正用着的同名节点不是同一个，`py node-rename 旧名 [路由器上的名字…]` 给这台的换个名字（`旧名-2`…，照 `node-check` 的起法避开，custom-nodes.json、可选节点、`node_ids`、各工具的账号表都跟着改；出口不变），`warn` 说一声；改名失败还撞上的，`merged_custom` 留别的设备的、这台的不写，stderr 提示。路由器端 `fill_has` / `fill_id`（`custom:<id>` 接在参考节点的 id 后面，两样哪个变了都重新校验）/ `fill_who`（说明里是“维护者参考配置里的节点”“自定义节点”还是两样都有，只有参考节点时说明和以前一字不差）/ `fill_label`（`cca router status` 那一行的开头）。`--fill-source` 把它们接在参考节点后面（`own`，起名时已经避开了参考节点的名字），同一套写法（块写法、行尾 ` # cca`、带记号的跟着改），只是**不进任何策略组**（账号的端口组 `CCA-n` 本来就列着全部可选节点）；同名的节点要是同一个（`ckey`：`nkey` 的 type、server、port、sni，再加 username、password、uuid——住宅代理常常是同一个网关、不同的用户名就是不同的出口）就当作有了；不是同一个的：没记号的（用户自己的）不写不改，带记号的（cca 写的）还有账号要用它（槽位的 `ck` 是它的，或者槽位没带 `ck`：旧版 cca 同步时丢了，或者别的设备把它当路由器上的节点选了）也不改，没人用了才换成新的（用户在外面改了这个节点）；没写的进 `cnote`（stderr 和 `cca router status` 第三行都说），名字被策略组占了、`dialer-proxy` 这里没有的也不写。生成端口池时逐个槽位核对：用自定义节点的槽位在账号表里带着 `ck`（这台的定义算的，辅助程序的 `custom_ck`：`ckey` 那几项照 Ruby 的 `to_s` 拼起来，取 64 位 FNV-1a 的十六进制；路由器端的 `fnv(ckey(…))` 同一个写法，路由器上的 ruby 不一定带 digest；`router_merge` / `router_evict` 给别的设备的槽位原样带着），配置里叫这个名字的不是它（或者没有）就只把这个槽位改为 REJECT、组里也不放它——宁可断开也不换出口，别的槽位照常（不过这个槽位 `select_all` 切不过去，和节点不可用一样，经路由器启动时都会停下：所以同步前先改名）。只有官方节点的账号表不带 `ck`，和以前逐字节一样。`--mirror` 也带上它们。Mac 端：`nodes-fill` 把路由器上还没有的自定义节点当成会补上的（选节点、核对节点时不算缺），`nodes-follow` 不管它们（不按摘要改名、不报丢失），`nodes_record` 记它们自己的摘要

## 测试
- 参考节点进路由器：回归 11b2b。`./policy.sh nodes` 从假的维护者 custom.yaml 抽节点，`nodes_pub [签名密钥]` 给 `$PR/nodes.json` 签名（命名空间 cca-nodes，11b6 也用），然后先后在 OpenClash、ShellCrash 上测：拉映射时写进配置文件、问过后重启（不热加载）、再同步不再写、旧的一行写法改成块写法、订阅更新换掉配置文件后钩子写回去、内核不认时不写（假的 mihomo 遇到 `$R/core_reject` 里写的文字就不通过 `-t`；`$R` 是 `$T/router`）、维护者改了节点跟着改、和用户同名的不动、非交互时不重启、签名或格式不对不换、和 ShellCrash 自定义节点重名的不写、组写成一行的只写节点；最后映射要某个账号走参考节点时自动加进可选节点。辅助函数 `rget`（Ruby 读配置）、`added`（只加了行、数带 `# cca` 的行）、`one_line`（换成旧版的一行写法）、`fill_tmp`（临时文件删干净没有）是这一节自己的。3.3.0-beta.8 删 Clash Verge 时这一节整个删掉过，后来恢复了路由器这一半
- 自定义节点进路由器：回归 11b2c（借用 11b2b 的 `rget`、`added`）。映射固定了节点的账号 `node use` 不问链接、不存；`node use 账号 socks5://…`（用户名密码带网址转义）在家时写进 OpenClash 的配置文件（不进组）、问过后重启、账号的端口切到它，密钥不进 ssh 的命令行；`cca router status`、`cca router nodes`；再同步不再写；订阅更新后钩子写回去；提问会话（`node.custom` 认不出时带原因重问，`consent.router_restart`，`result` 的 `saved`）；`_gui state` 的 `can.custom_proxy`；用自定义节点的槽位带 `ck`（`ckof` 在测试里另写一份算法核对）；多设备（`mdslot` 扮演另一台占一个空槽位，像 11a2 那样直接写路由器的 accounts.yaml + owners）：另一台同名、`ck` 不一样的槽位 REJECT（这台的照常，`ck` 原样带着），`ck` 一样的照常走；另一台在用的自定义节点这台同步时带着（写进配置文件，订阅更新后钩子也写回去）；这台改过的「Office」——另一台的槽位没带 `ck`、账号表里也没有 custom 时路由器端不换、说为什么，另一台正用着（custom 里有、`ck` 是原来的）时这台的改名为「Office-2」，只有这台时照新的更新；配置文件里同名、不是同一个的（用户自己改的）不写、端口 REJECT；还有账号在用的 `node rm` 不删。校验要下载内置代理的内核：这一节结束时连 `~/.cca/core` 一起还原（11b4 测第一次下载）
