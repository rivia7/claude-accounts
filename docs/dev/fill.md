# 维护者的参考节点

映射本身见 policy.md；路由器端的其余部分见 router.md。

- 维护者的参考节点（`fill`）：映射仓库里的 `nodes.json`（`{"version": 1, "group": 组名, "proxies": [节点定义…]}`），`./policy.sh` 从维护者放在映射仓库目录里的 `custom.yaml` 抽出策略组（默认 `OpenAi`，`CCA_FILL_GROUP`）引用的节点生成，`custom.yaml` 本身绝不提交（已提交就拒绝发布）。签名命名空间是 `cca-nodes`，和 `cca-policy` 分开（两份签名不能互相顶替）；`policy_fetch` 两份都验过、查过格式（`fill_problems`，客户端和维护者同一套）才一起换上，仓库里没有 `nodes.json` 了就删掉本机的。本机的 `policy/nodes.json` 有节点密钥：在 `CCA_DIR_PRIVATE` 里，`cca restore` 的备份不打包（拉取时的临时文件 `policy/nodes.json.*`、`policy/tmp.*` 也不打包）。缺的节点**直接写进用户当前在用的配置文件**：OpenClash 选用的那份（uci 的 `config_path`）、ShellCrash 的 `yamls/config.yaml`——不在运行配置里补，钩子也不补。内置代理不写配置文件：生成内核的配置时照同一套规则补上（`core_defs`）。写法是 `router_rb` 的 `--fill-source`（在路由器上跑）：节点按块写法（`emit`，一键一行，值能不加引号就不加，交给 Psych 判断）插在 proxies 开头，`name` 排第一、那一行行尾带 ` # cca`；名字接在同名组块写法的 proxies 后面（引号照组里原有的成员），行尾也带 ` # cca`。以后按记号认出哪些是 cca 写的：维护者改了节点，带记号的那一项整个换掉（`span_end` 按缩进找到这一项的末尾）；2.8.0-beta.5～7 写成一行的改成块写法（内容没变时退出码 3：只换写法，不校验、不重启）；没记号的同名节点是用户的，不动。其余一个字节不动，写好的读一遍核对；组写成一行的只写节点。规则：同名的是用户的（只补进组）；名字被组/内置出站/ShellCrash 自定义节点占了的不写；摘要相同的用用户的名字（cca 写的不算）；`dialer-proxy` 缺的不写；relay、include-all 的组不动。PY_SRC 的 `fill_plan` 是同一套规则（合并路由器节点列表 `nodes-fill`、内置代理补节点 `core_defs`），两份要一致。映射要某个账号走参考节点、它又不在可选节点里时，`reconcile_all` 先把它加进可选节点（`policy_nodes_fill`，记下摘要；没有可选节点、删掉过的账号不算），映射里的账号随后照常加进来；不是参考节点的照旧要用户在 `cca router setup` 里选。写进去的不会主动删（参考配置里去掉的、卸载 cca 之后都留着）
- 参考节点进路由器靠账号表的 `fill`（带 `id`，没有参考节点时 `router_accounts` 和以前逐字节一样）。路由器端 `fill_source` 在 `apply`（同步，`FILLFORCE` 照读）、`ensure-now`（每次在家启动）、两套的钩子里跑；`/etc/cca/fill.seen` 记着账号表 + 配置文件 + 内核（大小、时间）的校验和，都没变时不再读配置文件（启动不变慢）。别处的节点这台路由器的内核不一定认，认不出 OpenClash / ShellCrash 整个起不来：每一版先拿内核 `-t` 校验（正在用的运行配置加上这些节点），通过了记进 `/etc/cca/fill.ok` 才写，找不到内核、校验不过都不写（原因记在 `fill.why`，`cca router status` 说）；写之前的配置文件留在 `/etc/cca/source.bak.yaml`。在跑的时候写了，记 `fill.pending`：`apply_now` / `ensure_now` 返回 3、说"只能重启一次"（获准后 `restart_now`，按写好的配置文件重新生成运行配置），不热加载。订阅更新会把配置文件整个换掉：ShellCrash 的钩子在它读订阅配置之前写回去，这次启动就有；OpenClash 的钩子在运行配置生成之后才跑，写回配置文件的同时用 `apply.rb --mirror` 照配置文件把这些节点也放进这次的运行配置（再重启就不用了）

## 测试
- 参考节点进路由器：回归 11b2b。`./policy.sh nodes` 从假的维护者 custom.yaml 抽节点，`nodes_pub [签名密钥]` 给 `$PR/nodes.json` 签名（命名空间 cca-nodes，11b6 也用），然后先后在 OpenClash、ShellCrash 上测：拉映射时写进配置文件、问过后重启（不热加载）、再同步不再写、旧的一行写法改成块写法、订阅更新换掉配置文件后钩子写回去、内核不认时不写（假的 mihomo 遇到 `$R/core_reject` 里写的文字就不通过 `-t`；`$R` 是 `$T/router`）、维护者改了节点跟着改、和用户同名的不动、非交互时不重启、签名或格式不对不换、和 ShellCrash 自定义节点重名的不写、组写成一行的只写节点；最后映射要某个账号走参考节点时自动加进可选节点。辅助函数 `rget`（Ruby 读配置）、`added`（只加了行、数带 `# cca` 的行）、`one_line`（换成旧版的一行写法）、`fill_tmp`（临时文件删干净没有）是这一节自己的。3.3.0-beta.8 删 Clash Verge 时这一节整个删掉过，后来恢复了路由器这一半
