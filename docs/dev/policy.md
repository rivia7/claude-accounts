# 维护者的映射

参考节点（映射仓库里的 nodes.json）见 fill.md；设备统计的服务器见 presence.md。

- `./policy.sh 映射仓库的目录 ["提交说明"]` — 发布维护者的账号 → 节点映射：检查格式（`cca _policy-check`）、确认仓库是私有的，用发布密钥签名（命名空间 `cca-policy`），提交并推送。目录里有 `custom.yaml` 时顺带发布参考节点（抽成 `nodes.json`，`cca _fill-check`，命名空间 `cca-nodes`）；`./policy.sh nodes 参考配置 [策略组]` 只打印不发布
- `./policy.sh key [ls | add [公钥文件 | - | '公钥'] [别名] | rm 别名 | mv 别名 [新别名]] [-R 仓库] [-y]` — 维护者管理各台机器的 deploy key（经 `gh api`）：别名就是 GitHub 上 key 的标题，不许重复（命令里写的重复了、有终端时另问一个）；cca 给维护者的是一整行 `./policy.sh key add '公钥' 机器名`（`policy_prepare`；带空白和 `AAAA` 的参数当公钥），add 不写文件也不写公钥就读剪贴板，不写别名就提示（默认取公钥备注 `cca-policy@机器名` 里的机器名），总是加成只读；GitHub 的 deploy key 不能修改，mv 是删掉后用同一把公钥重新加（新的没加上时给出补回去的那一行 `./policy.sh key add -R 仓库 '公钥' '别名'`）。默认仓库从 `cca` 的 `POLICY_REPO_DEFAULT` 读（`CCA_POLICY_DEFAULT` 同样能换掉）
- 维护者的账号 → 节点映射（`cca policy`）：映射在维护者的私有 GitHub 仓库里，每台机器一把只读 deploy key（`~/.cca/policy/id_ed25519`），`policy_clone` 拉取时 `ssh -F /dev/null`、`IdentitiesOnly`、`IdentityAgent=none`、`GIT_CONFIG_GLOBAL=/dev/null`，主机公钥钉死（`GITHUB_HOST_KEYS`，`StrictHostKeyChecking=yes`）：ssh 先拿用户自己的 GitHub 密钥登录上的话，私有仓库只会回"不存在"。验签用 `RELEASE_KEY`、命名空间 `cca-policy`，通过才换上 `~/.cca/policy/policy.json`。强制在 辅助程序的 `reconcile`（每条命令读账号表都经过它）：映射里的官方账号节点不一致就改回并写回账号表；映射和账号表合并（`policy_merge`）：映射里有、这台机器上还没有的官方账号自动加进来（别名取映射可选的顶层 `aliases`，和本机别的账号重名就只写邮箱；已经在表里、键只是邮箱的映射账号，映射里有别名时补上（`policy_alias_fill`，只改键，端口、上次使用按邮箱跟着走）），这台机器自己的账号、起过的别名都不动。不加的（`policy_missing` 给原因，`cca policy` 列出来）：删掉过的（工具状态里的 `policy_skip`：`cmd_rm`、`cca edit`（`policy-have` / `policy-forget`，要在 `py validate` 之前记，否则 ctx 又加回来了）记下，`cmd_add` 清掉）、节点不在可选节点里的（加进来整张表就校验不过）、这台机器还没用过的工具（`policy_in_use`：当前工具或已有账号表；Codex 账号第一次用 cca codex 时才加，免得白占端口）。映射格式只能加旧版本会忽略的东西：客户端的 `policy_problems` 不查未知字段和 `aliases`（不合规的别名不用），只有维护者发布前的 strict 检查报错；改成旧版本认不出的格式，没自动更新的机器会一直用旧映射、跟不上节点调整。只有共享开着，config.json 才有 `policy` 这一项；每天的后台拉取（`policy_hook`）和自动更新的开关、开发模式无关。默认仓库是 `POLICY_REPO_DEFAULT`（`cca policy on` / `setup` 不写仓库、也没记着关掉前的仓库时用它；环境变量 `CCA_POLICY_DEFAULT` 可以换掉）。`policy_wait`（终端里等维护者：马上拉一次、之后每 5 秒自动再拉，`CCA_POLICY_POLL` 是测试用的间隔；回车马上再拉，s 先跳过，最多 30 分钟；GitHub 不认 deploy key（`POLICY_DENIED`）时不每次都说）直接从 fd 3 读（`read -t`：超时接着拉，读到头当跳过），不用 `ask`：`ask` 分不出回车和读到头
- 共享默认关着（用户完全独立使用：账号表里只有自己的账号，不生成 deploy key、不拉映射、不上报设备统计，也不用维护者确认这台机器）。终端里启动账号不引导配置映射；配置向导第 1 步先问「有没有维护者共享给你的账号？」（`onboard.share`，默认没有），服务器上直连不通时 `cca install` 同样先问（`install.share`：没有就 `builtin_own`，粘贴一条自己的代理当可选节点）。辅助程序里的闸门是 `policy_on()`（`core/policy.rs`）：config.json 的 `policy` 有值才算开着；config.json 不在算关着，读不了、不是对象算开着（设备统计的上报进程在 config.json 坏掉时照旧跑，和以前一样）；按文件的 (dev, inode, 大小, 修改时间) 缓存。映射文件都经 `policy_doc()` 读（`policy_raw`、别名、安装节点、`presence_server`），`policy_fill()` 关着时是 None：关掉以后才写回来的映射（关的时候后台正好在拉）不认
- 用哪个仓库只在两处算：`py policy-repo` 是开着的仓库（共享关着时是空的，`sharing_on` 就看它），`--known` 时共享关着就给关掉时记着的（config.json 的 `policy_was`：deploy key 加在它上面）；bash 的 `policy_repo_hint` 再退到维护者的默认仓库（`cca policy on`、配置向导第 1 步、服务器上的 `install.share` 不写仓库时用它），`policy_key_for 仓库` 看这台机器的 deploy key 是不是加在这个仓库上（是的话直接拉，不用再找维护者）
- `cca policy on`（`policy_setup` 不带仓库）：仓库是参数或 `policy_repo_hint`，都没有就问（`policy.repo`，空着是取消）。`policy_key_for` 的先直接拉（`py policy-set` + `policy_pull`：共享已经开着时就是再拉一次；关掉时留着的 key、维护者没撤销这台机器的，映射里的账号原样加回来；连不上 GitHub 也算打开了，之后每天再拉）；要维护者加公钥时 `policy_prepare` 给出那一行（换了仓库就换一把 key），App 里是 `policy_connect 仓库 on`（`policy_wait_page on`：和配置向导第 1 步同一页，选项说「先跳过」、页上说「加好后这里会自动打开共享」；选「不打开共享」是 `policy_decline`），终端里拉一次就走（之后每天自动拉）。成功是 `result` 的 `policy_on`（`policy_opened`：Claude、Codex 的启动器一起跟上），不打开是 `policy_off`
- `cca policy off [--forget-key]`：`py policy-off plan`（只读）说会动什么——要移出账号表的共享账号、自己的账号里用着只有维护者参考节点才有定义的节点的（`fill_only_nodes`：路由器没配置、参考节点里有、自定义节点和内置代理的节点缓存里都没有；关掉以后用不了，要换节点，不强制）；退出码 2 是本来就关着，3 是共享的账号正在用（命令行会话的登记、桌面 App 的进程开着：收起来以后会话收尾时找不到账号），`FAIL_CODE=policy_off_busy`。问过同意（`consent policy_off all`，默认否）以后先停掉设备统计的上报进程和折合金额的后台进程，`py policy-off apply [--forget]` 拿着锁再查一遍：共享账号记进各工具状态的 `parked`（`{账号目录名: {"key": 原来的键, "node": 节点}}`）、从账号表去掉（登录目录、钥匙串都不动），只有参考节点才有定义、关掉以后没有账号用的节点从可选节点里去掉，config.json 的 `policy` 换成 `policy_was`（记着仓库；`--forget` 不记）；账号表因此空了的机器记下 `onboarded`（App 不再当它是新装的）。先改账号表再改 config.json：中途断了共享还开着，下一条命令照映射把账号加回来。bash 再删拉到过的映射、参考节点、`checked`、日志、别的设备同步来的折合金额（`cost/remote.json`、`cost/sync.json`），`--forget-key` 连 deploy key 一起删（本来就关着时 `policy_decline`：也不再记着仓库）；有账号移出时同步路由器、改启动器。没有终端、没带授权时 `die "要先同意…"`（App 收到 consent 事件，问过带着 `CCA_GRANT` 重跑）
- 收起来的账号（`parked`）：重新打开共享时 `policy_merge` 照原来的键加回来（`parked_key`；别名和别的账号撞了就只写邮箱），同一个账号目录，不用重新登录；`reconcile` 看到它又在账号表里（打开共享加回来了，或者用户自己加回来了）就从 `parked` 里去掉。官方账号记下备查的 API key（`cca secrets forget` 清多余的 key 时）、邮箱助手的设置（`mail_forget_orphans`）都按收起来的账号留着；`cca restore` 退出登录前先 `py unpark` 放回账号表，好让它们也退出登录。`_gui state` 的 `config.policy` 带 `state`（`off` / `pending` / `on`）、`accounts`（账号表里映射的账号）、`parked`（PROTOCOL 2.2、4.12）。`policy_declined`（「不打开共享」时记的）现在不看它，只是留给旧版本：回退到旧版本时它们照它不在启动时引导配置映射
- App 的「共享与同步」（`SharingPage`、`SharingRow`，侧栏在远程会话下面）：只在 `config.policy` 带 `state` 时有（`PolicyConfig.switchable`；旧版 cca 没有这一页）。开关照 `state` 显示（`pending` 也算开着，侧栏挂「等维护者」），明细是 cca 给的仓库、`accounts`、`parked`，App 不重算。关掉是 `AppModel.setSharing(false)` → `CcaCommand.policyOff`（和同步路由器同一道闸、跑完为止；`consent policy_off` 先问，`policy_off_busy` 弹框说哪些账号正在用），打开是提问会话 `Handoff.policyOn`（`cca policy on`：问仓库、给维护者的那一行都在会话里）。契约测试 `SharingTests.swift`，截图场景 `sharing`
- 锁定请求（把账号的节点锁进映射）：别的机器只有只读 deploy key，改不了映射。`cca [codex] policy request 账号`（App 账号菜单的「请求维护者锁定节点」，`can.policy_lock`：官方账号、配置了映射、还没被映射固定）写一条维护者直接运行的命令 `./policy.sh lock claude|codex 邮箱 节点`（值经 `shlex.quote`，不带别名），不能请求时 `py policy-request` 退出码 2、stdout 是原因；在 App 里（有 `CCA_EVENTS`）stdout 就是那条命令，App 自己复制。维护者在 cca 的仓库里运行它（映射目录：`-C`、环境变量 `CCA_POLICY_DIR`，默认 cca 仓库旁边的 `cca-policy`）：`cca _policy-lock plan` 列出会改什么，问过才 `apply` 写进 policy.json（邮箱不分大小写，`-y` 不问），然后走照常的发布流程（检查、确认私有、签名、推送）。命令多半是别人发来的：控制字符、不合规的值不收也不原样显示（`cmd_policy_lock`）；节点不在 nodes.json 里时提醒（路由器上没有这个节点的机器，账号会用不了）；写进去了但没发布成时，再运行会提醒还有没发布的改动
- 映射的定时拉取（PROTOCOL 4.9）：`cca policy pull --json`，App 开着时一小时一次（`POLICY_POLL_INTERVAL`；`state.config.policy.next_check_epoch` 是 cca 算的，App 不重算，`PolicyPolling`、`Scheduler.updatePolicyPolling`）。拉到了马上照映射改账号表、同步路由器；要重载的不问（`consent` 事件忽略，留着 `pending`，用户点“同步”时再问）；拉不到不打扰，原因在 `$POLICY_DIR/log`（只留最后 200 行）。手动拉取（`AppModel.pullPolicyNow`，节点分流页的「拉取映射」、账号菜单的「现在拉取映射」）是同一条命令，不降优先级，结果照实提示，要重载时接着走 `syncRouter`（这次是用户点的，可以问）。`policy_pull` 会 `touch checked`，启动时的 `policy_hook` 不用再拉

- 映射：假 `git` 只管 `clone`，把 `$T/policy_repo` 里的文件拷过去，网址和 `GIT_SSH_COMMAND` 记在 `$T/git.log`；`touch "$T/policy_denied"` 模拟 deploy key 还没加上，`policy_offline` 模拟连不上 GitHub（带 git 自己的套话）。验签要用测试发布密钥，所以映射的用例放在自动更新那一节后面（那时装着的是 `mkver` 换成测试密钥的版本），映射用 `pol` 写进假仓库并签名
