# 在家还是在外、出口检测和泄露检测

- 在外面不连路由器：路由器同步留到回家后的下次启动（摘要对不上会自动补）；`at_home` 只探测 1 秒。从来没配置过路由器、只配置了本机客户端时（Linux 服务器；router-env 的 `LOCAL_SET`）`sync_if_changed` 不同步路由器
- 只经虚拟网卡连得到路由器不算在家（在外面开着 ZeroTier、VPN 也连得到家里的路由器，以前会被当成在家）：`at_home` 先 `route_iface` 查去路由器走哪块网卡（macOS `route -n get`、Linux `ip route get`，只查路由表；只查 IP：macOS 的 `route get` 会把主机名、不带 `-inet6` 的 IPv6 拿去解析，开着 TUN 时解析出来的是它的假 IP，所以主机名照旧直接探、IPv6 带 `-inet6`），是虚拟网卡（`VIRTUAL_IFACE_RE`：utun、ipsec、ppp、feth（macOS 上的 ZeroTier）、zt、wg、tailscale、tun、tap、Meta / Mihomo……；辅助程序的同名正则是同一份，回归 lint 核对）时，macOS 上绑定物理网卡（`phys_iface`：netstat 里第一条不是虚拟网卡的默认路由）再探（`PROBE_IF` → `nc -b`：在家开着 Clash 客户端的 TUN、路由器不在本网段时照样算在家），Linux 上不算在家；不绑定的同时再探一次，结果在 `ROUTER_REACH`（不多等）。不在家时一切照在外面办（不自动同步路由器、不拷节点定义；`cca router …` 照样经 ZeroTier 连）；`route: router` 时照旧走路由器。提示用 `away_what`（只经虚拟网卡连得到时照实说，不说“连不上”）；`_gui live` 的 `at_home` 是算不算在家，`router.reachable` 是经哪块网卡都算的连得上（`ROUTER_REACH`），连得上就看路由器的实况
- 出口检测结果：`coffee_check`（非 region 模式）之后 `py health-save` 记进账号目录的 `health.json`（600）；第三方 API 账号、端口不通用 `health_note`。泄露状态用 `leak-verdict` 输出的 `S<TAB>dns|webrtc<TAB>状态` 行（只在有横幅那一句时输出，`leak_finish` 只认 W / N / S 行），不要去解析 `LEAK_LINE`
- DNS / WebRTC 泄露检测（照 ip.net.coffee 的 DNS、WebRTC 检测页）只提示、不拦启动，而且不能拖慢启动：`coffee_check` 一开始就在后台跑 `py leak-probe`（和 trace、iprisk 同时），最后 `leak-verdict` 汇总成 `LEAK_LINE` / `LEAK_DNS` / `LEAK_WEBRTC`、写 `~/.cca/leak.json`（600）。DNS 经账号的端口：`<token>-n.d.ip.net.coffee/pixel.gif`（不等它做完，一秒后就去问）→ `/api/dns/result/<token>` → 解析器归属地（按 /24、/48 网段缓存 7 天：公共 DNS 的解析器换着来）；判定和检测页一样（有中国大陆的解析器、出口不在中国大陆）；按 `线路|节点` 缓存 6 小时（没测成 10 分钟），`cca check` 传开始时间强制重测、同一节点一次，而且多等一会儿（`LEAK_CHECK_DEADLINE` 20 秒，每个请求的上限也放宽：慢的线路上一次 HTTPS 要三四秒，启动时的 `LEAK_DEADLINE` 5 秒里问不到解析器；测成的缓存之后启动时也用）。WebRTC 是辅助程序直接发 STUN（connect 过的 UDP 套接字：端口不通马上报错；IPv6 只认真的，`::ffff:` 映射的不算），对方看到的 IP 和出口不同时，只有归属地是中国大陆才算泄露（`leak`，W 行），别的地区只是备注（`note`，N 行，不警告、不算问题），归属地查不到算没测成（`failed`，不能当作没问题）；归属地直连查（别经账号的出口，免得把两个 IP 关联起来）。命令行启动时 WebRTC 泄露只写在横幅里，`preflight app`、要在浏览器里登录时才 warn；`cca web` 照旧不做检测。服务器上（`login_remote`）没有账号专属的浏览器和桌面 App：`leak_start` 让 `leak-probe` 不测 WebRTC（结果里写明 `webrtc: off`；只是没有 `stun` 的结果照旧算没测成，`tests/isolation_leaks.py` 守着），`leak-verdict` 不说它（横幅只有 DNS，health.json 的 `webrtc` 是 null），`cca help` 只说 DNS 泄露。临时文件要写全模板（`mktemp "${TMPDIR:-/tmp}/cca-leak.XXXXXX"`：GNU、busybox 的 `mktemp -t 前缀` 没有 X 就失败，Linux 上以前一直没测成）。config.json 的 `leak_check: false` 关掉；出口本身不对（受限地区、拿不到 IP）时不等后台的结果

## 测试
- 出门在外：`touch "$T/away"` 让假 `nc`/`ssh` 连不上路由器（再 `touch "$T/vpn"`：模拟经 ZeroTier、VPN 连得到，不绑定网卡的 nc、ssh、经路由器端口的 curl 照样通，`nc -b`（绑定物理网卡）不通；探路由器的 nc 命令行记在 `nc.log`）；路由表是假的：`route -n get` 照 `$T/route_if/<地址>` 里写的网卡，`$T/tun` 时公网地址走 utun9（假 `netstat -rn -f inet` 也多一条 utun9 的默认路由），其余 en0；假 `ipconfig getpacket` 的 DHCP DNS 是 `$T/dhcp_dns`（默认 192.0.2.53）；`run` 带着 `CCA_RESOLV_CONF="$T/resolv.conf"`（系统的 DNS，只在内置代理要绑定网卡时读，不读真的 /etc/resolv.conf）。regress 11b4 里测开着 TUN 时的绑定、DNS 兜底、`core_bind: false`、经 ZeroTier 不算在家、在家开着 TUN 绑定网卡探路由器
- 泄露检测（regress.sh 3d）：假 `curl` 认 `*.d.ip.net.coffee/pixel.gif`（经哪个端口记在 `$T/dnsq/<token>`）、`/api/dns/result/<token>`（解析器取 `$T/dns/<端口>`，一行一个，默认出口那边的 `<网段>.53`；`$T/dns_down` 时连不上）、`/api/geoip/<IP>`（`$T/geo/<IP>.json`，默认美国；查到的按网段在 `~/.cca/leak.json` 里缓存 7 天，中途换了某个 IP 的假归属地要先删掉 leak.json，不然还是上次的；直连查的记成 `CURL direct`）。`run` 里 `CCA_STUN` 默认指向 `127.0.0.1:9`（不通，马上就知道 UDP 出不去，用例不用干等）；要 STUN 回答时开 `$T/fake_stun.py`（回 `$T/stun_ip` 里的 IP，端口写在 `$T/stun.port`，回答记在 `$T/stun.log`），用完 kill 掉、`STUN=` 清空
