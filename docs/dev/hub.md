# 自己的同步服务器（hub）

维护者共享以外的官方账号，设备统计、记下备查的 API key、折合金额经用户自己部署的服务器和自己的其他设备同步。界面上叫「自己的同步服务器」，命令是 `cca hub`，代码里叫 hub（`cli/src/cmd/hub.rs`）。别叫“中转”“relay”：那是远程会话的（remote.md）。服务器就是设备统计的那个程序，用 `server/cca-presence.py --mode own` 运行，请求和加入链接的格式见 server/README.md「自己的同步服务器」。三条管线本身（上报、API key、折合金额）怎么做见 presence.md、cost.md，这一份只写经哪台服务器、怎么加入。

- 要换成 Team（`cca team`：账号 → 节点由管理员的设备维护、每台设备一个邀请）：步骤见 team.md「迁移」的「自己的同步服务器 → Team」（`cca team import Team --mine`）。换完之前这一套照常用
- 账号走哪台（`route`）：第三方 API 账号、没有邮箱的哪台都不去；维护者映射里的官方账号走维护者的（它的数据是共享这个账号的各台设备的，不上自己的服务器）；别的官方账号走自己的（Antigravity 的官方账号也报设备统计，和维护者的一样；记下的 API key、折合金额只有 Claude、Codex 的）。`hub_of` 再看这台设备用不用得了那台：`hubs()` 里维护者的要共享开着、映射里有 presence 一节、有 deploy key（`presence_load`），自己的要加入了、密钥还在（`own_load`）；config.json 写着 `"presence": false` 时两台都不用。上报进程每台服务器一条线（`Lane`；自己的那一路的配置带着 `rev`，是 hub.json 的修改时间：重新加入以后算新的一路，从头报、不接着被移除那会儿的 10 分钟退避，它盯着 `~/.cca/hub/`，加入、退出马上醒来），`cca devices` 各台各问一次（终端里一台没问成照样显示别的那台，那一台说没问到；`--json` 有一台没成就是退出码 1），记下的 API key、折合金额各台各同步一轮（`cost sync --json` 的 `sync.hubs`，顶层是最要紧的那一台）。两台的状态文件分开：`HubKind::file`，自己的前面加 `own.`（`presence/own.keys.json`、`own.keys-sync.lock`、`own.status.json`，`cost/own.sync.json`、`own.remote.json`），维护者的文件名不变，不用迁移；盐、这台设备的指纹也各是各的，两台服务器上的账号摘要对不上。`presence/status.json`（上报进程没报成的原因）只在原因变了时写
- 加入（`cca hub join [--stdin] [--name 名字]` → `py hub-join`）：加入链接经 `ask_secret` 问（App 里是提问会话的 `hub.join`；配置向导里是 `HUB_JOIN_OPTIONAL=1 hub_join`：这一页 `optional`，留空是先不加入，返回 0），或者 `--stdin` 读，经管道交给辅助程序，不进命令行和环境变量。`link_decode` 核对前缀、校验、地址（`url_ok`）、指纹（`PRESENCE_PIN_RE`）、入伙口令（32 个小写十六进制字符）和盐（`PRESENCE_SALT_RE`，和映射里设备统计的盐一样认 32～128 个；生成的是 32 个）。第一次加入时生成这台设备在它上面的 ed25519 密钥（`~/.cca/hub/id_ed25519`；目录 700、文件 600），用它签 `join`（`pub`、`name`、`admit`、`check`）；名字默认是主机名，重新加入时沿用上次的。服务器回 200 以后才写 `hub.json`（`url`、`pins`、`admit`、`salt`、`name`、`joined_at`，600）、`members.json`、config.json 的 `device_id`，再在后台上报、同步一次（`agent_kick`、`keyshare_kick(true)`、`cost_kick_now`：`_cost-sync now`，不看上次同步过多久）；第一次加入没成什么都不留（刚生成的密钥也删掉，`join_post` 之后 `own_forget`）。stdout 一行一项：名字、地址、几台设备、关掉了同步时的原因（`"presence": false` 时照样加入，bash 说现在不经它同步）。已经加入了同一台（地址和盐的校验值一样）是重新加入（改名字、服务器丢了这台的记录时补上）；加入了别的要先 `cca hub leave`。以前加入过、没删干净的（密钥、经它同步来的）在加入新的一台之前删掉
- 失败的原因码：辅助程序的 stdout 是 `原因码\t原因`，bash 里成了 `FAIL_CODE=hub_原因码`（PROTOCOL 4.1）。加入时：`link`（链接不对）、`other`（加入了别的）、`name`、`sign`（生成不了密钥、签不了名）、`denied`（入伙口令不对：服务器对口令不对和签名不对一样回 403）、`salt`（409 `salt_mismatch`：链接里的盐和第一台设备登记的不一样）、`full`（507，最多 64 台）；别的请求和加入共用 `fault`：`pin`、`unreachable`、`old`（404：不是 `--mode own` 的服务器，或者太旧）、`clock`、`busy`（429）、`server`。部署时（见下面「部署」）：`usage`、`ssh`、`root`、`deps`、`image`、`port`、`taken`、`not_this`、`moved`、`host`、`install`、`start`，装好了加入没成时是加入的那些；加入着托管平台上的那一台时 `platform`（它没有 SSH）。托管平台（见下面「托管平台」）：`url`、`cert`（curl 51、60：证书验证不过）、`pending`、`not_hosted`、`seed`、`dir`。bash 自己的：`hub_not_joined`、`hub_no_device`、`hub_unavailable`、`hub_relink`（换加入链接没成）
- 设备标识：同一台设备在两台服务器上的指纹不一样，折合金额要认出是同一台：config.json 的 `device_id`（16 个十六进制字符，`router.rs` 的 `device_id`：几台设备共用一个路由器时早就有它），没有的话第一次加入成功时生成（`ensure_device_id`），以后不变。这台设备传的折合金额的明文里带 `dv`；`CostView` 按 `dv`（没有时按指纹）把各台归到一起，这台设备的 id 是 `device_id`（没有时是 `local`）；撤销了的设备照旧并进同名的新设备，只加新设备有数据以前的那些小时
- 别的命令：`cca hub [status [--json]]` 只读本机记着的、不联网（`hub_view`：三条管线最近一次的结果，`presence/` 的 status.json、keys.json，`cost/` 的 sync.json；`own_entry` 在加入了却用不了时把 state 换成 `off`（关掉了设备统计）或者 `error`，原因在 `error`）。`cca hub devices [--json]` 问服务器（op `members`），这台在前，`members.json` 记下几台（变了才写：App 盯着它）。`devices`、`remove`、`leave` 用 `own_cfg`（不看 `"presence": false`：管设备不是同步）。`cca hub remove 设备`（名字，或者指纹的开头）先问（`consent hub_remove 指纹`，默认不同意），移除以后它现在的密钥作废，是这台自己就是退出。移除了别的设备以后跟着换加入链接（`hub-remove apply` 里的 `relink`，见下面「换加入链接、服务器的记录没了」）：它留着的旧链接不能再用来加入，别的设备照旧；没换成（连不上……）时 stdout 是原因、退出码照样是 0，bash 是 `fail_warn hub_relink`（说怎么再换一次）。`cca hub leave` 先问（`consent hub_leave all`），先请服务器移除这台（连不上、服务器已经不认它了也接着退，说怎么在别的设备上移除），再删 `~/.cca/hub/` 和 `presence/`、`cost/` 里 `own.` 开头的；记下的 API key 留在这台设备上。`cca hub invite` 把加入链接打到 stdout（App 的「复制加入链接」经管道读）：先问一次服务器（`members`：别的设备换过的话换上新的；连不上照本机记着的打）；`--new` 先换一个（`consent hub_relink all`，默认不同意；`py hub-invite --new`，没成退出码 1、stdout 是原因，没加入是 2）。在 Claude Code 的会话里（`CLAUDECODE` 而且没有 `CCA_EVENTS`）不给：会进对话记录
- 凭证：`hub/hub.json`（入伙口令、盐）、`hub/id_ed25519` 和 `hub-hosted.json`（部署到托管平台、还没加入时的口令和盐）在 `CCA_DIR_PRIVATE` 里（cca 启动的 Claude Code 读写不了），`cca restore` 的备份不带它们（`hub-hosted.json` 写在 `--exclude` 里），也不带 `cost/own.remote.json`（别的设备同步来的）。restore 退出服务器（确认清单里说了；`py hub-leave apply`，连不上时说怎么在别的设备上移除这台）
- 界面 App（PROTOCOL 2.1 hello 的 `hub`；2.2 `config.hubs`、账号的 `hub`、`cost.sync.hub`；3.4 `devices --json` 的 `hubs`、账号的 `hub`；3.5 `sync.hubs`；4.13 `cca hub`；4.2 同意项 `hub_remove`、`hub_leave`、`hub_reset`、`hub_relink`；4.6 题号 `hub.join`、`hub.deploy`、`hub.password`、`hub.platform`、`hub.hosted`、`onboard.hub`）：`_gui state` 的 `config.hubs` 是 `hub_entries`（维护者的在前；只有自己的有 `members`、`joined_epoch`、`can_invite`、`pinned`（`hub_view`：加入链接里有没有指纹）），`can.devices` 就是账号的 `hub` 不是 null。Swift 模型在 `Protocol/Hub.swift`；旧版 cca 没有这些字段时，有「设备」一节的账号当作走维护者的（`Account.hub`、`CostSync.hub` 解码时补上；有这个字段时不认识的值当作 null）。App 盯着 `hub/hub.json`、`hub/members.json`、`presence/status.json`、`presence/own.status.json`、`cost/own.remote.json`、`cost/own.sync.json`（`CcaWatcher`）。页面见下面「界面 App」
- `cca policy off` 停掉上报进程（它告诉维护者的服务器这些会话停了）以后 `py presence-wake`（不带账号）再起一个：自己的同步服务器那一路接着报（中间会有一下子算离线）
- 服务器上最后一台设备退出以后，盐的校验值 `check` 和密文都留着：拿同一个加入链接还能回来；链接丢了要换口令（`cca hub deploy 服务器 --reset`，或者在服务器上运行安装脚本 `--reset`；托管平台上的：没加入的设备再运行 `cca hub hosted`，把平台上的 `CCA_HUB_ADMIT_HASH` 换成新的。服务器看到配置的口令的哈希变了，从头开始）
- 还没做的：托管平台的模板、一键部署的按钮（发布到平台上要维护者同意）；Railway、Sealos 上没真的部署过（步骤照它们现在的文档写，生成的 README 里说以平台现在的界面为准）。被移除的设备要是知道部署时的口令（`seed`），服务器的记录没了（`gen` 变了）以后还能拿它自己加回来：要挡住它只有从头部署（`--reset`、新的口令）。服务器的状态文件回滚到这台设备加入以前的一份（`gen` 一样）时，这台设备会被当成被移除了、删掉本机记着的（要重新拿链接加入）。`own_recover` 正在重新加入时恰好 `cca hub leave`，那次加入成了的话等于又加入了（`recover.lock` 只管 `own_recover` 之间，窗口极小）。另外 SSH 的目标不记：App 里「更新服务器…」预填的是加入链接里的地址和 root、22，经别的用户、端口、ssh 配置里的别名部署的要自己改

## 换加入链接、服务器的记录没了

- 换加入链接（`relink`：`hub-invite --new`，移除了别的设备以后的 `hub-remove apply`）：新的口令在这台设备上生成，服务器只拿到它的哈希（op `relink`，`own.admit` 换成它）和一份拿盐加密的新口令（`link_seal`：`blob_seal` 的格式，密钥是 `HMAC(盐, "cca-hub-link-v1")` 再分别 HMAC `enc`、`mac`，认证只带标签；明文 `{"a": 新的口令, "s": 部署时的口令 | null}`，格式见 server/README.md）。服务器回 `n`（换过几次），写进 hub.json 的 `link`。别的设备下次 `members`（`cca hub devices`、`invite`，App 打开「共享与同步」页）时拿到 `link: {n, blob, at}`，`n` 比自己记着的大就解开、换上（`link_refresh`，变了才写）：它们的 `cca hub invite` 给的也是新的。解不开（认证不过：别的盐）的不认
- 这一份记录的编号（`gen`）：服务器上没有状态文件、配置的口令的哈希变了（从头开始）时生成，`join` 和 `members` 回给设备，设备记在 hub.json；`members` 回的变了时换上，`link` 从头数（另一份记录）。加入时服务器还说用的是不是部署时配置的那个口令（`seed`：`admit` 的哈希和启动时配置的一样），是的话记在 hub.json 的 `seed`；换过口令以后加入的设备从解开的 `s` 里得到它（换的那台设备知道的话）
- 服务器不认这台设备了（403 `unknown_device`，带着服务器现在的 `gen`）：`presence_post` 里调 `own_recover`（`join` 不调）。`gen` 和记着的一样是被别的设备移除了：本机记着的和退出时一样删掉（`own_removed`），留下 `~/.cca/hub-removed.json`（哪台服务器、名字、什么时候；不放 `hub/`：退出、加入没成时整个目录会删掉），`cca hub`、设备统计、App 的原因都说被移除了、怎么再加入（`removed_note`）；之后不再自己加回去。不一样是服务器的记录没了（托管平台上没挂存储、数据目录删了……，配置的口令照旧）：拿记着的口令重新加入（`join_core`，名字照旧），服务器不认再试 `seed`（记录没了的服务器认的是配置的那个）；成了再发一次原来的请求。都不认（从头部署过、换了口令以后又丢了记录）时把这个 `gen` 记成 `stale`，不再为它试；连不上、别的错下次再试。上报、同步 key、折合金额几个进程可能同时碰到：拿着 `hub/recover.lock` 一个个来，轮到时 hub.json 已经变了（`hub_rev`）就当作别的进程处理过了。加入时没记下 `gen`、服务器没带 `gen`（以前的版本）的什么都不做
- 再加入（`join_core`）：被移除了的设备再加入时名字照移除前的（`hub-removed.json`），加入成了删掉它；没成时照旧留着。`hub-leave apply` 也删它（自己退出的没什么要说明：后台上报恰好在服务器移除了这台、本机还没删的那一下碰到 403，会当成被移除了写下它）。重新加入同一台（服务器的记录没了、再贴一次链接）时 hub.json 的 `hosted`（哪个托管平台）照旧
- 换链接（`relink`）的请求发出去以后这台设备退出了的，不再写回 hub.json（`save_json` 会建目录：写回去等于又加入了）

## 部署
- 同一份安装脚本也装 Team 的同步服务器（`--team-root`、`cca team deploy`：每个 Team 一个服务，和自己的同步服务器在一台机器上互不相干），见 team.md「部署」；bash 里问服务器、查登录、问密码的几段两种部署共用（`DEPLOY_PY`、`DEPLOY_WORDS`……）
- 安装脚本：模板 `server/hub-install.sh`（POSIX sh：dash、busybox ash、bash 都要能跑；`$变量` 后面紧跟中文要写 `${变量}`，服务器上的 sh 可能是 bash，回归的 lint 也查它）里标着 `# @CCA-HUB-EMBED@` 的那一行，`installer()` 换成版本（`CCA_HUB_VERSION`）、`hub-deploy` 给的那几项和服务端程序（函数 `hub_server_py` 里的 here-document，结束行是 `CCA_HUB_SERVER_PY_EOF`：服务端程序里不能有这一行，单元测试查）。模板和服务端程序都是 `include_str!` 编进辅助程序的：改了要重新编；`cca hub deploy --script`（`py hub-installer`）打出的、release.sh 放到发布页上的 `cca-hub-install.sh` 是同一份。模板本身不能运行（没有 `hub_server_py`：停下，说用生成的那一份）
- 服务器上装在 `/opt/cca-hub`（`--dir`：`/` 下面的一个目录，只认字母、数字和 `._/-`，没有空的、`.`、`..` 这样的一节，末尾的 `/` 去掉，不能在 `/usr`、`/etc`、`/home`、`/root`、`/run`、`/tmp` 这些下面（`DIR_HIDDEN`：systemd 方式的 unit 带着 `ProtectSystem=full`、`ProtectHome`、`PrivateTmp`，服务看不到、写不了那里，`/etc` 下面的还能起来、等设备加入要写状态时才出错；`/run` 重启就清掉）；安装脚本的 `dir_check` 和辅助程序的 `dir_of` 一样查。要是还没有、空的，或者以前装过的（有 `.cca-hub` 或者 `.env`）：别人的目录不碰，里面的 `data`、`certs` 会被 chown，卸载时会删。一台服务器只装一个：服务名、容器名都是 `cca-hub`，systemd 的 unit 里记着别的目录时停下）：`.cca-hub`（644，记着这个目录是安装脚本装的）、`app/cca-presence.py`（644）、`certs/`（700：`key.pem` 600、`cert.pem` 644，自签 P-256、10 年，没有才生成：macOS 的 curl 只给 RSA 和 P-256/P-384 做公钥钉住；私钥不出这台服务器）、`data/`（700，服务端的状态文件）、`.env`（600：`CCA_HUB_MODE`、`CCA_HUB_PORT`、`CCA_HUB_ADMIT_HASH`、Docker 的 `CCA_HUB_IMAGE`、`CCA_HUB_VERSION`）。Docker 的另有 `compose.yaml`（`docker compose -f compose.yaml`：目录里别的 compose 文件、override 不认；容器 `cca-hub`，用户 10001，只读的根、tmpfs 的 /tmp，去掉所有 capability、`no-new-privileges`，内存 256M、进程数 64，日志 3×1M；`certs/`、`data/` chown 给 10001），systemd 的是 `/etc/systemd/system/cca-hub.service`（系统用户 `cca-hub`、`EnvironmentFile` 是 `.env`、`ProtectSystem=full`、`ProtectHome`、`PrivateTmp`、`PrivateDevices`、没有 capability、`Restart=on-failure`）。文件都先写到旁边再 `mv`（`put`）。服务端用 `python3 -I` 运行（不看 `PYTHON*` 环境变量）。端口默认 18445（1024～65535），服务端在两种方式下都监听 0.0.0.0；起来以后等它在 127.0.0.1 上用这张证书回话（`openssl s_client`，最多 30 秒），起不来时打出最近的日志
- 运行方式：`--docker`、`--systemd`；不写时上次是 systemd、还能用就照旧，再是 Docker（有 compose 插件、`docker info` 通；只有老的 `docker-compose` 1.x 的不算：它认不得 `compose.yaml`，重建容器时还会出错），再是 systemd（`/run/systemd/system` 在、有 systemctl、python3 3.6 起、带 ssl）。镜像依次试上次用的、ECR 上的官方镜像、腾讯云和 DaoCloud 的同步源、Docker Hub（`docker pull` 每个最多 5 分钟；国内常常连不上 Docker Hub），都拉不到时、`docker compose up` 没成时（打出它说的最后 20 行）没指定 `--docker` 的改用 systemd（停掉、删掉半截的容器）。服务端 3.6 起能跑（3.7 才有的 `ThreadingHTTPServer` 换成 `ThreadingMixIn`，没有 `ssl.TLSVersion` 时用 `OP_NO_TLSv1*`）：CentOS 7、一些云厂商镜像里的 python3 是 3.6。两种方式之间换的时候停掉原来的那个，数据、证书、加入链接照旧
- 入伙口令的几种情况（脚本里的 `STATE`）：`new`（没装过）、`update`（只更新程序：口令、证书、数据、端口都不变）、`replace`（装过、还没有设备加入过：换一个新的口令。第一个链接丢了、端口没放行加入不成时再运行一次就行，不用记着上次的）、`reset`（`--reset`：换口令，服务端看到哈希变了从头开始）。有没有设备加入过看状态文件里 `own.check`（第一台设备加入时登记的盐的校验值）是不是 null，读不懂当作加入过。`update` 时换端口要 `--reset`（已经加入的设备认的是原来的端口）。`.env` 在起服务之前写（`write_env`），没装完（`die`，或者被打断：`trap` 了 HUP、INT、TERM、PIPE，SSH 断了以后往 stdout 写是 SIGPIPE）时换回原来的（`rollback`；第一次装的删掉），服务用新的 `.env` 起来了（`wait_served` 过了）才删掉 `.env.prev`、不再换回：下一次照原来的判断是哪种情况。不然 `--reset` 起不来以后不带 `--reset` 再运行，会把谁都不知道的新口令当作 update 用上（服务端看到哈希变了，从头开始）；起来以后再换回的话，跑着的服务和 `.env` 对不上，`--reset` 换掉的旧链接下次重启又能用了。所以打结果时 SSH 断了（设备那头是 `ssh`）服务器上已经是这一次的，这台设备照旧记着原来的，再部署是 `not_this`：先 `cca hub leave` 再 `--reset`
- 直接在服务器上运行（`sudo sh cca-hub-install.sh`）：有设备加入过就是 update，不然在服务器上生成新的口令和盐（`/dev/urandom` 各 16 字节），只在打出加入链接的那一刻在 shell 的变量里，服务器上只存口令的 SHA-256。链接里的地址是 `--host`，或者默认路由出去的源地址（是公网地址才认：云服务器的公网 IP 常常是 NAT 进来的，机器上看不到），都没有时有终端就问、没有就停下要 `--host`；stdout 不是终端时说一声链接可能进了日志。`--uninstall` 停掉、删掉程序、证书、数据、`.env`、unit 和系统用户（`cca hub deploy --script | ssh root@服务器 sh -s -- --uninstall`）
- `cca hub deploy [用户@]主机`（`py hub-deploy`）：入伙口令和盐在这台设备上生成（已经加入了的就是加入链接里的那一份；更新时服务器上配置的照**部署时的口令**（`configured_admit`：hub.json 的 `seed`，没有时先问一次服务器，还不知道是 `seed`，不拿现在的口令去碰：换过链接的话安装脚本会当成别的服务器）），安装脚本从 ssh 的 stdin 给过去，前面放进 `CCA_HUB_MANAGED=1`、`CCA_HUB_WANT`（口令的哈希）、`CCA_HUB_EXPECT`（这台设备加入着的那一份的口令的哈希：服务器上现在的不是它是 `not_this`，没装的是 `none`，bash 里都是 `not_this`。带不带 `--reset` 都查：加入了的设备只能更新、从头部署它加入的那一台，别的先 `cca hub leave`）和 `set -- --dir … [--port] [--docker|--systemd] [--reset]`；口令和盐不进 ssh 的命令行、环境变量，加入链接不打出来（别的设备要的用 `cca hub invite`）。ssh 带 `-T`（不要伪终端：脚本从 stdin 过去，ssh 配置里写了 `RequestTTY` 也不要）和 `ServerAliveInterval=30`（拉镜像时好几分钟没有输出）。在服务器上运行的是 `sh -c '…'`（登录 shell 不一定是 sh）：root 直接 `sh -s`，别的用户能免密码 sudo 就 `sudo -n sh -s`，要密码时什么都不运行、说用 root 登录（`root`）。脚本的进度写 stderr（ssh 转过来，直接给用户看），结果一行一项写 stdout（`report_managed`：`CCA-HUB mode|port|pin|state|ok`，没成是 `CCA-HUB fail 原因码 说明`），`report` 读，`fail_code` 换成 bash 的原因码。这台设备没加入、服务器上已经有设备加入过的不动（`taken`：在加入了的设备上 `cca hub invite`，这台 `cca hub join`；或者 `--reset`）
- 装好以后经 `join_with`（`cca hub join` 也是它）加入：已经加入了的照原来的链接重新加入（核对连得上；证书换了（服务器上的没了、重新生成）时换上新的指纹，bash 说别的设备要新的链接）。重新加入之前先拿新的指纹问一次设备（`refresh_admit`：`members` 不要口令）：别的设备换过加入链接、这台还没换上的话，记着的口令已经加入不了，问过以后照换上的加入；服务器的记录没了的话 `own_recover` 先重新加入，还加入不了再试 `seed`；没加入的、`--reset` 的用新的链接，地址是 `--host`、`--reset` 时原来链接里的（安装脚本按 `EXPECT` 核对过就是那一台），或者 `ssh -G` 的 hostname（ssh 配置里的别名也认得出真的地址），内网地址（10/8、172.16/12、192.168/16、100.64/10、127/8、169.254/16）说一声别的设备出门在外连不上。`--reset` 时这台设备记着的旧的先忘掉（服务器已经不认它了），名字照旧（`--name`，没写时 hub.json 里的）；服务器上没装成时本机照旧加入着原来的那一份。加入没成时服务器上已经装好了，本机什么都不留；连不上（多半是云服务商的安全组没放行）时说放行哪个端口、放行以后再运行一次（还没有设备加入过：换一个口令再加入）。已经加入了，`--host`、`--port` 和链接里的不一样是 `moved`（要 `--reset`）。`--reset` 先问（`consent hub_reset 目标`，默认不同意）。ssh 15 秒连不上算没连上；没有终端（App 里、`PROMPT_GUI`）时带 `BatchMode=yes`，ssh 退出码 255、又没有结果是 `ssh`。整个最多等半个小时。参数不对辅助程序先查（`opts`：`usage`，名字不对是 `name`），不连服务器；bash 自己查的（不认得的选项、没写服务器）也是 `hub_usage`。成了：stdout 是 `sh` 的 键=值（`mode`、`state`、`port`、`dir`、`lan` 地址只在内网、`name`、`host`、`members`、`off` 关掉了同步时的原因、`newpin` 证书换了），bash `eval` 它，说部署了还是更新了，`result` 的 `hub_deployed`
- App 里（`PROMPT_GUI`，不写服务器）：`hub_deploy_ask` 先问一页（`hub.deploy`：地址、SSH 用户、端口；加入着时预填 `hub_joined_at` 的地址，`message` 说是更新），再 `py hub-deploy 目标 --ssh-port 端口 --batch --check` 查登录得上不（`ssh_check`：只运行 `true`，什么都不装）。不成时 stdout 是 `ssh_trouble` 按 ssh 最后说的话分的原因码：`ssh`（连不上：地址、端口不对，主机名解析不了……，`SSH 连不上 目标：ssh 说的最后一行`）带着原因重问这一页；`ssh_auth`（密钥登录不了、服务器认密码或者 keyboard-interactive；还有 `Too many authentication failures`：ssh-agent 里的密钥太多，服务器只让试几次（`MaxAuthTries`），没轮到密码就断了，`LogLevel=ERROR` 时这是 ssh 说的最后一句）接着问密码（`hub.password`）；`ssh_keyonly`（服务器不让用密码、只认密钥）查登录时遇到的接着 `hub_pubkey_ask`：一页 `hub.pubkey` 给出在服务器上运行的那一行（`hub_key_file`：`~/.ssh` 里 ssh 默认会试的 id_ed25519、id_ecdsa、id_rsa 第一把有公钥文件的；`echo 公钥 >> ~/.ssh/authorized_keys`，用户在云服务商网页上的远程登录里运行），选「加好了，再试」再查（还不认带着原因重问，这回认密码了回去问密码）；还没有密钥的先问要不要生成一把（`ssh-keygen -t ed25519 -N ''`，`~/.ssh/id_ed25519` 已经有了、只缺公钥文件的不覆盖，说怎么补）；私钥有密码（App 里没法输）、要用别的私钥的选「在终端里部署」：`gui_terminal hub_deploy`，`argv` 是 `hub deploy 用户@地址 -p 端口`，App 照 `terminal` 事件交给终端。用密码那一次才看出来的 `ssh_keyonly`（多半是密钥太多，说在 `~/.ssh/config` 里写 `IdentitiesOnly`）、`ssh_hostkey`（主机密钥和 known_hosts 里的不一样：说 `ssh-keygen -R`）是 `hub_ssh`，停下。问到的密码经 `askpass_run`（和配置路由器的 `router_ssh_password` 共用：700 的临时目录里的 FIFO，写的一方是 bash 内建的 printf，askpass 读一次就删掉，ssh 再问读不到东西也不会卡住）交给 `--askpass --check`：用了密码还 `Permission denied`（服务器认密码）是 `ssh_denied`（密码不对，重问，最多三次：错得太多，服务器上的 fail2ban 这类会封这个地址；服务器两种都认时 ssh 一次连接错两回：keyboard-interactive 用了密码，`password` 拿到的是空的。很多系统默认不让 root 用密码登录（`PermitRootLogin prohibit-password`），却照样问密码、照样说 `Permission denied`：这边分不出来，用户是 root 时原因里提醒换成能免密码 sudo 的用户）；对了以后部署那一次也经它（部署只有一次要登录的连接：`ssh -G` 不登录）。App 里（`--check`、`--askpass`）没人能答要不要认这台主机：第一次连的认下（`StrictHostKeyChecking=accept-new`，和终端里答 yes 一样，变了照样拦；要 OpenSSH 7.6，Mac 上的都够新），命令行里没有终端（只有 `--batch`）的照旧不认没见过的主机（ssh 自己说 Host key verification failed），`LogLevel=ERROR` 不让「Warning: Permanently added」混进 ssh 最后说的那一行；`--askpass` 带 `PubkeyAuthentication=no`、`PreferredAuthentications=keyboard-interactive,password`、`NumberOfPasswordPrompts=1`，不带 `BatchMode`（它连 SSH_ASKPASS 也不问）。终端里不问这些：服务器写在命令行上，ssh 自己问密码、问要不要认这台主机（有终端时不带 `--batch`）；终端里没写服务器（App 失败页的「改在终端里完成」交过来的就是不带参数的 `cca hub deploy`）时 `hub_deploy_where` 先问地址（加入着的预填）、SSH 用户（root）、端口（22），没有终端的照旧说用法。App 里问着来的部署遇到 `taken` 时问要不要从头部署（`hub_reset_ok`：`consent hub_reset 目标`，说明里说可以在加入了的设备上复制加入链接；不同意是 `gui_cancelled`），同意了带 `--reset` 再部署一次。做完了、要人做点什么的用 `fail_warn`：`hub_newpin`（证书换了，别的设备要新的链接）、`hub_lan`（地址只在内网）、`hub_off`（关掉了设备统计）。`cca hub join` 在 App 里遇到空的、链接本身不对、服务器不认（`link`、`denied`、`salt`、`pin`）时带着原因重问（`ask_secret` 的 `error=`，密文不带回去），别的（连不上……）照旧停下
- 防火墙：脚本不动。systemd 的端口经 ufw、firewalld：开着又没放行时说放行的那一行（Docker 发布的端口不经它们）；云服务商的安全组最后总要说一句（经 `cca hub deploy` 时加入没成才说）
- 加入着托管平台上的那一台（加入链接里没有指纹）时 `hub-deploy` 不碰它：`platform`（带 `--reset`、`--check` 也一样，在连 SSH 之前；更新用 `cca hub hosted`；要改用自己的服务器先 `cca hub leave`）

## 托管平台

- `cca hub hosted [railway | sealos] [--dir 目录] [--name 名字]`（`py hub-hosted`，`cli/src/cmd/hub/hosted.rs`）：没有服务器时部署到 Railway 或者 Sealos（2026-11 调研过的两家：国外一家、国内一家；Cloudflare 那种要另写一份服务端，不做）。服务端是同一个程序，平台做 HTTPS：`--behind-proxy`（只说 HTTP；限流按 `X-Forwarded-For` 的最后一项，同一个 IP 的连接数不限）；平台的表单只填得了环境变量和一条命令，所以 `CCA_HUB_HOSTED=1` 等于 `--mode own --behind-proxy --listen 0.0.0.0:8080 --state /data/state.json`（端口固定 8080：Railway 的 `PORT` 不用，`railway domain --port 8080`），`/data` 不在时不启动；口令的哈希是 `CCA_HUB_ADMIT_HASH`。设备照系统的证书机构验平台的证书：加入链接里没有指纹（`pins` 是空的，curl 不带 `-k`、`--pinnedpubkey`；验证不过是 `cert`）
- 平台：参数里的，没写时 `py hub-hosted platform`（加入着的 hub.json 的 `hosted`，再是还没加入时记着的），都没有就问（`hub_platform_ask`：App 里 `hub.platform`，终端里 1/2；没有终端、不在 App 里时 `need_tty`）
- `py hub-hosted files 平台 [--dir 目录]`：生成部署文件（默认 `~/cca-hub-<平台>`；目录里只能有这几个文件和点开头的，不然 `dir`；这几个文件再运行时照样覆盖——更新要的——`fs::put` 跟着符号链接写，目录里有人放了同名的链接时写到它指的地方），stdout 是 `sh` 的 键=值（`platform`、`dir`、`hash`、`update`、`steps`）。Railway 是 `Dockerfile`（`python:3.13-slim`、`ENV CCA_HUB_HOSTED=1 CCA_HUB_ADMIT_HASH=…`；不用 railway.json：它的 config-as-code 已经不推荐了，挂载存储也没写进文档）、`cca-presence.py`、`README.md`；Sealos 是 `cca-presence.py`、`README.md`（表单里的配置文件 `/app/cca-presence.py` 就是程序的内容）。`steps` 是要做的几步：Railway 是一行一行的命令（`cd 目录`、`railway login`、`init`、`add`、`volume add --mount-path /data`、`up --detach`、`domain --port 8080`；没有 `#` 注释：交互的 zsh 默认不认它），Sealos 是表单里各项填什么。文件里只有口令的哈希
- 还没加入：口令和盐在这台设备上生成，记在 `~/.cca/hub-hosted.json`（`{v, admit, salt, platform, at}`，600；不放 `hub/`：`own_forget` 删整个目录），再运行照旧用它（已经部署好的照样认），加入成了删掉。加入：`py hub-hosted join 地址 [--name 名字]`，地址只认 https 的（没写协议的补上，不带路径、`?`、`#`、`@`，没写端口补 443），没有记着的口令是 `pending`；经 `join_with` 加入（`pins` 空着），成了在 hub.json 里记下 `hosted`（平台）。bash（`hub_hosted`）：App 里一页（`hub_hosted_spec`：`steps`、Sealos 另有 `server`，都是 `code` 的字段；`url` 是 `text`，说明照平台说地址在哪），哪些原因重问在 `hub_hosted_why`（App 和终端共用）：`url`、`denied`（服务器不认这一份口令：多半是 `CCA_HUB_ADMIT_HASH` 抄错了）带着原因重问，`cert`、`unreachable`、`server`、`busy`、`old` 的原因后面加「刚部署的话，等一两分钟再点继续」（终端里是「再试」）重问，别的停下；终端里打出步骤，有终端时接着问地址（空着是以后再加入：再运行 `cca hub hosted` 照旧用记着的）。加入成了说的话和 `cca hub join` 一样（`hub_joined_say`）
- 加入着、链接里没有指纹：是更新（钉着指纹的是自己部署的：`not_hosted`）。生成新版的文件，哈希照**部署时的口令**（`seed`）：服务器启动时比的是它，换成现在的（换过链接的）会让服务器从头开始、所有设备都要重新加入。平台上配置的看不到（经 SSH 的有安装脚本按 `EXPECT` 核对），所以 `update_seed` 每次先问一次服务器（`members`）：换过链接的换上 `seed`（换链接的设备在密文里放了 `s`），服务器的记录没了的 `own_recover` 先重新加入；服务器不认这台设备（403：服务器从头开始过、拿记着的口令都加入不了，记下 `stale`）时不生成（`denied`：照它记着的口令生成会让服务器又从头开始），被移除了的是 `not_joined`；连不上就照记着的。还不知道部署时的口令是 `seed`（在部署它的那台设备上更新）。公网地址贴成了加入链接（`hub_is_link`：`cca-hub1.` 开头）时 bash 先挡住重问，不交给辅助程序、不回显（`HUB_NOT_URL`）。App 里一页是步骤，最后是 `next`（只有「更新好了」），`result` 的 `hub_hosted`
