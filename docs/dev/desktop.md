# 程序坞、Claude App 和启动器（macOS）

- 程序坞（`cca _dock-tidy`，辅助程序的程序坞一节）：cca 打开的实例（账号的 Chrome、Claude / ChatGPT App）、终端交接用完退出的系统终端，退出后去掉程序坞「最近使用的 App」里留下的图标（多开的每退出一个就多留一个，固定的 App 也照留）。经 cfprefsd（ctypes 的 CFPreferences）改 `com.apple.dock` 的 `recent-apps` 再 `killall Dock`（程序坞只在启动时读设置）；只在真有多出来的图标时才改、才重启；系统没开「显示最近使用的 App」、config.json 的 `dock_tidy: false` 时不动。实测的坑：① App 主程序退出了，它起的进程（同一个 coalition：setsid、`responsibility_spawnattrs_setdisclaim` 都逃不掉）、经 `launchctl submit` / `bootstrap` 交给 launchd 的任务还在时，LaunchServices 留着它的记录（`lsappinfo list` 里是 `(exited-with-subordinates)`），这时重启的程序坞照着记录把它加回去（和退出了多久无关）。所以等待、整理的进程由 `open -g -j -n -a ~/.cca/dock/cca-dock.app`（`dock_hand`，LSBackgroundOnly 的小 App，内容不对就重写）当作独立的 App 起，不能从 cca、终端里直接起；整理前还要等目标 App 的记录没了（`dock_exited`，越等查得越慢（`dock_poll`），最多 `DOCK_WAIT_MAX`；一起整理的里有的一直不清时，别的最多陪它等 `DOCK_GRACE` 就先整理）。② App 退出 1.5～2.6 秒后程序坞才把它记进最近使用：最近一次退出后至少等 `DOCK_QUIET`；几个先后退出的一起整理、只重启一次（都记进 `DOCK_DIR/exited`；`tidy.lock` 有人拿着就走，拿着的那个一起整理，放锁以后再看一眼有没有新记的）；重启后过 `DOCK_LOOK` 再看，又加回来了再等、再重启一次（最多两次）。③ 新起来的程序坞给每个在跑的实例、每条还留着的记录各加一个图标，不认原来的：重启前这些 App 的图标也拿掉（`dock_tidied`），不然多出一个。在跑的实例按 `ps -axo comm=` 数主程序（Info.plist 的 CFBundleExecutable：Chrome 的辅助进程不算），固定在程序坞上的 App 有一个实例用固定的那个图标。④ 路径形式的设置域（`/…/x.plist`）经 cfprefsd 时，同一个进程读不到自己、别的进程后来写的（普通的 `com.apple.dock` 没这个问题）：`CCA_DOCK_PREFS` 是这种路径时直接读写文件（只给测试）。等实例退出用 kqueue 的 NOTE_EXIT（`DOCK_WAIT`，不轮询），`DOCK_DIR/<进程号>.wait` 的 flock 保证一个实例只有一个在等（账号的 Chrome 每次被 cca 用到都会来一次）；`DOCK_DIR` 在用户临时目录的 `cca-dock`。HOME 不是这个用户真正的主目录、又没指定 `CCA_DOCK_PREFS` 时（测试的沙箱）不碰程序坞
- Claude App 多开只认 `--user-data-dir`（签名版忽略 `CLAUDE_USER_DATA_DIR`）；App 不加单实例锁，同一个资料目录绝不能开两份。`cmd_app` 先用 `app_pid` 查，真正启动时再持有账号 `app-launch.lock`（fd 9，不传给 App）复查；新实例须由进程树 + lsof 证明打开了账号资料文件，旧 Local State 不足以证明。`app_open` 也必须使用 `child_env` 的环境清理。
- 启动器图标的轮廓必须和原图标一样：标识伸出圆角方形，macOS 26 起会把整个图标缩小、关进灰框。看效果要导出 `NSWorkspace.iconForFile`（系统实际显示的样子），只看 icns 本身发现不了

- 没装桌面 App 时（`app_missing`）：Claude App 给下载页（`https://claude.ai/download`），ChatGPT App 给官方安装包 `https://persistent.oaistatic.com/codex-app-prod/Codex.dmg`（`codex app` 没装 App 时自己下载的就是它，从 codex 0.172 里取出来的；3.6.15 起，以前 App 里没有补救、终端里说用 `codex app`）：bash 的 `codex_app_missing` ↔ App 的 `Remedy.chatgptDownload`。官方换了地址时两边一起换

## 测试
- 程序坞（regress.sh 11d）：`run` 带着 `CCA_DOCK_PREFS="$T/dock/dock.plist"`、`CCA_DOCK_SETTLE=0`（等待都换成这么久），回归绝不能碰真的程序坞；`dk set 最近使用的 [固定的] [show-recents] | get | add App` 改、读这份设置（`cca-test dockpl`，`tests/tool/fake/dock.rs`；App 名写成 `A:nobid` 是不带 bundle id 的图标），`dkapp 名字 bundle-id [真程序]` 建假 App（要“开着”就拷一份 /bin/sleep 当主程序、按路径运行）。假 `killall` 记 `killall.log`（`$T/dock_readd` 里写 App 名：重启后把它加回来一次，第二行写 keep 每次都加），假 `lsappinfo` 回 `$T/lsappinfo.txt`（每次调用记 `lsappinfo.log`），假 `open` 在后台跑 `cca-dock.app`，跑完在 open.log 记 `DOCK-APP-DONE 进程号`（`dkwait` 等它，不干等）
- Claude App：`run` 里的 `CCA_CLAUDE_APP` 指向假的 Claude.app；假 `open` 遇到 `--user-data-dir` 会建 `Local State`（有 `open_noprofile` 时不建）
