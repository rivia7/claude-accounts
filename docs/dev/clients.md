# 装和更新客户端（Claude / Codex / agy）

- 辅助安装（`cca [codex|agy] install-cli`，bash 的「辅助安装」一节、辅助程序的 `install-node` / `install-env`）：用三家的官方安装脚本（`Tool.install_url`：claude.ai/install.sh、chatgpt.com/codex/install.sh、antigravity.google/cli/install.sh；`install_shell` 是 bash 或 sh），和官网的 `curl -fsSL … | bash` 一样，脚本自己下载、校验、装进 `~/.local/bin`。下载只走 https（`--proto =https`，跳转也是），拿到的不是 `#!` 开头的算没拿到。先直连（`--proxy '' --noproxy '*'`）；拿不到脚本、或者直连没装成（脚本自己下载不了）时，`install_node_pick` 挑节点、`consent install_proxy <节点>` 问过（默认是），再另起一个临时内核（cca 的 mihomo：只有 127.0.0.1 上一个入站 `cca-install`、组 `CCA-INSTALL`、`MATCH,REJECT`，不开控制接口；不碰在跑的内置代理、路由器），安装脚本拿到 `HTTPS_PROXY` 等指向它，装完 EXIT trap 停内核、删临时目录（`mktemp -d …/cca-cli.XXXXXX`，配置有节点密钥，600 + `O_EXCL`）。节点由 Team 的配置的 `install_node` 指定（`policy_install_node`：各个 Team 的配置里第一个写了的；仓库里不写真实节点），`install_resolve` 按同名、`node_alias`、参考节点或 `node_ids` 的摘要认；定义取 `core_defs()`（路由器拷的 + 参考节点）。没指定、这台机器没有它的定义时终端里现选（`q=install.node`，选了就算同意，不记下）。安装脚本在 `env -i` 的空环境里跑（PATH 前面加 `~/.local/bin`：在 PATH 里了安装脚本就不改 shell 的配置文件；`T.install_env`：claude 用 `cu_claude_env` 的一次性 `CLAUDE_CONFIG_DIR`，codex `CODEX_NON_INTERACTIVE=1`），stdin 是 /dev/null，输出给 stderr。实测（2026-11-12，临时 HOME、经临时内核和一个 REALITY 节点）：codex 0.167.2、Claude Code 2.1.322 装上了，`claude install` 没写 `~/.claude.json`，claude 的安装脚本自己留下空的 `~/.claude/downloads`；agy 的没实测。`need_bin` 在终端里（不是提问会话）先问要不要装，装好后 `find_bins` 重新找（`~/.local/bin` 不在 PATH 里也认），非交互照旧 `FAIL_CODE=tool_missing`；`cca install` 没找到 claude 时问（install.sh、`need_deps` 不再要求先装 Claude Code）。`cca codex|agy install-cli` 不建账号表（`main` 里跳过 `py init`）。Team 的配置的 `install_node` 是只加的字段：旧版本的 cca 不认识照样忽略，设备上 `doc_problems` 只查它是不是字符串。管理员用 `cca team node Team install 节点|-` 指定（3.6.1 起；以前只有从维护者的映射导入时写进去过，见 team.md「Team 的节点」）。App：`hello.install_cli`，账号页“没装 X 命令”旁边、`tool_missing` 的补救都是 `Handoff.installCLI`（终端）
- 客户端统一更新独立于 cca 自更新和账号初始化：`cca clients status|check [--force]|mode auto|off|auto-install on|off|install TOKEN [--json]`，处理已安装的 Claude（`com.anthropic.claudefordesktop`）和 ChatGPT（`com.openai.codex`），差异都在 `CuClient`（全局的 `CU` 是正在处理的那一个，和账号的 `T` 一样）；一个客户端没装、出问题都不影响另一个。自动模式默认只检查/准备，不自动安装；用户打开「允许自动更新」（config.json 的 `client_auto_install`，`cu_auto_install`：只在自动检查开着时算数，`mode off` 一起关掉）后 `check` 查完马上装（`cu_auto`：打开开关就是同意，不再发 consent；桌面客户端开着时记 `auto_wait`、那一行 `auto_install_pending`，下次检查提前到 `CU_AUTO_RETRY` 以后，App 看到它退出也检查一次；终端工具只装官方安装器装的），这时 App 的 `clients check` 要跑完为止（`CcaCommand.clientCheck(install:)`）。不新增关闭原生更新器的设置、不写 Claude configLibrary。官方下载必须无账号凭据和共享ID：ChatGPT 先用 cca GUI 内置固定公钥验 Sparkle Ed25519；Claude 的更新源（Squirrel 的 json，`device_id` 必填，每次现生成、不存）带 SHA-256 和大小，下载后比对。然后都安全解包并验证 bundle ID、Team ID、版本、架构、代码签名及 Gatekeeper。安装许可绑定包摘要与目标快照，目标被其他更新器改动则停止；任何替换前必须重验并保留可恢复的旧包。状态读取不调用会写账号配置的 `ctx()`。专项测试见 `tests/client_updates.rs`。
- 终端里的 Claude Code、Codex 也在客户端更新里（`CuCli`，`id` 是 `claude-cli`、`codex-cli`）：只查版本，最新版本从和它们自己检查更新一样的公开地址查（`CU_CLI_SOURCES`，按安装方式：官方安装器、npm、Homebrew）。官方安装器装的，用户确认后运行它们自己的 `update` 命令（已实测 2.1.317→2.1.319、0.166.0→0.167.0）：空环境、真 HOME（要装进 `~/.local`、`~/.codex`），PATH 要有 `~/.local/bin`（不然 codex 的安装脚本会改用户的 shell 配置），claude 用一次性的 `CLAUDE_CONFIG_DIR`（`claude update` 不要登录，这样不碰账号和 `~/.claude`，不带设备标识）。npm、Homebrew 装的只提示在终端里运行什么（要用户自己的环境和权限）。claude 平时会自己更新：`status` 现跑 `--version`，上次检查的结论过时了就不再给更新按钮
- ChatGPT App 的 `CODEX_SPARKLE_ENABLED=false` 阻断已核验26.1021.31345构建的共享appcast安装ID发送；可经 GUI「客户端更新」检查、下载并在用户确认后安装。不改变签名App、不伪装HOME、不声称隔离了全部appData/Canvas/GPU等系统特征。原生可选验证见 `tests/isolation_credentials.rs`、`tests/isolation_chrome_native.rs`，默认跳过真实进程测试。
