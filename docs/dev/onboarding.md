# 配置向导、表单和添加账号

提问会话本身的规矩见 gui-contract.md。

- 配置向导 / 默认 GUI 安装（引导式初始化）：`install.sh` 在 macOS 上跑 `cca install --gui`——基础安装（bin、PATH、别名、`py init`）之后装好并打开图形界面 App（`( cmd_gui )`），剩下的配置在 App 里走引导向导，不在终端里问；macOS 26 以前（`gui_os_ok` 为假）或 App 装不上/打不开时自动回退到终端引导。不带 `--gui` 的 `cca install` 仍是原来的终端引导（保留给 Linux、无头 macOS、高级用户；顺序照旧）。向导是 `cmd_onboard`（派发 `_onboard`，走和 `add` 一样的 `dispatch` 路径，只在 `PROMPT_GUI` 下跑），三步；开头先定下这次要问哪几步——不在 Team 里（`py team-list` 是空的）才问第 1 步，路由器、本机客户端都没配好才问第 2 步，开始时还没有账号（`keys0`）才问第 3 步——页标题写「第 n 步（共 m 步）」（`onboard_title` 照这几项数，设 `ONB_TITLE`；只有一步时不写）。维护者的共享开着（`sharing_on`：`py policy-repo` 有值，一键安装时带了 `CCA_POLICY_REPO`、以前打开过）时开头先 `onboard_policy_quick`：有 deploy key 才拉一次（拉不到、但有上次的 policy.json 又不是 GitHub 不认 key 也算拉到），拉到了接着 `team_adopt`（映射里有给这台机器的邀请就自己加入，第 1 步也就不问了）；向导不生成 deploy key、不出给维护者的那一页（`policy_wait_page` 只有「共享与同步」页的 `cca policy on` 用，见 policy.md）。① 加入 Team（`onboard.team`，confirm，默认否：「有没有 Team 的邀请链接？」，`detail` 说 Team 是什么、没有的话以后在「共享与同步」里加入或者自己建一个）：答有接着 `( TEAM_JOIN_OPTIONAL=1 team_join )`（`team.join`，这一页可以留空：先不加入，没有提醒；链接不对、服务器不认、过期了、用过了（`link`、`denied`、`expired`、`used`）带着原因重问，原因后面说留空是先不加入；别的原因没加入成时失败已经报给 App，`|| true` 让向导照样做完，以后在「共享与同步」里再加入）；加入成了、取到了配置的 `team_settle` 当场照 Team 的配置导入节点（没配置过路由器时）、加账号（配置还没同步下来是 `fail_warn team_sync`）。② 网络出口（`onboard.net`：router / builtin / skip，`detect_router` 定默认：探到装了 Clash 的路由器默认 router、地址预填（`ROUTER_HINT_HOST`），探不到、能用内置代理（`core_possible`）默认 builtin，都不行默认 router；加入了 Team、拉到了映射时页上说网络出口配好后 Team / 映射给的账号自动加进来）：router 复用 `cmd_router_setup`，builtin 是 `policy_import` + `onboard_builtin`，skip 只 `policy_import`（不结束向导）；这一步不问、路由器又用不了（本机客户端已经配好）时也 `policy_import`。`policy_import` 在没配置过路由器、有维护者的 policy.json 时 `py nodes-import`（导入映射里账号的参考节点，映射里的账号随即被 ctx 加进来；`cca policy pull` 和 App 的定时拉取也跑它：`policy_nodes_fill` 在可选节点是空的时不补）。③ 添加账号（`onboard.add`）：这时还没有账号问「现在添加第一个账号？」（默认是）；Team 给的、映射里的账号这次加进来了时问「还要再添加一个账号吗？」（默认否，`message` 说按 Team 的配置 / 维护者的映射加了谁）→ 复用 `cmd_add`。这次加了账号、路由器能用、摘要和上次同步的不同时 `router_sync_soon`（没成是 `fail_warn sync_failed`）。做完：`py onboard-done` 记下 `config.json` 的 `onboarded`，最后 `gui_done onboarded`。取消（`gui_abort`，`$(…)` 里也 `kill -TERM $$`）不记 `onboarded`，下次还能再来。串起来之所以成立：`FlowModel` 只在 cca 进程退出时收场，中途 `team_join`/`cmd_add`/`cmd_router_setup` 各自的 `result` 事件被最后一条 `onboarded` 盖掉（最后一个胜出），中途的 `fail` 事件累积成「做完了，要提醒」；App 收到新的 `ask` 就换页，所以 cca 能自己翻过没回答的页。`state.config.onboarded`（`onboarded(c)`：显式标记过、或已有账号 / 配过路由器 / 配过本机客户端 → true；旧版 cca 没有这个字段，App 当作已配置、不弹）驱动 App 首页的 `WelcomeBanner`（`AppModel.needsOnboarding` / `showWelcome`；首页「以后再说」只这次会话收起、不持久，走完向导才持久（中间哪一步先跳过都算；`cca _onboard --skip` 只记下、不配置）；首次运行（`needsOnboarding`）先不弹新手教程，让欢迎卡片带头（`Guide.startIfNeeded(skip:)`，`MainWindow` 的 `.task` 等 state 读到再决定）。题号 `onboard.team`（接着 `team.join`）/ `onboard.net` / `onboard.add` 在 PROTOCOL 4.6 的映射表里；测试 regress 10h（`sess` 驱动 `_onboard` 的各分支；那里都不在 Team 里，每条都有第 1 步，答案表里要写 `onboard.team`：路由器配好、已有账号时只有第 1 步，标题不写第几步、默认没有；答有、服务器连不上时向导照样做完，原因是 `fail` 事件（`team_unreachable`），最后的结果还是 `onboarded`，事件里没有邀请链接；答有、链接少一截带着原因重问（说留空是先不加入），留空交上来先不加入、没有 `fail` 事件；第 2 步的默认（探不到路由器默认内置代理，`CCA_GATEWAY` 探到路由器时默认路由器、地址预填）、在 `router.basic` 取消不记 `onboarded`；第 3 步默认是，没有可选节点时 `add.node` 只有「自定义代理…」；三步都问时标题是「第 1 步（共 3 步）：加入 Team」……「第 3 步（共 3 步）：添加账号」，有维护者的默认仓库（`CCA_POLICY_DEFAULT`）也不生成 deploy key、不拉）、11b2（共享开着、拉一下就拉到了映射：第 2 步的页上说拉到了映射，映射的账号加进来，第 3 步问还要不要再加、默认不加、说明加了谁）、11b1（`cca install --gui` 装并打开 App、老系统回退）。已经在 Team 里时不问第 1 步的那一支回归里还没有用例。
- 加账号不要求先配置路由器（没有路由器的笔记本）：`cmd_add` 只在路由器用不了、又一个可选节点（`py nodes-allowed`）都没有时才处理：服务器（`server_builtin`）照旧 `builtin_onboard`；别的先 `policy_import`，还是没有时，配置过路由器（有地址、只是现在用不了，比如密钥没了）或用不了自定义代理（`! node_custom_ok`）才先 `cmd_router_setup`（`ROUTER_FORM_WHY` 说还没有可选的出口节点），否则不配置路由器：`pick_node` 只剩「自定义代理…」一项（`add.node` 的 `message` 说明）。从来没配置过路由器（没有地址）时 `sync_if_changed`、`router_sync_soon` 不同步路由器（以前只看 `LOCAL_SET`：没配置路由器、也没配本机客户端的机器启动、加账号时会报同步失败），配置过、只是现在用不了的照常报。`cmd_add_api` 选了节点、没有路由器时，只在用不了内置代理（`! core_possible`）时才先配置路由器。`onboard_builtin`：`core_possible` 不过就 `local_unavailable`；否则 `py local-set client builtin` + `core_setup`（端口池还空时不起内核），设 `LOCAL_SET=builtin`；节点是 Team 的配置带的（加入时 `team_settle` 导入）、维护者映射里的参考节点（`policy_import`），或第 3 步加账号时粘贴的自定义代理。配置路由器时预先勾上的节点（`py nodes-preselect`）也包括映射里的账号要的（`policy_in_use` 的工具，不算 `policy_skip`），先连上映射再配路由器时它们默认选好。
- 配置路由器、配置本机出口（内置代理）、账号表的表单（`hello.forms`，PROTOCOL 4.6，`Handoff.needsForms`：旧版 cca 这几条问的是终端里的那一套，走终端）：`cmd_router_setup` 在 `PROMPT_GUI` 时走 `router_form`（地址、用户、端口一页，`port_open` 连不上的带着原因重问）、`router_key_install`（密码在 App 里输入）、`pick_nodes_form`（多选，现在的预先选好，`py nodes-lost` 拦住还有账号在用的节点）。SSH 密码不进命令行和环境变量：`router_ssh_password` 用 `SSH_ASKPASS`（`SSH_ASKPASS_REQUIRE=force`）+ 私有目录（`mktemp -d`）里的 FIFO，写的一方是 bash 内建的 printf，askpass 读完删掉 FIFO，ssh 再问时读不到东西也不会卡住；登录成功之后才写 config.json（配错了不盖掉原来能用的）。`cmd_local_setup` 只有一页确认（`local.builtin`：用不用内置代理；Clash Verge、手动配置那几页 3.3.0-beta.8 删掉了）。`cmd_edit` 在 `PROMPT_GUI` 时走 `edit_form`：`py edit-form` 出页面（第一行是表键的摘要，表在中途变了就重新出表单），`py edit-apply` 校验和写表（维护者固定的账号答案不算数；换域名时删掉账号表里的 `key`：是旧服务商的），App 不碰账号表、看不到 key。表单改不了的（不是 JSON、键写错了、有不认识的字段：`edit_unfixable` 把能改的项换成合格的值再校验）发 `terminal` 事件（`edit`）走终端。`terminal` 事件的 `router_setup`、`local_setup` 和补救按钮直接开表单（`AppModel.presentHandoff`、`apply`）
