# 配置向导、表单和添加账号

提问会话本身的规矩见 gui-contract.md。

- 配置向导 / 默认 GUI 安装（引导式初始化）：`install.sh` 在 macOS 上跑 `cca install --gui`——基础安装（bin、PATH、别名、`py init`）之后装好并打开图形界面 App（`( cmd_gui )`），剩下的配置在 App 里走引导向导，不在终端里问；macOS 26 以前（`gui_os_ok` 为假）或 App 装不上/打不开时自动回退到终端引导。不带 `--gui` 的 `cca install` 仍是原来的终端引导（保留给 Linux、无头 macOS、高级用户；顺序照旧）。向导是 `cmd_onboard`（派发 `_onboard`，走和 `add` 一样的 `dispatch` 路径，只在 `PROMPT_GUI` 下跑），四步；先数这次要出页的有几步，页标题写「第 n 步（共 m 步）」（`onboard_title` 设 `ONB_TITLE`，只有一步时不写）：① 维护者共享的账号：共享开着（`py policy-repo` 有值：一键安装时带了 `CCA_POLICY_REPO`、以前打开过）时，有 deploy key 的先 `onboard_policy_quick` 拉一次，拉到了（或拉不到、但有上次的 policy.json 又不是 GitHub 不认 key）这一步不出页、不算数，否则直接是 `onboard_policy` 那一页；共享关着时只在知道仓库（`policy_repo_hint`：关掉共享时记着的，或维护者的默认仓库）才有这一步，先问 `onboard.share`「有没有维护者共享给你的账号？」（confirm，默认否：答没有不生成 key、不拉映射，直接到下一步），答有接着 `onboard_policy`（还是这一步）：关掉共享时留着的 key 先直接拉（`policy_key_for` + `policy-set` + `policy_fetch`；共享开着、`onboard_policy_quick` 已经拉过的 `onboard_policy tried` 不再拉），拉不到才 `policy_connect`：`policy_prepare` 生成 key，`policy_wait_page` 发 `onboard.policy`（`code` 是给维护者的那一行，`choice`：skip 先跳过 / decline 不打开共享），边等边每 `CCA_POLICY_POLL`（默认 5）秒 `policy_fetch` 一次，状态（等着 / 拉不到的原因 / 30 分钟到了）变了才重发一页，拉到了直接往下走——这一页不用回答：`gui_answer_wait` 带超时读答案（bash 3.2 的 `read -t` 超时和读到头都是 1，按等了多久分），第一个参数是这一题先后发过的所有序号（只是换了说明的同一题，换页前点的答案照样认；别的序号丢掉）；decline 是 `policy_decline`（`py policy-decline`：去掉 `policy`、`policy_was`，记 `policy_declined`——旧版本回退回来时照它不引导）并删掉 key 和拉到的文件。「共享与同步」页的 `cca policy on` 用的是同一页（policy.md）。② 网络出口（`onboard.net`：router / builtin / skip，`detect_router` 定默认；路由器或本机客户端已配好时不问）：router 复用 `cmd_router_setup`，builtin 是 `policy_import` + `onboard_builtin`，skip 只 `policy_import`（不再结束向导）；`policy_import` 在没配置过路由器、有 policy.json 时 `py nodes-import`（导入映射里账号的参考节点，映射里的账号随即被 ctx 加进来；`cca policy pull` 和 App 的定时拉取也跑它：`policy_nodes_fill` 在可选节点是空的时不补，第 1 步先跳过的没有路由器的机器，维护者加好后靠定时拉取补上节点和账号）。③ 添加账号（`onboard.add`）：还没有账号时默认是；映射的账号这次加进来了时问「还要再添加一个吗」（默认否，`message` 说加了谁）→ 复用 `cmd_add`。已经有账号、又没有第 1 步（映射的账号不会这次加进来）时这一步不问、不算数；有第 1 步时先算上（`askadd`），到了这一步映射没加进新账号就不问：前面已经出过页（`n` 大于 0，页上说了共几步、算上了它）时号照样占着（`n` 加一），「共几步」前后一样，最后一页是「第 m 步（共 m 步）」；还没出过页时不算它（只剩第 4 步时标题不写第几步）。这次加了账号、路由器能用、摘要和上次同步的不同时 `router_sync_soon`。④ 自己的同步服务器（`onboard.hub`，confirm，默认否：「有没有自己的同步服务器的加入链接？」；`hub_joined_at` 说加入着时不问、不算数）：答有接着 `( HUB_JOIN_OPTIONAL=1 hub_join )`（`hub.join`，这一页可以留空：先不加入，没有提醒；链接不对带着原因重问，原因后面说留空是先不加入；别的原因没加入成时失败已经报给 App，`|| true` 让向导照样做完，以后在「共享与同步」里再加入），部署在「共享与同步」里（hub.md）。做完：`py onboard-done` 记下 `config.json` 的 `onboarded`，最后 `gui_done onboarded`。取消（`gui_abort`，`$(…)` 里也 `kill -TERM $$`）不记 `onboarded`，下次还能再来。串起来之所以成立：`FlowModel` 只在 cca 进程退出时收场，中途 `cmd_add`/`cmd_router_setup` 各自的 `result` 事件被最后一条 `onboarded` 盖掉（最后一个胜出），中途的 `fail` 事件累积成「做完了，要提醒」；App 收到新的 `ask` 就换页，所以 cca 能自己翻过没回答的页。`state.config.onboarded`（`onboarded(c)`：显式标记过、或已有账号 / 配过路由器 / 配过本机客户端 → true；旧版 cca 没有这个字段，App 当作已配置、不弹）驱动 App 首页的 `WelcomeBanner`（`AppModel.needsOnboarding` / `showWelcome`；首页「以后再说」只这次会话收起、不持久，走完向导才持久（中间哪一步先跳过都算；`cca _onboard --skip` 只记下、不配置）；首次运行（`needsOnboarding`）先不弹新手教程，让欢迎卡片带头（`Guide.startIfNeeded(skip:)`，`MainWindow` 的 `.task` 等 state 读到再决定）。题号 `onboard.share` / `onboard.policy` / `onboard.net` / `onboard.add` / `onboard.hub` 在 PROTOCOL 4.6 的映射表里；测试 regress 10h（`sess` 驱动 `_onboard` 的各分支；那里都没加入自己的同步服务器，每条都有第 4 步，答案表里要写 `onboard.hub`；第 1 步的答没有、先跳过、不打开共享带 `CCA_POLICY_DEFAULT=example/cca-policy CCA_POLICY_POLL=1`，`$T/policy_denied` 让假 git 一直拒绝；不知道仓库时没有第 1 步；路由器配好、已有账号时只有第 4 步，标题不写第几步；第 4 步答有、服务器连不上时向导照样做完；答有、链接少一截重问、留空先不加入；已有账号、第 1 步答没有时第 3 步不问，最后一页是第 3 步（共 3 步））、11b3c（第 4 步答有、贴链接加入了，最后的结果还是 `onboarded`；加入着时不问）、11b2（答案表里写 null：那一页不回答，等维护者加上后自己拉到映射进第 2 步、导入参考节点、映射的账号加进来）、11b1（`cca install --gui` 装并打开 App、老系统回退）。
- 加账号不要求先配置路由器（没有路由器的笔记本）：`cmd_add` 只在路由器用不了、又一个可选节点（`py nodes-allowed`）都没有时才处理：服务器（`server_builtin`）照旧 `builtin_onboard`；别的先 `policy_import`，还是没有时，配置过路由器（有地址、只是现在用不了，比如密钥没了）或用不了自定义代理（`! node_custom_ok`）才先 `cmd_router_setup`（`ROUTER_FORM_WHY` 说还没有可选的出口节点），否则不配置路由器：`pick_node` 只剩「自定义代理…」一项（`add.node` 的 `message` 说明）。从来没配置过路由器（没有地址）时 `sync_if_changed`、`router_sync_soon` 不同步路由器（以前只看 `LOCAL_SET`：没配置路由器、也没配本机客户端的机器启动、加账号时会报同步失败），配置过、只是现在用不了的照常报。`cmd_add_api` 选了节点、没有路由器时，只在用不了内置代理（`! core_possible`）时才先配置路由器。`onboard_builtin`：`core_possible` 不过就 `local_unavailable`；否则 `py local-set client builtin` + `core_setup`（端口池还空时不起内核），设 `LOCAL_SET=builtin`；节点是第 1 步拉到的映射里的参考节点，或第 3 步粘贴的自定义代理。配置路由器时预先勾上的节点（`py nodes-preselect`）也包括映射里的账号要的（`policy_in_use` 的工具，不算 `policy_skip`），先连上映射再配路由器时它们默认选好。
- 配置路由器、配置本机出口（内置代理）、账号表的表单（`hello.forms`，PROTOCOL 4.6，`Handoff.needsForms`：旧版 cca 这几条问的是终端里的那一套，走终端）：`cmd_router_setup` 在 `PROMPT_GUI` 时走 `router_form`（地址、用户、端口一页，`port_open` 连不上的带着原因重问）、`router_key_install`（密码在 App 里输入）、`pick_nodes_form`（多选，现在的预先选好，`py nodes-lost` 拦住还有账号在用的节点）。SSH 密码不进命令行和环境变量：`router_ssh_password` 用 `SSH_ASKPASS`（`SSH_ASKPASS_REQUIRE=force`）+ 私有目录（`mktemp -d`）里的 FIFO，写的一方是 bash 内建的 printf，askpass 读完删掉 FIFO，ssh 再问时读不到东西也不会卡住；登录成功之后才写 config.json（配错了不盖掉原来能用的）。`cmd_local_setup` 只有一页确认（`local.builtin`：用不用内置代理；Clash Verge、手动配置那几页 3.3.0-beta.8 删掉了）。`cmd_edit` 在 `PROMPT_GUI` 时走 `edit_form`：`py edit-form` 出页面（第一行是表键的摘要，表在中途变了就重新出表单），`py edit-apply` 校验和写表（维护者固定的账号答案不算数；换域名时删掉账号表里的 `key`：是旧服务商的），App 不碰账号表、看不到 key。表单改不了的（不是 JSON、键写错了、有不认识的字段：`edit_unfixable` 把能改的项换成合格的值再校验）发 `terminal` 事件（`edit`）走终端。`terminal` 事件的 `router_setup`、`local_setup` 和补救按钮直接开表单（`AppModel.presentHandoff`、`apply`）
