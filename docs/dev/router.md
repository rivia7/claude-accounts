# 路由器端（OpenClash / ShellCrash）

参考节点写进路由器的配置文件见 fill.md；界面 App 里的路由器实况（`_gui live`）见 gui-contract.md。

- 路由器上可能是 OpenClash，也可能是 ShellCrash（juewuy/ShellCrash 1.9.0 起，1.9.4 在真实路由器上验证过）：`router_sh` 末尾先跑 `backend`，按在跑的内核进程（ShellCrash 的叫 `CrashCore`，OpenClash 的叫 `clash`）、再按开机自启认出用的是哪套，设好 `$BK`（oc / sc）和 `$NAME`（文案里一律写 `${NAME}`，Mac 端 `clash_name` 按输出里的名字问"现在重启 X 吗"）；`install_hook` / `remove_hook` 两套都管（都装了就都装上）。ShellCrash 的钩子是它启动前任务文件里不带 `#` 的一行（它的任务菜单"清空旧版任务"会删掉带 `#` 的行）：它在拼运行配置之前 source 这个文件。这个文件 1.9.0–1.9.4 是 `task/bfstart`，下一版（GitHub 的 dev 分支）起是 `configs/task/bfstart`（升级时它把旧文件 `mv -f` 过去；运行目录也从 `command.env` 挪到 `configs/directories.env`，`sc_find` 两个都读）。`sc_task` 看它的启动脚本里 source 的是哪个，不看目录在不在（有的 1.9.4 上本来就有 `configs/task/`）；装钩子时把另一处 cca 的那一行删掉，免得它下次升级拿旧文件盖掉用户的任务。1.8 及更早没有这个钩子点，也不处理 listeners，不支持。钩子这一行把 `$core_config` 换成 `/tmp/cca.shellcrash.yaml`，即订阅配置原样复制、只在 proxy-groups / listeners 两段开头插入端口池（`apply.rb --insert`，插完再读一遍核对）。不能整份 `YAML.dump`：ShellCrash 按顶格的键用 sed 拆段再拼，它自己追加的入站（meta_listeners，两格缩进）和重排后顶格的项对不上，整份配置读不出来，连它的回退（基础配置）都起不来。插入的项写成 `{name: "…"}` 一行：ShellCrash 往组里加自定义节点时按 `- name: 组名` 前缀 grep，碰不到它们。ShellCrash 的节点只认订阅配置里的（`nodes` 列的、热加载时 `apply.rb --base` 限定的都是它）：自定义节点、策略组启动时才拼进来，自定义配置校验失败时又被去掉，端口池引用它们会让回退的配置也起不来。热加载 `PUT /configs` 的路径必须在 mihomo 的主目录（`-d`）里（真机：`/tmp` 下的回 400 path is not subpath of home directory），用 ShellCrash 放在主目录里的链接 `config.yaml`（`reload` 里处理）。ShellCrash 停止时把面板改过的选中项存进 `configs/web_save`、启动后还原，钩子删掉其中 `CCA-n` 的（`sc_unsave`）。它关了覆写时运行配置是链到订阅配置的链接：改运行配置一律用 `put_runtime`（换成文件，不写穿）。只支持 Meta 内核（`sc_meta`）；ShellCrash 的路由器不一定有 ruby，bundle 先查（`ruby -ryaml`）。`sc_cfg` / `sc_ports` 在子 shell 里 source 它的设置文件，`.` 一个不存在的文件会让 sh 直接退出，先 `[ -f ]`
- OpenClash 的运行配置文件可能被删掉（真实路由器上遇到过，内核照跑）：`ctl_init` 改从 uci 读控制接口的端口和密钥（`cn_port`、`dashboard_password`），`nodes` 改读 OpenClash 自己的配置；`apply_now` 各槽位切得过去就不动它，要建立或调整端口池时返回 3，获准后 `restart_now` 重启 OpenClash（钩子在启动时注入），不再报"成功"；切不过去的节点 OpenClash 自己的配置里也没有时（`in_source`），重启也没用，不提重启。Mac 端 `allow_reload "$out"` 看路由器的说明，要重启时问的是"现在重启 OpenClash 吗"
- 运行配置文件在、内核却落后于它（文件重新生成过，内核没重新加载；真实路由器上遇到过）：只比文件的结构会以为不用重载，切换被内核拒绝（400：它的组里没有这个节点），以前每次同步都失败。`select_all 运行配置`（`apply_now` 结构没变的那条路、`ensure_now`）遇到 400 而文件里这个组有这个节点时（`in_group`）返回 2，和组不在内核里一样问过再重载；文件里也没有的（节点不在路由器上）照旧返回 1，不提重载
- 多设备共用一个路由器（owners 认所有权）：两台 Mac 在同一个局域网里管同一个路由器时不互相覆盖端口池。`router_push` 推之前先抢锁（`router_lock_read`：路由器上 `/etc/cca/push.lock` 目录 + 里面的 ts，超 120 秒算陈旧破锁；`router_unlock` 放锁；抢不到就这次先不推、下次补），回读路由器现有的 `accounts.yaml` + 一个新文件 `owners`（槽位 → `device_id`，`cmd_router_merge` 输出的第四段；一次 ssh 把锁、accounts、owners 一起拿）。`router_merge`（PY）合并成并集：别的设备的槽位（owner 不是我）原样保留，我自己的、不在账号表里的去掉，共用账号（两台同一个邮箱）天然共用一个槽位；本机账号的端口写回并集槽位。`owners` 读不到（旧版 cca、全新路由器、升级前的备份还原）时当作全是我的 → 直接覆盖（和以前一样）。所有权记在**路由器侧**（owners 文件），不记在 config.json：`cca restore` / 手工还原 config.json 都不影响判断（早先把它记在 config.json 的 `router_mine` 会被还原回退、把我删过的账号误当别的设备的保留，改掉了）。`device_id` 是 config.json 里懒生成的随机串（非隐私、换路由器不变，`cfg_clean` 空了清掉）。`accounts.yaml` / `apply.rb` / 同步摘要都不变（owners 是另一个文件），单设备逐字节不变、不强制重新部署。启动前 `route_router` 回读校验「`ACC_SLOT` 上的账号就是我这个账号」（`router_slot_check` + `py slot-name`，按账号名认、和出口节点/改名无关）：对不上（别的设备或旧版 cca 改了槽位）就重新同步一次，还不对就停——宁可断开也不走错出口（`sync_if_changed` 只看本机摘要，拦不住别的设备的外部覆盖，所以要这步回读）。卸载按 owner（`router_uninstall` + `py router-evict`）：路由器还有别的设备时只撤这台的账号端口 + 这台的 SSH 公钥、保留分流（不整体删 `/etc/cca`），只有这台（或读不到 owners）才整体拆除。测试：`tests/router_merge.py`（单元：并集/共用去重/删号/owners 缺省覆盖），regress 多设备端到端（直接写路由器的 `owners` 扮演另一台设备，断言保留别人的槽位、卸载按 owner）
- 节点按「类型 + 服务器 + 端口 + TLS 域名」的摘要认（`node_fp`；TLS 域名分开走 CDN、共用服务器地址的节点；config.json 的 `node_ids` 只存摘要，不存地址），名字只是叫法：路由器上改了名，`nodes_follow`（`router_sync` 先跑它；`router_ensure` 有槽位切不过去、`sync_if_changed` 校验不过时也跑）按摘要把可选节点和各工具的账号表改成新名字，并记下 `node_renames`（维护者的映射里还写着旧名字时，`policy_map` 经 `node_alias` 换算，否则 `reconcile` 会把账号表改回旧名字、整张表校验不过）。认不出的（名字和地址都变了；或者认到的是另一个还在用的可选节点、好几个旧名字认到同一个新名字：这些不是改名，自动合过去会让账号悄悄换节点）交互时让用户选一个代替，用户选的不记进 `node_renames`（映射照样要求原来的节点）；旧名字在路由器上又出现了，那条换算作废。`node_replace` 要在 `while … <<<` 循环外面调用：循环里 fd 0 是 here-string，`interactive` 会把真实的终端当成非交互（同理 `cmd_check` 的循环从 fd 4 读）；循环里调 `rsh` 要加 `</dev/null`，不然 ssh 会把循环后面的输入读走。内置代理的节点定义里名字不同时按摘要换算（`local_names` → `core_names`：端口池、切换、启动前核对都用它那边的叫法），不改账号表。节点列表用 `router_node_list`：把这一版的 `router_sh` 经 `sh -s nodes` 现跑，不依赖路由器上部署的版本
- 路由器端只用 busybox 一定有的命令：OpenWrt 默认的 busybox 没有 `cksum`（真实路由器上遇到过，算摘要用 `sum_in`：md5sum → sha256sum → cksum → ruby），假路由器的 `rbin/cksum` 也照样报 not found
- 路由器的 `nodes` 输出里 `C<TAB>名字` 是 ShellCrash 的自定义节点（不能当出口，只给 `nodes-fill` 判断重名）：只取名字的地方要滤掉 `C` 行

## 测试
- OpenClash 重启：假的 `$R/etc/init.d/openclash restart` 按 OpenClash 自己的配置重新生成运行配置、跑钩子、让内核加载（router.log 记 `RESTART`，不算重载）；内核加载过的配置存在 `$R/core.yaml`，运行配置被删后切节点按它判断；`touch "$R/kernel_stale"` 时也按它判断（模拟内核落后于运行配置文件，regress.sh 8c）。regress.sh 10a 里 `node_rn` 改路由器上节点的名字和地址、`oc_restart` 模拟重启（这一节结束时还原路由器和账号表）
- ShellCrash（regress.sh 10a2）：假的 ShellCrash 模板在 `$T/shellcrash`（setup.sh 生成；`start.next.sh` 是下一版的启动脚本，只是任务文件换成 `$TASKCFGDIR/bfstart`，这一节末尾拿它换掉 start.sh、照它的 init.sh 搬任务文件和运行目录来模拟升级），这一节才拷进路由器根目录，并 `echo CrashCore > "$R/core"`（假 `pidof` 按 `$R/core` 认在跑的内核进程，没有这个文件时是 OpenClash 的 clash）；`sc_restart` 跑它的 start.sh：source task/bfstart（钩子在这里换 `$core_config`，换成哪份记在 `$T/sc_core_config`），按 ShellCrash 的做法按顶格的键拆段、拼出运行配置（自定义节点 SC-X 接在节点后面，有 `$R/sc_vmess` 时追加一个两格缩进的入站），读不出来记 `SCBAD`，再让假内核加载（记 RESTART）。假 mihomo 在 ShellCrash 模式下和真的一样只肯重载 `$R/etc/ShellCrash/` 下的文件，别的路径记 `UNSAFE_PATH`、回 400；membership 按 ShellCrash 的运行配置查
