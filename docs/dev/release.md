# 发布和更新（cca、界面 App）

规矩（正式版必须全流程、测试版可以先发后验）在根目录 CLAUDE.md 的「发布」。

- `./release.sh "更新说明"` — 先把 `cca` 里的 `VERSION` 改大，在 `macos/Sources/CcaKit/Model/WhatsNew.swift` 最前面写好这个版本“更新了什么”（`ReleaseNote(version: "版本号"`，界面 App 升级后第一次打开时给用户看；没有就不发布，顺便看看新手教程 `Guide.swift` 的 `TutorialCard` 要不要跟着改），再提交（工作区要干净）；先跑 App 的单元测试（不带参数的 `macos/test.sh`：夹具、各部件的单元测试，更新说明的用词和版本先后也在这里查；回归里只跑它解码真实输出的那部分），再跑回归、签名、编译界面 App（要命令行工具里的 swiftc 和 macOS 26 以上的 SDK）、打 tag、推送，发布 cca、cca.sig、install.sh、cca-app.zip、cca-app.zip.sig、cca-hub-install.sh（Team 的同步服务器的一键安装脚本，就是这一版 `cca team deploy --script` 打出来的那一份：release.sh 用这台机器的辅助程序、照发布的 cca 的走法生成（`CCA_SELF=接好辅助程序的那一份 cca-core hub-installer`：带的服务端程序就是它后面接着的 Linux 的那两份），核对 `CCA_HUB_VERSION='版本号'` 那一行、`CCA_HUB_CORES='X86_64 AARCH64'`，两种机器的服务端程序（here-document，结束行 `CCA_HUB_CORE_<机器名>_EOF`）解出来和编出来的一字节不差、和 `HELPER_SUMS` 记的、脚本里写的校验值（`CCA_HUB_CORE_SHA256_<机器名>`）是同一个、文件头是那种机器的静态链接的程序（`core_ok`），`/bin/dash -n`，不带只给 `cca team deploy` 用的那几项和以前 Python 的东西；约 10 MB；不另签名，要核对的用 `cca team deploy --script` 在本机生成，见 docs/dev/team.md「部署」）（整个约 25 分钟，大半是回归，同样放到后台跑）。`VERSION` 写成 `X.Y.Z-beta.N` 时发成测试版（GitHub pre-release、不设为 Latest）：`releases/latest` 不指向它，自动更新和一键安装都不装，只能 `cca update X.Y.Z-beta.N` 或 `install.sh` 后面跟版本号手动装；版本比较里同号的测试版比正式版旧（`ver_gt`）。**测试版（beta）允许「先发后验」**：已经单独跑过一轮完整回归、确认 PASS 之后，可以跳过 release.sh 里的回归步骤先发布（把 release.sh 复制一份到仓库外、删掉「跑回归测试」那三行、开头的 `cd "$(dirname "$0")"` 改成仓库绝对路径，这样仓库里的 release.sh 不动、`git status` 保持干净；单元测试和所有签名自检都保留），发布后立刻另开后台把完整回归再跑一遍验证；没过就撤回（`gh release delete v<版本> -R rivia7/claude-accounts --yes --cleanup-tag` 删掉 release 和远程 tag、`git tag -d v<版本>` 删本地 tag，必要时 `git push --force-with-lease` 回退 commit）。beta 是 pre-release，自动更新和一键安装本来就不装它，撤回影响很小。正式版（stable）不走这条，必须 release.sh 全流程、回归过了才发
- `cca` 和 `install.sh` 里各有一份 `RELEASE_KEY`，必须和 `~/.ssh/cca_release_ed25519.pub` 一致（release.sh 会检查）
- release.sh 在跑完回归后编通用版 App、`ditto` 打成 `cca-app.zip`、用发布密钥按 `cca-app` 签名，并确认这个签名在 `cca-release` 命名空间里不通过，和 cca 一起上传
- 检查更新（`cca update --check [--json]`，App 的「检查更新…」，PROTOCOL 5.1）：发布列表走 `api.github.com` 的 releases（`update_releases`，拿不到、被限流时退回 `releases/latest`：只看得到正式版），按现在的版本挑（测试版也看更新的测试版）；版本的先后 辅助程序的 `ver_key`、Swift 的 `AppVersion` 都和 bash 的 `ver_gt` 一样。自动更新、不带版本号的 `cca update` 不变（只看正式版）。App 带事件文件运行它（查不了的原因看 `fail` 事件，不读 stderr），一天最多自动查一次、查不了 3 小时后再查；开发模式看 hello 的 `dev_mode`。「更新并重新打开」先 `cca update 版本号`，再照常 `cca gui update` 两步
- 换了版本以后的第一条命令（`update_after`，`main` 的 `*)` 里 `update_hook` 之后、`policy_leftovers` / `team_hook` 之前）：删掉 `teams/checked`，这一次
  各个 Team 同步配置不等间隔（平时一个小时；在后台）——在 Team 里的设备一更新就拿到最新的配置（3.6.0 以前还删 `policy/checked`、马上拉一次映射）。`update/ran` 记着上一次运行的版本，和现在的不一样就是换了版本；以前的版本不记它，所以没有 `ran` 时要有
  更新留下的上一个版本（`update/cca.prev.version`：自动更新、`cca update`、一键安装再装一次都留着）才算，全新安装的两样都没有、不算。开发模式不做（不自动
  更新，也就没有更新后）。不经过启动钩子的命令（`_gui`、`team`、`cost`、`remote`、`update`、`install`、`version`）不算：换了版本以后第一条经过钩子的命令才做。
  回归：Team 那一节的最后几条。
- `cca gui`（在 `main` 最前面分派）：只装和当前 cca 版本号相同的 App（`$UPDATE_REPO/releases/download/v版本/cca-app.zip` 和 `.sig`，命名空间 `cca-app`、principal `cca-app`，和 cca 的 `cca-release` 分开；再查 bundle id `local.cca.app`、版本号、`codesign --verify`、`--self-check`）。下载好的先放在 `~/.cca/gui/next`，App 开着时不换（`gui_running`），换的时候旧的先挪开、换不上挪回去。`gui_hook` 在每次启动时看：装过 App（`gui/enabled`）、版本和 cca 不同 → 后台 `_gui-fetch`（6 小时一次）；用户自己删掉的 App 不装回来。开发模式下 `cca gui` 用 `macos/build.sh` 现编，`open --env CCA_GUI_CCA=<仓库里的 cca>` 打开 `macos/build/cca.app`，不装进 `~/Applications`
- 辅助程序（`cli/` 的 Rust 程序，见 docs/dev/rust.md）：release.sh 一开始先编四种机器的那一份（四个目标一条命令 `cargo build --release --locked --target … --target …`，cargo 自己并行，比一个一个编少等两三分钟：两种芯片的 Mac、x86_64 / arm64 的 Linux（musl 静态链接，在 Mac 上交叉编译：辅助程序带着 ring，它里面的 C 和汇编要先 `. cli/musl-env.sh` 指定编译器和归档工具，缺 rustup 的 `llvm-tools` 组件时它说）；要装 Rust 和这四个目标，`rustup target add`），带 `--remap-path-prefix` 去掉这台机器的路径并核对程序里没有 `$HOME`，各看一眼文件头（确实是那种机器的程序，Linux 的两份是静态链接的——它们在这台 Mac 上运行不了，真跑要靠 `tests/linux.sh`）；回归用要发布的那一份跑（`CCA_HELPER=cli/target/<这台机器的目标>/release/cca-core`，不另编）；回归过了以后用 `cca-core pack` 把四份接到 `cca` 后面（`cli/target/<这台机器的目标>/release/cca-core pack cca 输出文件`：就是这台机器的那一份辅助程序，见 docs/dev/rust.md；仓库里的 `cca` 不带辅助程序，发布的那一份约 20 MB；Linux 的那两份同时就是 Team 的同步服务器要传到服务器上的程序，见 team.md「安装脚本」），接好的文件 `bash -n`、在一个空的 HOME 和空的缓存目录里真的运行一次（`cca _gui hello`：解出这台机器的那一份、校验、经它报出版本号；解出来的要和编出来的一字节不差；这台 Mac 能经 Rosetta 跑 Intel 的程序时，另一种芯片的那一份也这样跑一次），然后才签名。测试版「先发后验」用的那份 release.sh 拷贝只去掉回归那一步，编和接照旧
