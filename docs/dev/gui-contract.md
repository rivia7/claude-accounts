# 界面 App 的接口（cca 这边）

接口写在 `macos/PROTOCOL.md`；App 那边怎么写在 `macos/CLAUDE.md`。

- App 只经 `macos/PROTOCOL.md` 写的接口和 cca 打交道：不读 `~/.cca` 里的文件、不解析中文、不在 Swift 里重算 cca 的规则。改了这些输出（`_gui hello|state|live`、`usage --json`、`check --json`、`codex reset --json`、`update --check --json`、`health.json`、事件）要同时改 PROTOCOL.md、Swift 模型（`macos/Sources/CcaKit/Protocol`）和 regress 的 10g；只能加字段，删改要升 bash 的 `GUI_API`
- `cca _gui …` 在 `main` 最前面分派（不经过自动更新、映射拉取），`state` / `live` 在 `CCA_RO=1` 下跑：`ctx`、`reconcile` 只在内存里对账，不写 config.json 和账号表，也不往 stderr 说（`notice()` 记进 `NOTICES`，输出在 `notices` 里）。辅助程序里新加会写文件、会说话的对账逻辑也要照这个规矩。`state` 一个进程里看两个工具：`Using::tool(工具)` 换掉当前的工具（`ACCT_JSON` 跟着清）；`codex.json` 不存在时 Codex 算没启用，App 绝不能为了看 Codex 去跑 `cca codex …`（会建出 codex.json，映射里的 Codex 账号随即被加进来）；Antigravity 同理（`agy.json`、`hello.tools.agy`，`CcaClient.setEnabledTools` 挡住没启用的工具的命令）。工具有什么功能看 state 里工具的 `features`（App 的 `AppModel.features`；旧版 cca 没给时 `ToolFeatures.defaults`），不按工具名猜：用量统计只算 `features.usage` 的工具，Antigravity 的组是 `Employee.Department.antigravity`
- 事件：`CCA_EVENTS=文件` 时往里追加 JSON 行（`gui_event`；`consent` / `terminal` / `fail` / `result` / `step`），不设就什么都不做、退出码和 stderr 和不设时一样（启动器、命令行都不设）。用文件是因为很多地方在 `$(…)` 里。失败原因：`fail_warn 代码 文字`、`FAIL_CODE=代码 die …`（bash 3.2 里函数调用前的赋值只在这次调用里有效）；要在终端里做的：`gui_terminal 代码 说明 cca 后面的参数…`（Codex 自动加 `codex`）
- 要用户同意的地方一律用 `consent 项 范围 标题 问题 说明 [默认]`：交互时照旧 `confirm`；非交互时记一条 consent 事件、返回 2（照旧拒绝），App 弹窗同意后带 `CCA_GRANT=项:范围` 重跑同一条命令。授权必须带范围、原样匹配（`router_reload:OpenClash`、`low_purity:<出口 IP>`），不保存；`CCA_YES` 仍然只管 `cca router sync -y`。后台任务（`_update-fetch` 等）在 `main` 里先 `unset CCA_EVENTS CCA_GRANT CCA_RO`，`child_env` 也不把它们带给 claude / codex
- 提问会话（PROTOCOL 4.6）：App 开的封闭流程，cca 还是跑命令行的那份流程，`CCA_PROMPT=1`、事件文件、fd 3 是答案管道时，每问一页发一条 `ask` 事件（`gui_ask` / `gui_fields`，描述经 stdin 交给 `py prompt-emit`），App（`FlowModel`、`FlowSheet`）显示成控件，答案 `<seq> <字段 id> <值>` 写回 fd 3。问题只能经基元（`ask`、`confirm`、`ask_secret`、`ask_fields`、`pick_node`……，k=v 是给 GUI 的，终端里用不上），别处不许读 fd 3；有 `q=` 的题号都要写进 PROTOCOL 4.6 的映射表（回归 lint）。多字段的用 `ask_fields`（一页填完，终端里逐个问，结果在 `F_变量`，不能放在 `$(…)` 里）。读到 EOF 一律按取消（`gui_abort`），不取默认值；提问常在 `$(…)` 里，要 `kill -TERM $$`，`exit` 只退子 shell。bash 3.2 在 `$(…)` 里解析不了 `case` 的右括号，要放进函数。密文（`secret`）只经答案管道，事件里的 `value` 永远是空的。fd 3 读端接给子进程前要挪到高位（读端碰巧是 3 时 `dup2(3, 3)` 什么也不做，close-on-exec 清不掉）。`Handoff.inApp` 标记搬过来的流程，`AppModel.run` 按 `hello.prompt` 决定走提问会话还是终端
- 路由器实况（`_gui live`）是经 SSH 跑这一版 `router_sh` 的 `status`（`sh -s status`，和 `router_node_list` 一样不依赖路由器上部署的版本），由 `cmd_gui_live` 解析槽位行（`GUI_SLOT_RE`）：`router_sh` 的 `status` 输出格式不能随意改（regress 守着）。应选的节点按这台 Mac 的账号表算，不看路由器上的“应为”

## 测试
- 图形界面的接口（regress.sh 10g，`cca gui` 在 11b1）：`gj hello|state|live` 是 `cca _gui …`（stdin 接 /dev/null）；`jok '条件' < JSON` 断言 JSON（`d`，条件里 `tab("accounts.json")`、`cfg` 读 ~/.cca 里的文件）；`runev 命令…` 带着新的事件文件 `$T/ev.jsonl` 运行，`evq '条件'`（每条事件是 `e`）、`evn 类型` 断言事件；`snap` 是 ~/.cca 里文件的摘要（证明只读）。要指定环境变量就写进 `run` 的参数里（`run CCA_ROUTE=router cca _gui live`）：`run` 是 `env -i`，外面的变量带不进去。10g 的输出存进 `$GF`（`$T/guifx`），这一节最后交给 `macos/test.sh` 解码（契约测试；没有 swiftc 时 SKIP）。`publish_app 版本 [命名空间] [plist 版本] [自检退出码]` 往假 GitHub 放一个签好名的假 cca.app；假 App 的可执行文件不能 `exec`（`gui_running` 按命令行里的路径认它）。测试用的开关：`CCA_GUI_APP`（App 装在哪，默认 `~/Applications/cca.app`）、`CCA_GUI_OS`（假装 macOS 的主版本号）、`CCA_GUI_SRC`（开发模式下编译用的源码目录，测试里放一个假的 `build.sh`）
- 提问会话（regress.sh 10h）：`sess 答案JSON [--eof-at 题号] [--stale] [--wrong-field 题号] [--keep] -- 命令…` 带答案管道运行（`tests/gui_session.py` 扮演 App，按题号从答案表取答案：`{"题号":[第一次的答案,第二次的…]}`，每次是 `{"字段 id":"值"}`；写 `null` 的那一次不回答，等 cca 自己换页：配置向导等维护者的那一页），`asks` 列出问过的题号，`evq` 查事件。`macos/build/contract-tests --session-smoke cca路径 答案表 命令…` 是 App 真正的答案管道（ProcessTransport）对真的 cca；`--terminal-smoke cca路径 会话的id 停止文件 [先要看到的字 [要敲的一行 敲完要看到的字]]` 是 App 真正的伪终端（界面里的终端，PROTOCOL 9.3）对真的 `cca remote attach`
