# 折合金额

同步经设备统计的服务器，服务器本身见 presence.md。

- 折合金额（cost，辅助程序的「折合金额」一节；`_gui state` 账号的 `cost`、顶层的 `cost_total`，PROTOCOL 2.2；`cca cost sync [--now] [--json]`，PROTOCOL 3.5）：共享的会话记录（`~/.claude/projects` 的主会话和子代理，`~/.codex/sessions`、`archived_sessions`）里每次请求的用量按官方 API 的标价（`CLAUDE_PRICES`、`OPENAI_PRICES` 这几张表，`COST_PRICES_DATE` 是核实的日期；改了价格表或读的规则要改 `COST_BUILD`，scan.json 从头重算（早于现在还在的最早的会话记录（修改时间）的小时，会话记录可能已经被 Claude Code 删掉了一部分：以前算过的沿用以前的，`cost_keep_old`；旧的 scan.json 没了就从 local.json 取））折成百万分之一美元，按登录的身份、按小时记。不是实际花费，只读用量的数字，不读对话内容。身份：Claude 是 `session-owner` 那一行的 accountUuid（按位置认：换号续接以后的回复归新的；子代理按所在会话的时间线；行要以 `{"type":"session-owner"` 开头（再按 JSON 核对 type），别的行里也会出现这几个字），Codex 是文件里第一个 `session_meta` 的 creator_user_id（后面的是复制进来的历史；model_provider 不是 openai 的不算），用量取 `token_count` 的 last_token_usage（`thread_settings_applied` 给 service_tier：Fast 2 倍、Ultrafast 只有 `OPENAI_ULTRA` 的模型 6 倍、Flex 半价）。身份 → 邮箱由 `cost_who` 认（cca 的账号目录、`~/.claude.json`、`~/.codex/auth.json` 的 id_token，只读声明；以前认出的留着，从头重算也留着：`cost_who_kept` 从旧的 scan.json、local.json 搬过来），认不出的记成 orphan（`cost_total.unattributed`）。gpt-5.6-sol 是官方写着到 2026-11-30 的促销价：之后官方改价时，价格表要能按请求时间分段（直接换价、改 `COST_BUILD` 会从头重算，以前的用量也按新价算）。增量读：每个文件记着 inode、读到哪、读过的末尾 64 字节的摘要（对不上从头读），只读完整的行；Claude 按消息 id + requestId、Codex 按时间 + 累计用量去重。统计在后台进程（`cca _cost-sync`：会话结束（`py link 键 cost`）、`cca usage`、`cca devices`、上报进程里的 `cost_kick`，最多 `COST_EVERY` 一次，`cost.lock` 保证只有一个）里做，写 `~/.cca/cost/`（700；scan.json 读到哪和去重，local.json 是给 state 和同步的，remote.json 是别的设备同步来的，sync.json 是同步的状态，都 600；`cost_save` 在 config.json 不在时不写：restore 刚删掉 ~/.cca）。`_gui state` 只读这些（`CostView`），不起统计。时段：按天是最近 `COST_DAYS` 个本地日历日；按周用额度窗口（`usage_weeks` 的 weeks），空着的按本地周一零点补，不到一天的零头并进前一项，最多 13 项；跨边界的小时按中点归；平均只算有数据以后的、过完的整周（`average_weeks` 没有时是 0），按天的平均（`average_day_usd`、`average_days`）只算有数据以后的、过完的整天；一台设备的 summary 也有这几项，平均按整个账号的那几周、那几天算（各台设备的平均加起来就是账号的）。`cost_total` 顶层是各账号所有设备加起来的，`me` 一节是各账号里这台设备的那一份加起来的（App 的「本机 | 所有设备」照它切，账号页看账号的 summary 或设备列表里 `me` 的那一台，App 不自己加）。config.json 的 `cost: false` 关掉（`cost sync` 退出码 2、`cost_off`）；restore 的备份不带 scan.json、remote.json 这些
- 会话开始的记录（认不出账号时的补充）：Claude Code 2.1.316 及以前不写 `session-owner`，Claude App 的 Code 会话（`entrypoint: claude-desktop`）从来不写，这些回复原来只能记成 orphan（「有的设备有漏」：别的设备经 cca 用旧版 Claude Code，金额一直是空的）。cca 启动 Claude Code 时经 `--settings` 带一个 SessionStart hook（`accounts.rs` 的 `session_hook`，见 isolation.md；`cost: false` 时不带），会话开始、续接、`/clear`、压缩以后回调 `cca _session-start 账号目录名`（bash 那一段什么都不打印、总是成功：hook 的 stdout 会进 Claude 的上下文），辅助程序的 `session-start` 从 stdin 读 hook 的输入（最多 64 KB；会话 id、source 核对过样子；账号目录得已经在），在这个账号目录的 `sessions.jsonl`（600，加锁追加；超过 1 MB 留最后 512 KB 的整行）末尾记一行 `{"sid", "at", "source"}`。统计时没有 session-owner 的回复按它认（`Marks`：碰到第一条这样的回复才读；记录变了的话每个会话记录文件最多重读一次）：这个会话在回复的时间（加 2 秒的余量：Claude Code 记的时间只到秒）以前最后一次是在哪个账号下开始的（续接到别的账号下也认得出），身份照 `cost_who` 的办法从那个账号目录的 `.claude.json` 取；第三方 API 账号下开始的不算（不是订阅的用量；原来算进 orphan）；有 session-owner 的照旧按它。不经 cca 启动的（直接运行 claude、Claude App、IDE）没有记录，照旧认不出。
- 诊断（「哪台设备漏了、为什么」）：每条算进来的 Claude 回复记下命令行（不是 Claude App）里最近用的 Claude Code 版本（scan.json 的 `diag.cc`），认不出账号的再按原因记下最近一次和那时的版本（`old_claude_code`：早于 2.1.317；`claude_app`；`unknown`：别的），都是 `[时间, 版本]`、不记条数，同一个版本隔 10 分钟以上才改。local.json 的 `diag` 是最近 31 天的；传给别的设备的那份多一个 `dg`（cca 的版本、Claude Code 的版本、原因，时间只到 UTC 的天；server/README.md），读别的设备的那份时核对样子（`cost_diag_ok`：最多 8 个原因，旧版 cca 读到会丢掉这一项）。`_gui state` 给 `devices[].diag`、`cost_total.unattributed` 的 `why`、`claude_code`、`claude_code_old`（PROTOCOL 2.2；版本由 cca 比，App 不比）。别的设备没有这个账号的记录、但最近有认不出的回复时也列出来（数字都是 0），这台设备没有记录的不列。认不出的用量不知道是哪个账号的，所以那台设备用的每个账号都带着同一份。App 在设备那一行（橙色三角）和提示里说「有用量没算进来」和原因，这台设备命令行里的 Claude Code 太旧时在折合金额页提醒更新（按钮去「客户端更新」）。这些规则让 `COST_BUILD` 换成了 `/2`：已安装的机器升级以后从头重算一遍（以前的小时照 `cost_keep_old` 留着），最近 30 天的原因才全。
- 折合金额的同步（`cost.sync`，PROTOCOL 2.2）：映射里的 Claude、Codex 官方账号、开着设备统计、这台设备登录着这个账号时，经设备统计服务器的 op `ledger`（`/v1/ledger`、`data/cost-slots.json`；不叫 cost：第一版 3.1.0 的 `/v1/cost` 是另一种格式，换了名字，新客户端遇到那一版服务器、那一版客户端遇到新服务器都是干净的 404，各自按旧服务器处理）交换：每个账号每台设备一份、只写自己的那一份；密钥照 keyshare 的派生（标签 `cca-cost-v1`，和 API key 的不通），认证带着账号摘要和设备指纹（挪不到别的账号、别的设备上），明文是 zlib + 4 字节长度、补齐到 1024 字节，格式在 server/README.md（`tests/spec_wire.py` 照文档独立实现一遍核对：`tests/cost_view.py`、regress 11b3c 的 `dcost` 用它）。服务器回各台设备的（have 里认证码没变的、自己的不带密文，回的密文有上限，其余下次再取）、撤销的设备照样回（标 revoked；同名的新设备有数据以后的小时不再算撤销的那份，不重复计），`missing` 是 30 天内经 cca 用过这个账号、却没传过的设备（多半是 cca 太旧）。最多 `COST_SYNC_EVERY` 一次（`--now` 不等），内容没变 `COST_BEAT` 重传一次，别的设备超过 `COST_STALE` 没传算 stale；旧的服务器（404，body 大时先回 413）记 `COST_OLD`，`COST_RETRY` 后再试。共享关着（policy.md）时没有映射里的账号，不同步；`cca policy off` 先 `py cost-stop` 停掉后台进程，再删掉别的设备同步来的（`cost/remote.json`、`cost/sync.json`），折合金额只剩这台设备自己的（共享的账号也移出了账号表，用量统计、折合金额里都不出现）
