# 界面 App（macos/）

App 只经 `macos/PROTOCOL.md` 写的接口和 cca 打交道：不读 `~/.cca` 里的文件、不解析中文、不在 Swift 里重算 cca 的规则。cca 那边的接口规矩（只能加字段、`CCA_RO`、事件、`consent`、提问会话）在 `docs/dev/gui-contract.md`，改接口前先读；界面怎么画（Logo、颜色、按钮、版心）写在 `macos/README.md`「界面的规矩」。各功能在 App 里的那一部分写在 `docs/dev/` 对应的那一份（用量和套餐档位在 usage.md、内置代理在 local-proxy.md、配置向导和表单在 onboarding.md、Team 在 team.md、检查更新和 `cca gui` 在 release.md）。

## 命令
- `bash macos/build.sh [--version V] [--arch universal|arm64|native] [--debug] [--out 路径.app]` — 编图形界面 cca App（默认 `macos/build/cca.app`，版本号取 `cca` 的 VERSION）；`bash macos/test.sh [夹具目录]` — App 的契约测试（解码 cca 的真实输出；源码、架构、编译器都没变时用上次编好的）。只要苹果的命令行工具，不用 Xcode

## 写法和坑
- 只有命令行工具（没有 Xcode）时：macOS 27 SDK 里的 `@State` 是宏，插件只随 Xcode 提供，编不过——App 的状态一律放在 `@Observable` 对象里（`@Environment`、`@Bindable`、`@Namespace` 可以用）；`@Entry`、`#Preview`、`@Previewable` 也不能用。部署目标 macOS 26，27 的 API（`.pickerStyle(.tabs)` 等）放在 `if #available(macOS 27, *)` 里；x86_64 也用 27 的 SDK 编，和 arm64 用 lipo 合成一个。没有 actool：图标由 `macos/tools/make-icon/main.swift` 画（Logo 的字形和颜色只写在 `Sources/CcaApp/LogoGlyph.swift`：App 里的 `BrandMark`、`Brand` 也取它，build.sh 把它一起编进 make-icon），sips + iconutil 打包；签名是临时签名（curl 下载不带隔离标记，所以 Gatekeeper 不拦；浏览器下载的会被拦）
- App 平时在后台运行：`LSUIElement` + `.accessory`，只有菜单栏图标，启动时不开、不恢复窗口（`CcaApp.opensWindowAtLaunch`：只有 `--window`（`cca gui`、更新后重新打开，`gui_open`）和演示模式才开；第一次打开、cca 没准备好时 `model.start()` 之后也开，教程和引导都在主窗口里）。`WindowOpener.showMain` 换成 `.regular`（才有 Dock 图标），最后一个窗口（主窗口、设置）关掉时换回 `.accessory`。“打开主窗口”的回调在菜单栏图标里就登记（启动时就有，主窗口、面板这时都还没建）。退出分两种（`AppExit`）：Dock 里的“退出”（`applicationShouldTerminate` 收到 `aevt/quit`）、⌘Q 只回到后台（`toBackground`：内置代理的内核、定时检查都不停）；菜单栏面板和应用菜单的「退出」、更新后重新打开（`AppExit.quit`）、注销关机（`willPowerOff`、事件里的 `kAEQuitReason`）、没有 Dock 图标时收到的退出请求（脚本、活动监视器）才真的退出。窗口挂着弹层时 AppKit 自己不让退出（不调 `applicationShouldTerminate`）
- 菜单栏面板：`WindowOpener.showMain`（点“打开主窗口”、面板上的操作要到主窗口里做）收起面板：先走 SwiftUI 的 `dismiss`，还开着时像再点一下菜单栏图标（`performClick`，只关窗口的话 SwiftUI 还以为面板开着，下次点图标要点两下），最后才 `close()`。面板打开的状态用脚本验证不了：注入的点击到不了 SwiftUI 的状态栏按钮（看得到按钮的 state 变，面板不出来），要真人点
- 定时器（`Scheduler.swift`，都带容差）：用量每分钟看一眼（只算内存里的东西），`UsagePolling` 挑到期的账号，`cca usage 这几个账号` 只查它们（查一次要经账号的出口起 Claude Code / Codex / agy 进程，不便宜；Antigravity 的 `Item.slow`：查一次十几秒，间隔长一倍多，cca 也是 30 分钟才算它过时）；不管 App 看不看得见都查，看不见时放慢，用户走开了（`SystemConditions`：15 分钟没碰键盘鼠标）、过热时不查，查失败靠 `usageAttempted` 按间隔重试。点了“登录”、等着登录好的那段时间（`UsagePolling.reloginWatch`，每分钟一次）只查登录好了能查用量的账号（`usageAfterLogin`：`features.usage`，`can_why.usage` 没有或者是 `not_logged_in`）；查不了的（3.6.10 及以前的 cca 给的 Antigravity：`features.usage` 是 false，不跑 `cca agy usage`）按同样的间隔只重读 state。Antigravity 的额度是几组（`quota_groups`，没有 5 小时、本周这些窗口）：账号页 `QuotaGroupsView`，小条 `QuotaStack`（各组里同一个窗口用得最多的那个），算不算用完看用得最少的那个（`UsageEntry.pressureWindows`，`Diagnosis`、菜单栏图标的标记都用它）；没有每周用量的统计，用量统计页不算它。客户端更新不空转：睡到 cca 给的 `next_check_epoch`（间隔是 cca 的 `CU_CHECK_INTERVAL`，App 不重算）。网络出口同样定时检测（`ExitPolling`，同一个定时器，比用量慢得多：`cca [codex] check 这几个账号`，最多 6 个，只给登录着的账号；不弹框、不占 `activities`，所以账号的按钮不受影响；结果在 health 里，测完读一次 state）。这几种后台的活用 `CcaCommand.isBackground`（`posix_spawnattr_set_qos_class_np` utility，实测子进程、孙进程都继承；`nice` 不改调度优先级，没用）。
- 账号的排序和置顶（`AccountArrangement`）：顺序以账号表为准，拖动、置顶后 App 写回（`writeOrder` → `cca [codex] reorder`，官方账号在前、第三方 API 在后，各组里置顶的在前），写好、读回 state 之前界面先用 `arrangement.order`；置顶只记在 App 的设置里，账号按 `Account.stableID`（工具 + cca 给的账号目录名 `id`）认，改别名不丢。组和总览一样（`Employee.Department`：Claude、ChatGPT、第三方 API），第三方 API 这组是两个工具共用的，侧栏只显示当前工具的，`AccountArrangement.move` 只换显示的这几个之间的先后。`Account.pinned` 是另一回事（Team 的配置锁定了节点）
- 终端：App 发起的命令（登录、`terminal` 事件、安装……，`Handoff.systemTerminal` 默认是 true；cca 太旧、在 App 里问不了时的添加账号、配置路由器也算）一律用系统自带的“终端”，用户选的终端只管账号页的「终端」（账号的会话 `Handoff.session`）。`TerminalApp.known` 是认识的终端，App 按 bundle id 看装了哪些（没装的在选择列表里灰着、不能选），用户选的记在 App 的设置里（不进 `~/.cca`）；没选过时用第一个装了的全自动第三方终端，都没有就是系统自带的。全自动的都是运行同一份 `.command` 交接脚本：Terminal、iTerm2、Warp、WezTerm、Hyper、cmux 把文件交给它们（iTerm2 第一次会问要不要运行），Ghostty、kitty、Alacritty、Tabby、Rio 开新进程带参数（Ghostty、kitty 打开文件每次都要确认，Alacritty 不能打开文件，Tabby 每次运行前自己弹窗确认）。半自动的（`Launch.paste`：Termius、Wave，读过 Termius 10.4.0 的代码：外部链接只管登录、SSH、共享终端，新建本地终端只在它自己的菜单里）App 打开它、把命令放进剪贴板，用户粘贴运行；不用模拟按键（要辅助功能权限，App 是临时签名，焦点不对时命令可能敲进连着服务器的 SSH 会话）。系统自带的“终端”进程结束后默认留着窗口（[进程已完成]）：脚本按键之前趁自己还在跑认出窗口 id（结束的窗口还报着旧的 tty，新窗口会重用这个号），按键后等 shell 退出用 AppleScript 关这一个（Terminal 发给自己的 Apple Event 不用授权，实测；窗口里有别的标签页时不关），“终端”没有别的窗口了就退出它；cca 够新（hello 的 `dock`）时再 `cca _dock-tidy <终端.app> <终端的进程号>`，去掉程序坞里它留下的图标。等着关窗口的是后台进程（setsid，经管道等脚本结束：按键、点关闭、^C 都算），最后只是把活交给 cca 的后台小 App 就退出：从这个窗口里起的进程都算“终端”的下属，还活着时重启的程序坞会把“终端”又加回去（见「程序坞」）。脚本开头 `mv` 自己，App 的 `reclaim` rename 同一个文件，只有一边成功：第三方终端 `terminalGrace`（30 秒）还没运行脚本，App 收回它、问要不要改用系统自带的，不会跑两遍。账号的会话（`Handoff.session`，`cca [codex] @账号`）从选的文件夹启动，结束后留在用户的登录 shell 里；最近的文件夹（最多 8 个，所有账号共用：换账号接着做同一个项目）也记在 App 的设置里；能不能开看 cca 给的 `can.cli`（要有 claude / codex 命令）
- 总览（首页，`SidebarItem.office`，每次打开 App 先看它）：每个账号一张卡片，画面设计上参考办公室（工位、坐着的人），但**界面上的文字不用“办公室、员工、工位、在忙、休息、回来”这类比喻的词**，照实说（账号、在用、额度用完、几点恢复、未登录、账号不符）；代码里的 `Office` / `Employee` 只是类型名。每个账号的状态（`Employee`，CcaKit）从 `Diagnosis.all`（CcaKit）派生，账号页那句话（`Advice`）也取它的第一条——问题的先后顺序只写在 `Diagnosis` 一处。“在用”是 `app.running || cli.running`（头像右下角的绿点也是），3.6.16 起别的设备上在用（`AppModel.elsewhere`：定时 `cca devices --json` 不写账号，PROTOCOL 3.4）的头条也是在用、写出是哪台（`Employee.elsewhere`，卡片上「在用（Mac-mini）」，提示里「在「Mac-mini」上在用」；绿点、左上角的小图标只算这台 Mac 的）：在用时卡片的头条总是在用，有问题（没登录、登错号、登录失效、线路或出口、额度用完）时问题跟在后面（`Employee.trouble`，“在用 · 端口无法连接”，小圆点是问题的颜色），点名算在用、要处理的照样算进“要处理”（`OfficeCensus.workingTroubled`）；以前问题排在在用前面，桌面 App 开着、命令行没登录的账号在总览里是“未登录”。套餐的四档样子在 `PlanBadge.swift`（`TierStyle`），按 cca 给的 `plan_tier`。工位插画在 `DeskArt.swift`（Canvas，没有图片资源；动画只在窗口看得见、没开“减少动态效果”时走：读环境里的 `motionAllowed`，主窗口和菜单栏面板的根上 `motionScope` 各设一次，别在各处自己算）。演示模式（`CCA_GUI_FIXTURES`）把夹具里的时间平移到打开的这一刻（`FixtureTransport` 的 `rebaseTo`），测试读原样的文件。卡片左下角的小票是还能重置几次（`usage.reset_credits`，一张一次，最多画 5 张），旁边是 cca 算好的最早到期日，`Texts.resetSummary` 这一句也进提示和读屏
- 内置代理的内核（`CoreHost`，PROTOCOL 7）：App 跑 `cca _core run` 用 `Transport.startCore`（不限时，输出追加进 `~/Library/Caches/local.cca.app/core.log`，不放 runs 目录：那里一天前的会被清掉），停的时候 SIGTERM 进程组；测试替身和演示数据走协议扩展里的默认实现（不支持）。带 `--core` 启动（`CcaApp.launchedForCore`）什么情况下都不自己弹主窗口
- 看界面改得怎么样：`bash macos/build.sh --debug` 编出的调试版有截图模式（`CCA_GUI_FIXTURES=macos/Tests/Fixtures CCA_GUI_SNAPSHOT=目录`，各场景浅色、深色各截一张 PNG 后退出；终端没有屏幕录制权限，`screencapture` 用不了）。界面的规矩（Logo 和档位参考 Google 新的图标语言：渐变互相过渡、粗圆扁平；以信息简洁易懂为主，不为装饰上色、画框；颜色只表达账号、状态和套餐档位（档位低调：中性胶囊，只有小徽记有颜色；Logo 的整条渐变只给 premium 的四角星和侧栏头像的细光晕，侧栏每行左边留出光晕的宽度免得被裁掉，别处的头像、卡片都不带）、玻璃只给控件层、账号色的分流线贯穿侧栏 / 线路 / 分流图、操作放在它作用的内容旁边、按钮只有几种样子（标题上的 `SectionAction` 和信息行的 `RowAction` 一个样子、行里的等宽对齐，打开网页的 ↗，提示条里解决问题的 `.borderedProminent`）、各页共用一个版心、宽窗口时账号页两栏、总览）写在 macos/README.md「界面的规矩」。新手引导（卡片教程、提示卡片、“下一步”那句话、默认收起的技术细节）在 `Guide.swift`，“下一步”只按 cca 给的状态说话，不重算 cca 的规则
