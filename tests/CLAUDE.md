# 测试（tests/）

这里是回归（tests/regress.sh）和 Linux 测试（tests/linux.sh）的通用写法。某一块功能的测试怎么写（假命令怎么扮演、在回归的哪一节）在 `docs/dev/` 对应那一份的「测试」里；界面 App 接口的测试（10g、提问会话）在 `docs/dev/gui-contract.md`。

## 命令
- `bash tests/regress.sh` — 全流程回归，约 12 分钟（含 App 的契约测试；超过 Bash 工具前台 10 分钟的上限，放到后台跑）；全用假的路由器/claude/curl/ssh/GitHub，不联网、不碰真实 `~/.cca`；`KEEP=1` 保留沙箱，`DEBUG_OUT=1` 时失败的用例附上 `$out` 的最后几行；`TIMING=文件` 找慢在哪：每个用例记一行（耗时、行号、cca 起了几次辅助程序、sleep 了几秒、说明），`KEEP=1` 时沙箱里的 `py.count` 记着每次 py 的子命令。开头先编辅助程序（`cli/` 的 Rust 程序，要 cargo；`CCA_HELPER=路径` 时不编、整套用那一份），unit 一节（排在最后）收 `cargo test` 和 suite 各个模块的结果（它们开头就在后台跑了，辅助程序用的是同一份：`CCA_HELPER`），再跑 `tests/path_unhint.sh`；只能在 macOS 上跑（BSD sed、/bin/dash、ruby）
- `bash tests/linux.sh [--docker [镜像…]]` — Linux 上的测试（regress 只能在 macOS 上跑；临时 HOME，假的 crontab，不碰真的 `~/.cca` 和 crontab）：一键安装（install.sh：假 curl 把 GitHub 换成本机的文件、发布密钥换成临时生成的，验签、`cca install`、PATH 写进 `~/.bashrc`；藏起 nc 看缺命令时给出这个发行版的安装命令）、自动更新（假 GitHub 上的 9.9.9：后台下载验签、下一条命令换上，`--rollback` 后不再自动装）；之后用旁边放了 `.git` 的一份（开发模式，认这次的发布密钥）。假的 claude / codex 是两行 sh，要做的交给 `cca-test` 的角色 `linux-claude`、`linux-codex`（`tests/tool/fake/linux_*.rs`：登录照真的开本机回调、交出网址；codex 的 app-server 回登录和用量；`$D/hold` 在时会话一直开着），测试节点是本机另一个 mihomo（socks5 → DIRECT）。依次测：内置代理（真的下载、校验内核，`cca _core-keep` 托管，问过后在 crontab 加 `@reboot` 那一行；经账号的端口访问本机的 HTTP 服务、空槽位拒绝、杀掉内核后拉起来、照 crontab 那一行在 cron 的环境里模拟重启）；服务器上登录（login-page 那一行带别名、节点和节点摘要，state 不对不转，取消）、启动账号、key 存成 600 的文件；设备统计（真的服务器：辅助程序的 `team-server`，管理员由 `cca-test spec` 扮演；会话开着报在用、关了报没在用；要 openssl）；远程会话（测试程序 `suite` 的 `remote_host`、`remote_relay` 两个模块把辅助程序当黑盒跑：会话宿主、配对、经服务器中转；只在宿主机上，容器里不跑）；Codex（没有路由器也能加、服务器上登录、启动带的开关、查用量、查用量途中 TERM 马上停掉后台的查询、cxa）；真实的出口和 DNS 泄露检测（结果随网络变，只核对测了、记下了、没说 WebRTC）；只在 macOS 上的命令说清楚、`cca help` 不列；`cca local off`（crontab 那一行删掉）；`cca uninstall`（`cca restore` 是同一条命令；GNU / busybox 的 tar 打包，登录凭证、密钥文件、参考节点不进包，crontab 那一行删掉，缓存目录里解出来的辅助程序、`~/.bashrc` 里 cca 加的那两行也清掉；没有 tar 的发行版上先停下、什么都不动，`--no-backup` 才卸载）；服务器上不用路由器（全新的 HOME，直连通不通由假 curl 定（`$D/direct_down`、`$D/direct_loc`，只认直连的 trace，别的交给真的 curl）：直连不通时 `cca install` 不问路由器、改用内置代理，`_core-keep` 托管，问过后加开机那一行，经账号的端口出去）。Team 的同步服务器的一键安装脚本（`suite` 的 `hub_deploy` 模块，假服务器是 `tests/kit/hubbox.rs`：这个发行版的 sh——dash、busybox 或者 bash——和 openssl，假的 systemctl、docker 起真的服务端；没有 openssl、ssh-keygen 时跳过）。在家走路由器只在容器里测（`CCA_LINUX_CONTAINER`，`--in-container` 设的：端口池监听 0.0.0.0）：假路由器 127.0.0.2 上跑真的 cca-router.sh / apply.rb，内核是真的 mihomo，uci、pidof、netstat 是假的，假 ssh 把命令交给它；`cca install` 里配置路由器、选节点、加账号、问过后重载，经路由器的端口池出去，在家时给内置代理拷节点（装不上 ruby 的容器跳过）。端口池固定从 7901 起，被占用时不跑；退出时停掉命令行或环境里带着沙箱路径的进程。`--docker` 每个发行版一个容器并行跑（不写镜像就跑开头 `IMAGES` 里的主要发行版，各用发行版自己的包管理器装依赖，busybox、curl-minimal 原样用，另装 openssl、ruby；Debian、Ubuntu 不另装 procps（Debian 的镜像里本来就没有，Ubuntu 的自带；dnf 系的镜像也没有，测试给它们装上了）：cca 在 Linux 上不靠 ps、pgrep、pkill，`cca usage` 被 Ctrl-C 时停后台查询用 `kill_kids`，没有 pkill 就读 /proc）；内核在宿主机上只下载一次、校验过挂进各个容器（`CCA_LINUX_CORE_CACHE`：假的 curl 从这里拿内核文件，cca 照样校验，别的请求交给真的 curl；直接跑时也能设）。要联网（下载内核、镜像、测出口）；在别人的机器上跑 `--docker` 前后比一比 `docker images`，删掉拉下来的镜像。整个脚本不用 python3，那台机器上没有它也能跑（只有「cca 不用 python3」那一条在 PATH 里藏起它）：测试自己用的是两个静态链接的程序，小工具 `cca-test`（假命令的角色、读写 JSON 的求值器、`spec` 扮演 Team 的管理员、`http-serve` / `accept-close` 两个小服务）和测试程序 `suite`。有 cargo 时脚本自己编，没有时用 `CCA_TEST_BIN`、`CCA_SUITE_BIN` 指的（辅助程序是 `CCA_HELPER`）或者 `cli/target/<目标>/kit/` 下编好的，`--docker` 在宿主机上编好、指给各个容器；怎么弄到没装 Rust 的机器上见 docs/dev/linux.md「测试」。suite 不认识的模块（名字写错了，或者指的那一份 suite 比脚本旧）、一个用例都没跑都算失败，不算跳过；没过时把没过的用例和它们的输出打出来（沙箱退出时就删了）。`cca-test` 遇到不认识的写法记在 `$D/trap`，最后有一条查

- `cd cli && cargo test --profile kit -p cca-tests --test suite -- web_relay` — 远程会话的网页端（`tests/web_relay.rs`，回归的 unit 一节里是 `suite_ok web_relay` 那一行；单独跑之前先 `cargo build --release`）。服务器那一半、`cca remote pair --web` 只要 python3；浏览器里跑的那一份（`server/web/core.js`，经 `tests/web_client.mjs`）要 Node 22 以上，真的页面走一遍（`tests/web_page.mjs`）还要 Chrome（`CCA_CHROME` 换路径，`CCA_WEB_SHOTS=目录` 留下截图）——没有时那几个用例自己跳过，回归照样过，但那一半这次就是没测。`cd cli && cargo run --profile kit -p cca-tests --bin cca-test -- web-demo` 在本机把网页端跑起来自己看（`tests/tool/web_demo.rs`）。见 docs/dev/remote.md「网页端」

## 写法
- 分节续跑（省开发迭代时间；发版、平时照样跑全量、一行不差）：`CKPT=目录 bash tests/regress.sh` 先全量跑一次、在每节开头存快照（沙箱 tar + 跨节用到的变量和函数）；之后 `CKPT=目录 FROM=10h`（从某节恢复、跑到结尾）或 `CKPT=目录 ONLY="10h 11b4"`（只跑这几节、各从自己的快照起，约 1-2 分钟，不是 13 分钟）。每节都包在 `if sect 节名; then … fi` 里，不带 CKPT/FROM/ONLY 时 `sect` 恒真、逐字跑全量（发版门不受影响）。坑：① 沙箱固定在 `$TMPDIR/cca-ckpt.sandbox`（和快照里的路径要一致），快照目录约 600 MB（11b 以后沙箱里有十几个接着辅助程序的假发布版，每个快照 35～60 MB），`$T.lock` 防并发（一次只能一个，共用沙箱并发会互删、报 getcwd 错）。② bash 3.2 没有 `declare -g`：存变量去掉 `declare` 前缀存成普通赋值，恢复是在 `_ckpt_restore` 函数里 source 的，`declare --` 会建成函数局部、一出函数就没了（跨节的 `$VS`/`$GF` 全丢）；不带名字的 `declare -p` 在 bash 3.2 也没有 declare 前缀（得按名字一个个存）。③ 改了定义跨节函数（`node_rn` 这类）、设跨节变量的早节之后，要重建快照。④ 11b 的「发布版安装」之后 `$H/.local/bin/cca` 是 mkver 出来的拷贝（之前是链到仓库 cca 的链接），快照里存的是建快照时的那份：改了 cca 或者辅助程序以后 `ONLY=` 跑 11b 及以后的节测的还是旧代码（新行为的用例会挂）：这些节用 `FROM=11b`（从装发布版之前恢复、跑到结尾，约 6 分钟），或者不带 CKPT 跑全量；`FROM=`/`ONLY=` 不重建快照，要重建就再 `CKPT=目录` 全量跑一次。⑤ 快照可以几个 worktree 共用：`$CKPT/repo` 记着建快照的那份检出，在另一份检出里续跑时 `_ckpt_restore` 把沙箱里指着它的链接、写着它的路径的文件和变量换成当前这一份的（11b 之前 `~/.local/bin/cca` 是指着仓库里的 cca 的链接）；跨节的函数还是快照里的（见 ③）。不抓后台进程（各节多自起自停）。实测 10h/12/3d/10c/11b4 逐字一致
- 开发时不跑某几节：`SKIP="unit 10g" bash tests/regress.sh`（`sect` 对它们返回假）。只能跳别的节不靠的那些（unit：Rust 的单元测试和 tests/ 下各份黑盒测试，带上它后台那一路也不起；10g 里的 App 契约测试）；发版、提交前的那一遍不带这个变量
- 测试用的小工具 `cca-test`（tests/ 是 Rust 包 `cca-tests`：支持库 `kit/`、小工具 `tool/`、测试程序 `suite.rs`，和辅助程序同一个 workspace，`cd cli && cargo build --profile kit -p cca-tests`）：回归开头编出来（`CCA_TEST_BIN=路径` 时不编），regress.sh 里是 `"$TESTBIN"`，沙箱里的假命令经 `"$CCA_T/cca-test"` 找它。setup.sh 写出来的假 claude / codex / agy 这些是 shell 脚本，里面要算的（写配置、登录的回调、app-server、STUN、程序坞的设置……）交给它的角色（`tests/tool/fake/`，一个假命令一个文件）；一直开着的那几个用 `exec -a "$CCA_T/fake_oauth"` 这样起，回归按这个名字 `pgrep -f` / `pkill -f`。它遇到不认识的写法退出码是 2，并在 `$CCA_TEST_TRAP`（`$T.trap`）里记一行；回归最后一条用例查这个文件是空的
- 各份把 cca、辅助程序当黑盒的测试是 `tests/<模块>.rs`，合成一个程序 `suite`（`tests/suite.rs` 列着各个模块；运行器是自己写的 `kit::harness`：一个模块一个子进程、用例有时限、收尾一定跑，怎么写用例、有哪些开关见 `tests/kit/harness.rs` 开头）。单独跑：`cd cli && cargo test --profile kit -p cca-tests --test suite -- 模块名`（要先 `cargo build --release` 编好辅助程序）；回归开头就把它整个放到后台跑（`$SUITEBIN`，`CCA_SUITE_BIN=路径` 时不编；几个模块同时跑，跑完接着 `cargo test`、`cargo fmt --all --check`、tests/ 自己的单元测试），主流程同时往下走；unit 一节在最后，等它跑完、一个模块一行结果（`ok … 'suite_ok 模块'`、`cargo_ok …`）。`tests/suite.rs` 里加了模块，unit 一节也要加一条 `suite_ok`（漏了有一条用例说）。结果和输出在沙箱旁边的 `<沙箱>.unit/`（`results.tsv`、`logs/<模块>.log`、`cargo-*.log`；`KEEP=1` 时留着）
- 交互流程：`CCA_TTY="$(ans 答案1 答案2 …)"`，一行一个答案
- 真终端里的提问（不设 `CCA_TTY`）：`{ printf 答案; 等完成标记; } | script -q 日志 env -i … bash -c 'cca …; touch 完成标记'`，左边要一直开着到命令跑完（macOS 的 script 读到 EOF 会先送一个 ^D，打乱输入）。见 regress.sh 10a
- 方向键菜单和 readline 输入要在真 pty 里测：`script -q 日志 bash 驱动脚本`，配合定时输入
- 别让用例干等：`run` 带着 `CCA_RETRY_WAIT=0`（下载失败后不等 2 秒再试），假 ssh 的 `CCA_WAIT=2`；等不到才判失败的用例把等待调短（`CCA_APP_WAIT=1`：cca app 等 App 打开资料目录），等后台任务时等它写下的结果（`wait_log`），不要等满超时。3c 检查完启动器图标后 `touch "$T/fake_icons"`：以后新建、重画的启动器图标用假的 osascript（badge.js）、sips、iconutil（真画一个将近 1 秒）
- 假 `ssh` 像真的一样把 stdin 读走（只读普通文件，也就是 bash 3.2 的 here-string，终端、管道不碰）：循环里调 ssh 吞掉后面输入的问题测得出来。假的路由器控制接口要密钥（`test-secret`，uci 的 `dashboard_password` 也是它），密钥不对回 401
- 假 `defaults`（只在 `$T/defaults.log` 里记一笔，读什么都说没有）：真的不看 `HOME`，经系统的设置进程读写这台 Mac 上真的 `~/Library/Preferences`——没有它时 `cca gui remove`、`cca restore` 每跑一次就把真的 cca App 的设置删一次。cca 新用到别的不看 `HOME` 的系统命令时，先在 `tests/setup.sh` 里放一个假的。缓存目录同理：`run` 不带 `TMPDIR`，macOS 上 cca 的缓存目录就是这个用户真的临时目录（`cca-helper` 在那），会整个删掉它的用例带 `TMPDIR=<临时目录下单独的一个>`（见 docs/dev/uninstall.md）
- 不经 `run`、自己拼 `env -i` 运行 cca 的地方（真终端的那种、另一个 HOME 的 `r3` / `r4` / `rs`）要带上 `CCA_HELPER="$HELPERWRAP"`：不带的话那一处用的是仓库里 `cli/target/release` 下的那一份，`release.sh` 跑回归时（`CCA_HELPER` 指着要发布的那一份）测的就不是同一份了。有 lint 守着；想自己验证就照 `release.sh` 的方式在一份不带 `cli/target` 的仓库拷贝里跑
- 测试辅助脚本只用沙箱里的路径，不能靠 `$HOME`：在 `run` 外面直接调用时 `$HOME` 是真实的主目录（会碰到真的 `~/.cca`、`~/.claude` 等）
- 菜单行很宽：要看行尾的内容时用 `run COLUMNS=160 …`（`tput cols` 认 `COLUMNS`）
- 断言（`ok` 的第二个参数是 `eval` 的）里别写 `"$(函数 "{\"…\"}")"`：bash 3.2 解析双引号里命令替换中的转义引号会把参数拆碎（JSON 按空格断成几段，`[` 报 too many arguments，断言失败却看不出为什么）。期望值先在断言外面算好放进变量（11b2c 的 `ckw`）；`"$(函数 "$变量")"` 没问题
